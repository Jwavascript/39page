# 0020. 재생 시점 조회와 이동은 어댑터 계약에 더하고, 코디네이터가 중계한다

- 상태: 채택 (설계)
- 날짜: 2026-11-07
- 관련: **ADR 0006** (어댑터 소유권), **ADR 0008** (어댑터 이벤트 계약),
  **ADR 0009** (Playback Coordinator), **ADR 0011** (가시성 가드),
  **ADR 0012** (재생 실패 처리), **ADR 0019** (Moment 도메인),
  `docs/architecture/MOMENTS_DESIGN.md` §4

## 배경

Moment 를 저장하려면 **지금 몇 초인지** 알아야 하고, Moment 로 가려면
**그 초로 옮겨야** 한다. 현재 `PlayerAdapter` 계약에는 둘 다 없다.

```ts
mount() · destroy() · load(videoId, options?) · play() · pause() · state()
```

M3 가 일부러 뺀 것이다. 다만 **뺀 것은 "우리가 만드는 탐색 바 UI"** 였다
(`IMPLEMENTATION_PLAN.md` 3.1 — "자체 탐색 바·볼륨 UI 를 만들지 않는다").
YouTube 네이티브 컨트롤이 스크럽을 제공하고 우리는 그것을 가리지 않는다
(개발자 정책 III.I.6). 프로그램으로 특정 시점에 가는 것은 다른 이야기다.

이 ADR 은 **어느 계층에 넣는가**를 정한다.

## 결정

### 1. 어댑터가 시점을 책임진다

```ts
interface PlayerAdapter {
  // ... 기존 여섯 개

  /**
   * 현재 재생 위치(초). 준비 전이거나 적재된 영상이 없으면 `null`.
   * 숫자를 지어내지 않는다.
   */
  position(): number | null

  /** 적재된 **같은 영상** 안에서 지정한 초로 이동한다. */
  seek(seconds: number): void
}
```

어댑터여야 하는 이유는 기존 계약의 이유와 같다. YouTube 특이사항을 밖으로
새지 않게 하는 것이다 (`AGENTS.md` 규칙 4, ADR 0006). `getCurrentTime()` 은
플레이어가 준비되기 전에 `0` 을 돌려주거나 던진다 — 그 사정을 아는 곳은
어댑터뿐이고, 밖에는 **`null` 이라는 도메인 값**으로만 보여야 한다.

`null` 이 중요하다. `0` 을 돌려주면 호출부가 "영상 맨 앞" 과 "아직 모른다"
를 구분할 수 없고, 사용자는 **0초짜리 Moment** 를 얻는다.

`FakePlayerAdapter` 도 같은 계약을 실제로 구현한다 (기존 방침 그대로).

### 2. 영상 전환은 `seek` 이 아니라 `load` 의 인자로 한다

```ts
interface PlayerLoadOptions {
  autoplay?: boolean
  /** 이 초부터 시작한다. 생략하면 처음부터. */
  startSeconds?: number
}
```

다른 영상의 Moment 로 갈 때 `load()` 후 `seek()` 을 부르면 경쟁이 생긴다 —
새 영상이 준비되기 전의 `seek` 은 **이전 영상에 적용되거나 사라진다.**
어댑터가 `load` 를 보류하듯 `seek` 도 보류 큐를 따로 가져야 하고, 둘의
순서까지 보장해야 한다.

`loadVideoById({ videoId, startSeconds })` 는 **YouTube 가 공식으로 주는
인자**다. 보류 중인 `load` 하나에 시점이 같이 실려 있으므로 경쟁할 것이
없고, 0:00 에서 점프하는 장면도 보이지 않는다.

그래서 두 경로를 나눈다.

| 상황                   | 하는 일                                           |
| ---------------------- | ------------------------------------------------- |
| **지금 영상**의 Moment | `seek(atSeconds)` + `play()` — 다시 적재하지 않음 |
| **다른 영상**의 Moment | `load(videoId, { autoplay: true, startSeconds })` |

같은 영상을 다시 `load` 하지 않는 것이 중요하다. 재적재는 버퍼링을 다시
일으키고, 사용자에게는 같은 곡이 끊기는 것으로 보인다.

### 3. UI 는 어댑터를 부르지 않는다 — 코디네이터에 면을 하나 더한다

```ts
export interface PlaybackMoments {
  /**
   * 지금 재생 중인 영상의 시점을 찍는다.
   * 재생할 영상이 없거나 플레이어가 아직 모르면 `null`.
   */
  capturePosition(): MomentCapture | null

  /** Moment 가 가리키는 지점부터 재생한다. */
  playMoment(target: { videoId: string; atSeconds: number }): PlayRequestResult
}
```

`PlaybackRequests` · `PlaybackTransport` 와 같은 자리다. Moments 위젯은
어댑터도 YouTube API 도 모른 채 이 둘만 부른다 (ADR 0009).

**`playMoment` 가 `PlayRequestResult` 를 돌려주는 것이 핵심이다.** 다른 재생
요청과 **같은 가시성 가드**를 통과한다 (ADR 0011) — 플레이어가 가려져 있으면
같은 문구로 거절되고, M7-2 의 `stepAside()` 로 시트가 먼저 비켜주는 흐름도
그대로 쓴다. Moment 재생만 예외인 경로를 만들지 않는다.

`capturePosition()` 이 `null` 이면 저장 버튼은 **비활성**이다. 시점을 모르는
채로 Moment 를 만들지 않는다.

### 4. 시점은 **누를 때** 찍는다

저장 버튼을 누른 순간 `capturePosition()` 이 값을 고정한다. 메모를 다 쓴
뒤에 다시 읽지 않는다.

메모를 20초 동안 쓰면 재생은 20초 흘러간다. 저장 시점에 읽으면 사용자가
표시한 순간과 저장된 숫자가 어긋난다 — 그 20초가 바로 사용자가 "이 부분"
이라고 생각한 구간을 지나간 시간이다.

### 5. 정확히 그 초에서 시작한다

`atSeconds - 2` 처럼 앞당기지 않는다. 목록에 `1:23` 이라 적어두고 `1:21`
부터 틀면 표시와 동작이 어긋나고, 어긋남의 크기를 사용자가 조절할 수도 없다.

> 대안으로 "도입 2초" 를 검토했다. 음악적으로는 더 나을 때가 있지만,
> 그러려면 저장값과 재생값이 달라진다는 사실을 UI 가 설명해야 한다.
> 숫자를 하나만 두는 쪽을 택했다.

### 6. 확장(M10)을 위한 모양

`capturePosition()` 은 **이 탭의 플레이어**를 보지만, Moment 를 만드는 함수는
그렇지 않다.

```ts
createMoment({ videoId, atSeconds, note, title, now, id }): Moment
```

입력을 전부 명시로 받는 순수 함수다. "지금 재생 중인 것" 을 암묵적으로
읽지 않으므로, YouTube 페이지에서 확장이 모은 값으로도 같은 함수를 쓸 수
있다 (지시서 E). 확장과 웹앱 사이의 **전달 방식은 M10 에서 설계한다**
(`BACKUP_FORMAT.md` §6-3).

## 경계 사례

| 사례                            | 처리                                                                                           |
| ------------------------------- | ---------------------------------------------------------------------------------------------- |
| API 이벤트 지연 · 준비 전       | `position()` 이 `null`. 저장 버튼 비활성. 숫자를 지어내지 않는다                               |
| 영상 전환 중 저장               | 전환 후 `ready` 전까지 `null` 이므로 같은 경로로 막힌다                                        |
| 재생 불가 영상의 Moment         | 기존 실패 경로 그대로 (ADR 0012). **Moment 를 지우지 않는다** — 자동 삭제 금지                 |
| 자동재생 차단                   | 기존 `autoplayBlocked` 안내. Moment 누름은 사용자 제스처라 보통은 닿지 않는다                  |
| `atSeconds` 가 영상 길이보다 큼 | 막지 않는다. 저장 시점에 다른 영상의 길이를 알 수 없다. 재생은 끝으로 가고 `ENDED` 로 처리된다 |
| 플레이어가 가려져 있음          | 다른 재생 요청과 **같은** 거절 (ADR 0011)                                                      |

## 대안

| 후보                                            | 탈락 이유                                                                          |
| ----------------------------------------------- | ---------------------------------------------------------------------------------- |
| **어댑터에 `position`/`seek`** (채택)           | 위                                                                                 |
| 컴포넌트가 `YT.Player` 를 직접 부름             | 규칙 4 위반. YouTube 특이사항이 UI 로 샌다. ADR 0006 이 금지한 소유권 침범         |
| 코디네이터가 `getCurrentTime` 을 직접 폴링      | 어댑터를 우회한다. 숫자 상태값을 밖에서 해석하게 된다                              |
| `load()` 후 `seek()`                            | 준비 전 `seek` 이 사라지거나 이전 영상에 적용된다. 보류 큐를 하나 더 만들어야 한다 |
| `position()` 이 준비 전 `0` 을 반환             | "맨 앞" 과 "모른다" 가 구분되지 않는다. 0초 Moment 가 생긴다                       |
| 시점을 **저장 버튼을 누를 때가 아니라** 저장 시 | 메모를 쓰는 동안 흘러간 만큼 어긋난다                                              |
| 탐색 바 UI 를 우리가 그림                       | 네이티브 컨트롤을 가린다 (III.I.6). M3 결정을 뒤집을 이유가 없다                   |
| Moment 재생을 가시성 가드에서 제외              | 가려진 채 소리가 난다 (III.I.9). 예외 경로가 정책을 무의미하게 만든다              |

## 결과

- 계약이 여덟 개가 된다. 추가 둘은 **선택이 아니라 필수**이므로
  `FakePlayerAdapter` 도 구현한다 — 두 구현이 갈라지지 않게 하는 기존 방침.
- `PlayerLoadOptions` 에 선택 필드가 하나 는다. 기존 호출부는 그대로다.
- `PlaybackCoordinator` 가 다섯 번째 면을 얻는다. 기존 네 면은 바뀌지 않는다.
- Moment 재생이 가시성·실패·거절에서 **다른 재생과 완전히 같게** 동작한다.
  새 정책이 없으므로 새 구멍도 없다.
- `PlayerSurface` 와 iframe 은 전혀 바뀌지 않는다. `seek` 도 `startSeconds`
  도 **적재된 플레이어에 보내는 명령**이지 재생성이 아니다 (ADR 0002).
