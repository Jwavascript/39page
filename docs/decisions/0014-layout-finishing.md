# 0014. 레이아웃 마무리는 DOM 래퍼 없이 하고, 실측으로 검증한다

- 상태: 채택
- 날짜: 2026-11-04

## 배경

M5 에서 승인된 디자인과 실제 앱을 나란히 놓고 비교했다. 네 가지가 달랐고,
셋은 **브라우저 실측에서만** 드러났다.

| 차이                          | 어떻게 찾았나                  |
| ----------------------------- | ------------------------------ |
| 정보 열 구분선이 없다         | 스크린샷 비교                  |
| 푸터가 없다                   | 스크린샷 비교                  |
| 마스코트가 열 바닥으로 밀린다 | 스크린샷 비교                  |
| 360px 에서 영상이 198px 이다  | CDP 모바일 에뮬레이션 실측     |
| 트랙 ▶ 가 30×22 이다          | CDP 실측 (24px 미만 요소 수집) |
| 페이지에 `h1` 이 없다         | CDP 로 제목 구조 수집          |

고치는 데 걸린 제약: **위젯 루트는 그리드의 직계 자식이어야 한다**
(ADR 0002 · 0005). 래퍼를 하나라도 끼우면 플레이어 iframe 의 부모가 바뀌어
재로드된다. 승인된 디자인은 두 열을 각각 `.deck-wrap` / `.info` 래퍼로 묶어
해결하는데, 우리는 그 길이 막혀 있다.

## 결정

### 1. 정보 열 구분선은 의사 요소로 그린다

```css
.widget-host::before {
  content: '';
  grid-row: 1 / -1;
  grid-column: 2;
  margin-left: calc(-0.5 * var(--host-gap));
  border-left: 1px solid var(--info-border-color);
  pointer-events: none;
}
```

의사 요소도 그리드 아이템이 된다. 명시적 `grid-column` / `grid-row` 를 주므로
다른 위젯의 자동 배치를 밀지 않고, **요소 노드를 늘리지 않는다.** 선은 열
사이 간격의 **가운데**에 선다 — 승인된 디자인의 `.info { border-left }` 와
같은 자리다.

`pointer-events: none` 이 필요한 이유: 플레이어 열 전체에 겹쳐 있어, 포인터를
먹으면 YouTube 컨트롤이 막힌다.

1열 레이아웃에서는 `border-top` 으로 바꾸고 시계 행에 둔다. 승인된 디자인도
같은 전환을 한다 (`.info { border-left: 0; border-top: 1px }`).

### 2. 푸터는 별도 컴포넌트다

`AppFooter.vue` 가 테마 store 를 읽는다. `DashboardShell` 에 넣으면 셸이
테마를 알게 되고, **두 테마가 같은 셸 인스턴스를 공유한다**는 보장(ADR 0001)
을 지키는 정적 검사가 깨진다. `AppHeader` 가 `ThemeSwitcher` 를 품는 것과
같은 구조다 — 테마를 아는 책임을 잎으로 민다.

### 3. 그리드를 3행으로 바꾸고 늘이지 않는다

```
'deck   clock'      (기존: 'deck clock' / 'deck weather' / 'deck player' / 'mascot player')
'deck   weather'
'mascot player'
```

`align-items: start` 를 함께 둔다. 기존 4행 배치에서는 마스코트가 넷째 행,
즉 **열 바닥**에 놓여 데크와 300px 가까이 벌어졌다. 승인된 디자인에서는
마스코트가 데크 바로 아래다.

**남는 차이**: 데크가 위 두 행의 내용보다 크면 그 차이가 두 행에 나뉘어,
시계와 날씨 사이가 레퍼런스보다 약 35px 넓어진다 (1440px 실측). 첫 행을
`max-content` 로 묶어봤지만 막히지 않았다 — 두 트랙 모두 내재 크기라 분배
대상이다. 래퍼 없이 두 열을 각자 흐르게 할 방법이 없으므로 여기까지가
한계다. 300px 를 35px 로 줄이는 거래로 받아들인다.

### 4. 최소 크기는 **플레이어 뷰포트** 기준이다

공식 요구는 iframe 이 200×200 이상이라는 것이다. 테두리는 그 바깥이다.
`box-sizing: border-box` 아래에서 `min-height: 200px` 만 두면 iframe 은
198px 이 된다 — 360px 화면에서 실제로 그랬다.

```css
--video-border-width: 1px;
min-height: calc(var(--size-video-min) + 2 * var(--video-border-width));
```

### 5. 작은 컨트롤은 이웃의 치수에 맞춘다

`.track-play` 는 승인된 디자인에 높이가 없어 글자 높이(22px)가 됐다. 같은
행의 `.track-controls button` 이 29px 이므로 그 값으로 맞춘다. **새 치수를
만들지 않고** 24px 최소 터치 목표를 넘긴다.

### 6. 브랜드를 `h1` 으로 올린다

레퍼런스는 `<span class="brand">` 라서 페이지에 제목이 하나도 없다. 그러면
드로어의 `<h2>` 가 첫 제목이 되어 단계가 끊기고, 보조기기 사용자는 문서의
시작을 찾을 수 없다. `.brand` 의 `font` 단축 속성이 크기·굵기를 다시 정하고
`margin: 0` 이 여백을 지우므로 **보이는 모습은 같다** (ADR 0004 와 같은 판단
— 작성된 의도를 따른다).

### 7. 가시성 안내는 상황이 풀리면 지운다

"영상이 보이지 않아 재생할 수 없어요" 가 영상이 다시 보이는 동안 남아 있으면
사실과 어긋난다. 코디네이터가 안내의 **출처**를 기억했다가, 다시 보이면
가시성 안내만 지운다. 오류·큐 끝 안내는 사정이 그대로이므로 남긴다.
안내를 지워도 **재생을 되살리지는 않는다** (M3-4 의 수동 복귀 원칙).

### 8. 검증은 CDP 로 한다

`--dump-dom` 으로는 뷰포트를 바꿔가며 잴 수 없고 실제 키 입력도 못 보낸다.
최소 CDP 클라이언트를 두고 `Emulation.setDeviceMetricsOverride`(360px 모바일
에뮬레이션, DPR 3), `Emulation.setEmulatedMedia`(모션 감소),
`Input.dispatchKeyEvent`(Tab · Enter · ESC · Space), `Page.captureScreenshot`
을 쓴다. 측정 스크립트는 저장소에 넣지 않는다 — 제품 코드가 아니고, 결과를
문서와 테스트에 옮기는 것이 재현 가능한 형태다.

## 대안

| 대안                                      | 왜 택하지 않았는가                                                           |
| ----------------------------------------- | ---------------------------------------------------------------------------- |
| 열마다 DOM 래퍼를 둔다 (레퍼런스 방식)    | 위젯 루트가 그리드의 직계 자식이 아니게 되어 iframe 이 재로드된다 (ADR 0002) |
| 구분선을 각 위젯의 `border-left` 로       | 간격마다 선이 끊긴다. 레퍼런스의 선은 이어져 있다                            |
| 구분선을 배경 그라디언트로                | `clamp()` 패딩과 간격에 맞춰 위치를 계산할 수 없다                           |
| `min-height` 를 `.player-mount` 로 옮긴다 | 절대 위치라 홀더 밖으로 2px 삐져나와 상태 영역을 덮는다                      |
| `.track-play` 를 42px 로 키운다           | 승인된 디자인의 행 높이가 바뀐다. 이웃 버튼의 29px 가 이미 기준이다          |
| 마스코트를 승인된 위치 그대로 두기        | 승인된 위치가 **데크 바로 아래**다. 지금이 그것과 달랐다                     |

## 결과

- 승인된 디자인과의 차이가 **하나**(정보 열 35px)만 남았고 그 이유가 적혀 있다.
- 1440 · 1100 · 1000 · 730 · 650 · 600 · 500 · 360px 전부, 두 테마 모두에서
  가로 오버플로가 없다.
- 360px 에서도 플레이어 뷰포트가 200×200 을 넘는다 (306×200 실측).
- 24px 미만 터치 목표가 없다.
- `h1 → h2 → h3` 로 제목 단계가 이어진다.
