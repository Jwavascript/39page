# 0021. Music Moments UI — 정보 열의 빈자리에 두고, 재생이 실제로 시작된 뒤에만 저장한다

- 상태: 채택 — **M9-4 에서 구현·실측 (2026-11-10)**
- 관련: **ADR 0019** (Moment 도메인), **ADR 0020** (시점 조회·이동),
  **ADR 0011** (가시성 가드), **ADR 0002** (플레이어 영속),
  **ADR 0005** (그리드 영역 레이아웃), `docs/product/MUSIC_MOMENTS.md` F13~F16,
  `docs/architecture/MOMENTS_DESIGN.md` §9

## 배경

M9-1 은 UI 자리를 **설계안**으로만 남기고 "M9-4 에서 실측으로 확정" 이라고 적었다
(`MUSIC_MOMENTS.md` §5). 저장 버튼은 "플레이어 영역, 트랜스포트와 같은 줄의 형제",
목록은 "3열의 빈 자리" 였다. M9-3 은 실제 IFrame API 에서 **새 영상을 적재한 뒤
약 200ms 동안 `0` 이 보고되는 창**을 관측하고 그 처리를 M9-4 로 넘겼다.

이 ADR 은 그 둘과, 구현하면서 정해야 했던 나머지를 기록한다.

## 결정

### 1. 저장 버튼은 트랜스포트 줄이 아니라 Moments 위젯 안에 둔다 — 설계안에서 벗어남

**실측** (기준 빌드 `97af2fe`, Chromium 155):

| 확인한 것                   | 값                                                                       |
| --------------------------- | ------------------------------------------------------------------------ |
| 360px 에서 트랜스포트 줄 폭 | 308px 중 ~297px 사용 (`⏮ ▶ ⏭` + `YOUTUBE에서 열기 ↗`)                    |
| 넓은 화면 정보 열의 빈자리  | 1280×800 **274px** · 1440×900 313px · 1920×1080 419px (날씨 아래 3·4 행) |
| 플레이어 열이 늘어날 때     | 1·3 행 높이를 플레이어가 정하므로 **플레이리스트·마스코트 행이 밀린다**  |

- 트랜스포트와 **같은 줄**은 360px 에서 자리가 없다 — 버튼 하나만 더해도 넘친다
- 플레이어 영역 **아래 줄**에 두면, 메모 폼을 여는 순간 플레이어 열이 ~220px
  늘어나 아래 행 전체가 밀린다. 저장할 때마다 화면이 출렁인다
- `PlayerSurface` 가 Moments 를 품으면 `playback` → `moments` 기능 간 직접
  import 가 생긴다 (`AGENTS.md` 규칙 2). `PlayerSurface` 는 iframe 을 품은
  가장 민감한 컴포넌트이고, 조건부 렌더를 쓰지 않는다는 원칙이 있다 (ADR 0002)

그래서 저장 버튼·메모 폼·목록을 **한 위젯**(`MomentsWidget`)에 모은다.

- 넓은 화면: **정보 열의 빈자리**(3·4 행). 플레이어 바로 오른쪽이다
- 좁은 화면(≤1100px): **플레이어 바로 아래 한 행**. 시계·날씨가 한 칸 내려간다
  (M9-1 이 남긴 TODO "세로 화면 자리" 를 여기서 닫는다. 실기기는 미확인)

영상 위가 아니므로 네이티브 컨트롤을 가리지 않는다 (III.I.6).

### 2. 넓은 화면에서 위젯은 행 높이를 정하지 않는다 — `contain: size`

`WidgetHost` 에서 Moments 만 `contain: size` + `align-self: stretch` 를 갖는다.
자기 내용이 트랙 크기 계산에 끼어들지 않고, 데크·플레이어·플레이리스트·
마스코트가 정한 칸을 그대로 채운다. 넘치는 내용은 **위젯 안에서** 스크롤한다.

실측: 폼을 열기 전/후 호스트 바닥·플레이리스트·마스코트 위치와 위젯 높이가
1101 · 1280 · 1440px 에서 **모두 같았다.** 1280×800 에서는 폼이 칸보다 14px 커서
위젯 몸통 안에서만 스크롤됐다.

좁은 화면에서는 자기 행을 가지므로 `contain` 을 푼다. 풀지 않으면 행이 0 이 된다.

### 3. 저장 버튼은 **재생이 실제로 시작된 뒤에만** 켠다 — 200ms 의 가짜 0초

새 영상을 적재하면 플레이어는 지정 시점으로 가기 전 `0` 을 보고한다. **영상은
맞고 시간만 틀린 값**이라 M9-3 의 영상 식별 판정(`getVideoUrl()`)을 통과한다.

"마지막 명령 이후 실제로 재생이 시작됐는가" 는 코디네이터가 이미 `ENDED` 판정에
쓰던 사실(`hasStartedPlaying`)이다. 그것을 **playback store 로 옮기고** 파생값
`isPositionReliable` 을 두었다.

```
isPositionReliable = 현재 트랙 있음 ∧ hasStartedPlaying ∧ 상태가 idle·error 가 아님
```

- 저장 버튼의 활성 상태와 코디네이터의 `capturePosition()` 이 **같은 값**을 본다.
  둘이 따로 판정하면 버튼은 켜졌는데 저장이 거절되거나 그 반대가 된다
- 같은 사실을 두 곳에 두지 않았다 — 코디네이터의 지역 변수를 **옮겼다**
- 정상적으로 확인된 **0초는 유효하다.** 판정은 숫자를 보지 않는다

**실측이 이 결정을 뒷받침한다.** B 로 넘어가는 순간 앱의 상태는 아직 A 의
`재생 중` 이었는데 iframe 의 `<video>` 는 이미 **B · 0초 · 정지**였다 (표본 5개).
재생 상태만 보고 버튼을 켰다면 거기서 B 의 0초 Moment 가 만들어졌다. 그 동안
버튼은 전부 꺼져 있었다.

### 4. 누른 순간을 고정하고, 곡이 바뀌면 **알리되 대상은 바꾸지 않는다**

누르면 `{ videoId, atSeconds, title }` 을 복사해 폼 위에 보여준다. 메모를 쓰는
동안 재생이 흘러가도, 곡이 바뀌어도 저장되는 것은 그 줄에 적힌 순간이다
(ADR 0020 결정 4). 곡이 바뀌면 "재생 중인 곡이 바뀌었어요. 메모는 위에 적힌
순간에 저장됩니다." 를 띄운다.

다시 확인을 받는 대안(바뀌면 저장 버튼을 막고 재확인)은 택하지 않았다. 대상이
화면에 고정돼 있으므로 사용자가 무엇이 저장되는지 이미 안다 — 확인 단계를
하나 더 두면 메모를 쓰다 곡이 넘어가는 흔한 경우마다 일이 는다.

### 5. 목록 — 영상별 묶음, 가장 최근 순, 지금 곡 강조, `이 곡`/`전체`

- 묶음 순서는 그 영상의 **가장 최근에 만든** Moment 순 (`createdAt`).
  메모를 고쳐도(`updatedAt`) 순서가 바뀌지 않는다 — 고치는 동안 줄이 튀지 않게
- 묶음 안은 `atSeconds` 오름차순, 같은 시점이면 먼저 만든 것이 앞
- **같은 시점의 Moment 를 합치지 않는다.** 메모가 다를 수 있다
  (ADR 0019 의 TODO 를 닫는다)
- 해석할 수 없는 날짜는 가장 오래된 것으로 본다. 버리지 않는다 (ADR 0019 결정 9)
- 지금 곡의 묶음을 강조한다 — 색과 함께 `aria-current` 와 "· 재생 중" 글자로
- 기본 보기는 `전체`. `이 곡` 은 재생 중일 때만 고를 수 있다. 정렬을 지금 곡에
  맞춰 바꾸지 않는다 — 곡이 바뀔 때마다 목록이 재배열되면 찾던 줄을 잃는다

### 6. 표시 제목 3단의 "라이브러리" 는 선택 목록 먼저다

같은 영상이 여러 목록에 다른 이름으로 들어 있을 수 있다. **선택된 목록을 먼저**,
그다음 라이브러리 순서로 보고 처음 만난 이름을 쓴다. Moment 재생이 큐를 고르는
순서(`MOMENTS_DESIGN.md` §4-5)와 같다 — 목록에 보이는 이름과 눌러서 재생되는
트랙의 이름이 같아진다. 라이브러리에 없으면 "· 목록에 없음" 을 함께 보인다.

### 7. 재생은 다른 표면과 같은 길 — 시트를 비키게 한 뒤 가드를 지난다

Moment ▶ 는 `stepAside()` (M7-2) 를 기다린 뒤 `playMoment()` 를 부른다. 가드를
건너뛰는 경로가 아니다 — 시트가 닫혀 가림이 0 이 된 **뒤에** 코디네이터가 다시
잰다. 그래도 가려져 있으면(`display: none` 등) 다른 재생과 같은 문구로 거절한다.

실측 (390×844): 시트가 하단 557px 를 덮은 상태에서 그 위 띠의 ▶ 를 누르자 시트가
닫히고, 플레이어를 화면 안으로 끌어온 뒤(336×200) B 가 61초부터 재생됐다.

### 8. 접기·펼치기는 좁은 화면에서만 그린다

F14 는 "플레이리스트 위젯과 같은 펼침 방식" 이다. 좁은 화면에서는 같은 토큰
(`--size-playlist-collapsed-max-height` / `--size-playlist-max-height`)과 같은
기본값(접힘)을 쓴다. 넓은 화면에서는 위젯이 이미 정해진 칸을 채우므로 접어도
아무것도 올라오지 않는다 — 토글을 그리지 않는다.

### 9. 그 밖에

| 항목         | 결정                                                                                  |
| ------------ | ------------------------------------------------------------------------------------- |
| 시간 표기    | YouTube 와 같은 `0:42` · `12:05` · `1:02:03`. 실시간 시계는 두지 않는다 (타이머 없음) |
| 메모 입력    | `maxlength=500` + 글자 수 + 넘기면 저장 막음 (스크립트·붙여넣기 경로)                 |
| 메모 표시    | 보간만 쓴다. HTML 로 해석하지 않는다. 첫 줄만, 전체는 `title`                         |
| 삭제         | 그 줄 바로 아래 인라인 확인 (`role="alertdialog"`). 한 건씩. "전부 지우기" 없음       |
| 저장 안내    | `persisted: false` 를 성공으로 말하지 않는다 — 이유와 "새로고침하면 사라짐" 을 함께   |
| 상태 배너    | Moments 전용 배너. 라이브러리와 따로 보호되므로 따로 알린다 (클래스 이름도 다르게)    |
| 포커스 링    | 위젯 안에서는 **안쪽**으로 그린다. 칸 안에서 스크롤하므로 바깥 링이 잘린다            |
| 폼 여는 동안 | 목록·거르기는 잠시 물러난다 (`v-show`). 고치던 메모는 버리지 않는다                   |

| 지금 곡의 묶음을 맨 위로 정렬                       | 곡이 바뀔 때마다 목록이 재배열된다                                             |
| `window.confirm()` 삭제 확인                        | 앱의 다른 삭제(트랙·목록)와 다르다. 테마를 따르지 않는다                       |

## 결과

- 저장 → 목록 → 그 시점 재생이 **실제 YouTube iframe 에서** 확인됐다 (실측 요약은
  `IMPLEMENTATION_PLAN.md` M9-4). 자동재생 우회 플래그 없이 실제 클릭만 썼다
- 레이아웃 데이터가 하나 늘었다 — `WidgetType` · `GridArea` 에 `moments`. 기존
  영역 이름과 순서는 그대로다
- playback store 에 `hasStartedPlaying` · `isPositionReliable` 이 생겼다. 쓰는 곳은
  여전히 코디네이터 하나다
- ⚠ **M9-5 전까지 Moments 는 JSON 백업에 들어가지 않는다.** M9-4 를 운영에
  배포하지 않는다. 그 전에 받은 백업 파일에는 Moment 가 없다
