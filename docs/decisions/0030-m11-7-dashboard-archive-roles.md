# 0030. 대시보드는 지금 재생 큐와 이 곡의 Moments 를 보이고, 관리는 보관함 한 곳에서 한다 (M11-7)

- 상태: **부분 채택 — M11-7B (2026-11-14, 로컬 브랜치).** 사용자가 7개 방향을 골랐다(아래 "사용자 결정"). 그중 대시보드 ·
  보관함 · 헤더 · 모바일은 M11-7B 에서 구현했고, Moment 저장 · 트랙 편집은 채택했지만 M11-7C 에서 구현한다. 고르지 않은
  나머지는 **Proposed** 로 남는다. (제안 — M11-7A)
- 관련: **ADR 0027** (M11 정보 구조 — 이 결정이 입구 · 위젯 역할을 고친다), **ADR 0002** (플레이어 노드 영속), **ADR 0009** (라이브러리와
  재생은 코디네이터로만), **ADR 0011** (가시성 가드), **ADR 0025** (탭 간 잠금), **ADR 0028** 결정 15 (확장의 Moment 는 잡고 저장),
  `docs/product/M11_7_UX_REDESIGN.md`, `design/mockups/m11-7a/`

## 배경

M11 UAT 와 Claude for Chrome 평가에서: Moment 저장 상태가 헷갈리고(U1), 대시보드에서 지금 목록의 곡을 고를 수 없고(U2), 보관함에서
곡이 목록 아래로 밀리고(U3), 곡 순서를 한 칸씩 옮기며(U5), 같은 곳으로 가는 입구가 많았다(U8). 고른 목록과 재생 중인 목록이 함께
강조되고, 순서를 바꿔도 재생 순서가 그대로인데 알려 주지 않았다 — 큐는 재생 시작 때의 스냅샷이고 **어느 목록에서 왔는지 기록하지
않는다**.

## 결정 (추천 — 사용자 선택 대기)

1. **헤더 입구는 "▤ 보관함" · "⇩ 데이터 · 백업" · 테마 전환.** 음악 · Moments 입구를 보관함 하나로 합치고 마지막 탭으로 연다.
2. **PLAYLISTS 카드 위젯을 NOW PLAYLIST(지금 재생 큐) 위젯으로 바꾼다.** 큐가 있으면 큐와 출처 목록 이름, 없으면 고른 목록을 "재생 대기"
   로. 줄을 누르면 큐 안의 그 자리로. 목록 바꾸기는 위젯 안 펼침(플레이어를 덮는 떠 있는 팝오버를 쓰지 않는다).
3. **큐의 출처를 메모리에 기록한다**(저장하지 않는다). 출처 목록이 바뀌면 알리고 "새 순서로 이어 재생" 을 준다. 마지막 재생 목록은
   기억하지 않는다 — 기억하려면 저장 변경이 필요하다.
4. **대시보드 Moments 위젯 = 이 곡의 모든 Moments.** 데스크톱은 고정 높이 안쪽 스크롤(흐림 + "n개 더"), 모바일은 펼치기.
5. **음악 보관함 = 목록 칸 | 상세 칸 (모바일은 두 단계).** 이름 바꾸기 · 삭제는 목록 칸의 ⋯, 전체 재생 · 링크 추가는 상세 칸.
6. **보관함이 열리면 왼쪽 재생 열에 영상 · 조작 · 이 곡 Moments 를 남긴다**(CSS 영역만 — 노드 이동 없음). iframe 을 숨기거나 덮는
   미니 플레이어는 쓰지 않는다.
7. **Moment 저장은 "시점 잡기 → 최종 저장"(B).** 확장 패널과 같다. 저장 형식 · store 계약은 같다.
8. **곡 편집은 혼합(C)** — 데스크톱 ≡ 끌기 + ⋯ 메뉴, 모바일 편집 모드, 키보드 Space+화살표. 라이브러리 없이 직접 구현하고 store 에
   `moveTrackTo` 를 더한다(같은 잠금 · 개정 번호 · 저장 형식).
9. **모바일 순서는 영상 → 이 곡 Moments → NOW PLAYLIST → 데크.**

## M11-7B 에서 정한 구현 세부 (결정의 범위 안)

- **헤더의 "보관함" 은 마지막으로 쓰던 탭**으로 연다 — 셸의 메모리에만 있다 (저장 안 함, 새로고침하면 음악 탭). 데크 →
  음악 탭, Moments 위젯 "모두 보기" → Moments 탭은 그대로다.
- **NOW PLAYLIST 의 "목록 바꾸기"** 는 위젯 안에서 펼치고, 고르면 그 목록을 **"재생 대기" 로 보여 줄 뿐** 재생을 바꾸지 않는다
  (추천안의 "고르면 처음부터 재생" 대신 — 지시서 3-5 "목록 전환이 기존 재생을 무조건 변경하지 않음"). 대기 목록의 곡을
  누르거나 "처음부터 재생" 을 눌러야 큐가 바뀐다. "재생 중인 큐 보기" 로 돌아온다.
- **출처를 모르는 큐**(목록 밖 영상의 Moment 재생)는 "현재 재생 큐" 라고 부른다.
- **새 순서로 이어 재생**: 지금 곡을 **트랙 id** 로 바뀐 목록에서 찾아 그 자리에 선다. 플레이어에는 아무 명령도 보내지 않아
  재생 위치 · 소리가 끊기지 않는다. 지금 곡이 목록에서 빠졌으면 이어 갈 수 없으므로 "바뀐 목록을 처음부터 재생" 을 준다.
  견주는 것은 트랙 id · 영상 · 제목과 순서다 (이름 바꾸기도 "바뀜").
- **목록 관리**는 목록 칸 행의 "관리"(곡 줄과 같은 방식)로 편다 — 추천안의 "⋯" 대신 글자 단추. 목록 칸에는 재생 단추가 없다.
- **작은 영상 띠**: 영상 384px 이상(16:9 → 216px), 옆에 지금 곡 · 조작, 그 옆(좁으면 아래)에 "이 순간 저장" — **대시보드와
  같은 위젯 인스턴스**를 CSS 로 다시 놓는다. 보관함 높이는 화면 안에서 끝나게 재서 맞춘다(300–900px). 세로 화면은 쌓기,
  낮은 가로 화면은 옆 배치(M11-2 의 두 배치를 그대로 쓰고 재생 띠만 더했다).
- **모바일 작은 데크 띠**: 데크 아트를 **자르지 않고 통째로 줄여**(118–164px) 왼쪽에, 안내를 옆에 둔다 — 레퍼런스 변형이 없어
  별도 승인이 필요하지 않다. 줄어든 아트의 재생 키는 누를 수 없는 크기라 끄고, 띠 전체가 보관함 열기다. 순서: 데크 띠 →
  영상 → 이 곡 Moments → NOW PLAYLIST.
- **낮은 가로 화면의 대시보드**는 영상을 첫 행에 둔다 — 실측에서 폰을 가로로 돌리면 영상이 화면 밖으로 밀려 가시성 가드가
  재생을 멈췄다 (기존 동작 · 이번에 찾아 고침).

## 대안

헤더 H2(좁으면 더보기), 카드 위젯 유지, 보관함 배치 A(지금) · C(작은 영상 띠), Moment 바로 저장(A), 편집 A · B, SortableJS, 모바일 M2(잘라 쓴
작은 데크) — 비교는 `M11_7_UX_REDESIGN.md` §3 · §9 · §10 · §11 · §12.

## 결과 (채택되면)

- 저장 키 · 백업 스키마 · 확장 저장 계약은 바뀌지 않는다. 새 상태는 메모리의 큐 출처뿐.
- 코디네이터 계약에 큐 읽기 전용 보기 · `playQueueIndex` · `resyncQueueFromSource` 가 더해진다(ADR 0009 — 라이브러리 화면은 여전히 계약만 안다).
- `PlaylistWidget` · `PlaylistTile` 이 NOW PLAYLIST 로 대체되고, `ArchivePlaylistNav` · `PlaylistEditor` · `TrackList` · `MomentsWidget` 의 역할이 바뀐다.
- ADR 0027 결정 2(헤더 입구 셋) · 5(Moments 위젯 최대 3행) · D2(바로 저장)를 대체한다.
