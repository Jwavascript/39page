# 0030. 대시보드는 지금 재생 큐와 이 곡의 Moments 를 보이고, 관리는 보관함 한 곳에서 한다 (M11-7)

- 상태: **부분 채택 — M11-7B (2026-11-14) · M11-7C (2026-11-15), 로컬 브랜치.** 사용자가 고른 방향 중 대시보드 · 보관함 ·
  헤더 · 모바일은 M11-7B 에서, Moment 저장 B · 트랙 편집 C · Moments 위젯 "이 곡 전체" 는 M11-7C 에서 구현했다. 고르지 않은
  나머지(마지막 재생 목록 기억 · 데크 본체 누름 · 같은 영상의 대표 제목)는 **Proposed** 로 남는다. (제안 — M11-7A)
- 관련: **ADR 0027** (M11 정보 구조 — 이 결정이 입구 · 위젯 역할을 고친다), **ADR 0002** (플레이어 노드 영속), **ADR 0009** (라이브러리와
  재생은 코디네이터로만), **ADR 0011** (가시성 가드), **ADR 0025** (탭 간 잠금), **ADR 0028** 결정 15 (확장의 Moment 는 잡고 저장),
  `docs/product/M11_7_UX_REDESIGN.md`, `design/mockups/m11-7a/`

## 배경

M11 UAT 와 Claude for Chrome 평가에서: Moment 저장 상태가 헷갈리고(U1), 대시보드에서 지금 목록의 곡을 고를 수 없고(U2), 보관함에서
곡이 목록 아래로 밀리고(U3), 곡 순서를 한 칸씩 옮기며(U5), 같은 곳으로 가는 입구가 많았다(U8). 고른 목록과 재생 중인 목록이 함께
강조되고, 순서를 바꿔도 재생 순서가 그대로인데 알려 주지 않았다 — 큐는 재생 시작 때의 스냅샷이고 **어느 목록에서 왔는지 기록하지
않는다**.

## 결정 (추천 — 사용자 선택 대기)

1. **헤더 입구는 "▤ 보관함" · "⇩ 데이터 · 백업" · 테마 전환.** 음악 · Moments 입구를 보관함 하나로 합치고 마지막 탭으로 연다.
2. **PLAYLISTS 카드 위젯을 NOW PLAYLIST(지금 재생 큐) 위젯으로 바꾼다.** 큐가 있으면 큐와 출처 목록 이름, 없으면 고른 목록을 "재생 대기"
   로. 줄을 누르면 큐 안의 그 자리로. 목록 바꾸기는 위젯 안 펼침(플레이어를 덮는 떠 있는 팝오버를 쓰지 않는다).
3. **큐의 출처를 메모리에 기록한다**(저장하지 않는다). 출처 목록이 바뀌면 알리고 "새 순서로 이어 재생" 을 준다. 마지막 재생 목록은
   기억하지 않는다 — 기억하려면 저장 변경이 필요하다.
4. **대시보드 Moments 위젯 = 이 곡의 모든 Moments.** 데스크톱은 고정 높이 안쪽 스크롤(흐림 + "n개 더"), 모바일은 펼치기.
5. **음악 보관함 = 목록 칸 | 상세 칸 (모바일은 두 단계).** 이름 바꾸기 · 삭제는 목록 칸의 ⋯, 전체 재생 · 링크 추가는 상세 칸.
6. **보관함이 열리면 왼쪽 재생 열에 영상 · 조작 · 이 곡 Moments 를 남긴다**(CSS 영역만 — 노드 이동 없음). iframe 을 숨기거나 덮는
   미니 플레이어는 쓰지 않는다.
7. **Moment 저장은 "시점 잡기 → 최종 저장"(B).** 확장 패널과 같다. 저장 형식 · store 계약은 같다.
8. **곡 편집은 혼합(C)** — 데스크톱 ≡ 끌기 + ⋯ 메뉴, 모바일 편집 모드, 키보드 Space+화살표. 라이브러리 없이 직접 구현하고 store 에
   `moveTrackTo` 를 더한다(같은 잠금 · 개정 번호 · 저장 형식).
9. **모바일 순서는 영상 → 이 곡 Moments → NOW PLAYLIST → 데크.**

## M11-7B 에서 정한 구현 세부 (결정의 범위 안)

- **헤더의 "보관함" 은 마지막으로 쓰던 탭**으로 연다 — 셸의 메모리에만 있다 (저장 안 함, 새로고침하면 음악 탭). 데크 →
  음악 탭, Moments 위젯 "모두 보기" → Moments 탭은 그대로다.
- **NOW PLAYLIST 의 "목록 바꾸기"** 는 위젯 안에서 펼치고, 고르면 그 목록을 **"재생 대기" 로 보여 줄 뿐** 재생을 바꾸지 않는다
  (추천안의 "고르면 처음부터 재생" 대신 — 지시서 3-5 "목록 전환이 기존 재생을 무조건 변경하지 않음"). 대기 목록의 곡을
  누르거나 "처음부터 재생" 을 눌러야 큐가 바뀐다. "재생 중인 큐 보기" 로 돌아온다.
- **출처를 모르는 큐**(목록 밖 영상의 Moment 재생)는 "현재 재생 큐" 라고 부른다.
- **새 순서로 이어 재생**: 지금 곡을 **트랙 id** 로 바뀐 목록에서 찾아 그 자리에 선다. 플레이어에는 아무 명령도 보내지 않아
  재생 위치 · 소리가 끊기지 않는다. 지금 곡이 목록에서 빠졌으면 이어 갈 수 없으므로 "바뀐 목록을 처음부터 재생" 을 준다.
  견주는 것은 트랙 id · 영상 · 제목과 순서다 (이름 바꾸기도 "바뀜").
- **목록 관리**는 목록 칸 행의 "관리"(곡 줄과 같은 방식)로 편다 — 추천안의 "⋯" 대신 글자 단추. 목록 칸에는 재생 단추가 없다.
- **작은 영상 띠**: 영상 384px 이상(16:9 → 216px), 옆에 지금 곡 · 조작, 그 옆(좁으면 아래)에 "이 순간 저장" — **대시보드와
  같은 위젯 인스턴스**를 CSS 로 다시 놓는다. 보관함 높이는 화면 안에서 끝나게 재서 맞춘다(300–900px). 세로 화면은 쌓기,
  낮은 가로 화면은 옆 배치(M11-2 의 두 배치를 그대로 쓰고 재생 띠만 더했다).
- **모바일 작은 데크 띠**: 데크 아트를 **자르지 않고 통째로 줄여**(118–164px) 왼쪽에, 안내를 옆에 둔다 — 레퍼런스 변형이 없어
  별도 승인이 필요하지 않다. 줄어든 아트의 재생 키는 누를 수 없는 크기라 끄고, 띠 전체가 보관함 열기다. 순서: 데크 띠 →
  영상 → 이 곡 Moments → NOW PLAYLIST.
- **낮은 가로 화면의 대시보드**는 영상을 첫 행에 둔다 — 실측에서 폰을 가로로 돌리면 영상이 화면 밖으로 밀려 가시성 가드가
  재생을 멈췄다 (기존 동작 · 이번에 찾아 고침).

## M11-7C 에서 정한 구현 세부 (결정의 범위 안)

**Moments 정보 구조 (지시서 Part B · C · E)**

- **영상 띠(보관함 열림)의 Moments 는 보기 · 재생 전용**이다 — "이 곡의 Moments N개", 시점 순 전부, 누르면 그 시점부터. 저장 ·
  모두 보기 · 관리가 없다. 대시보드 위젯과 **같은 인스턴스**이고 `archive.isOpen` 으로 모양만 바뀐다. 저장 전 초안이 있으면
  "저장 전 초안 m:ss 이 있어요 · 이 곡 탭에서 이어 쓰기" 만 보인다.
- "이 곡" 은 **실제로 재생 중인 영상**(코디네이터 `nowPlaying`)이다. 보관함에서 고른 목록과 무관하고, 재생 중인 곡이 없으면
  아무 곡도 "이 곡" 이 아니다.
- 대시보드 위젯은 이 곡의 Moments 를 **모두** 보인다(M11-3 의 "최대 3개 · N개 더" 를 대체 — ADR 0027 결정 5). 넓은 화면은
  칸 안 스크롤(`clamp(150px, 30vh, 280px)`, `overscroll-behavior: contain`, 흐림 + "아래에 N개 더"), 700px 이하 대시보드는
  안쪽 스크롤 없이 앞 4개 + "모두 펼치기". **지금 선**("지금 m:ss")이 순간들 사이에 재생 위치를 보인다 — 소리가 날 때만 1초마다
  코디네이터에게 묻는다(`usePlaybackPosition`). 방금 저장한 줄은 "방금 저장" 으로 강조하고 칸 안에서만 보이게 굴린다.
- 보관함 Moments 보기 순서는 **이 곡 → 전체 → 최근**. 자동 기본값은 **Moments 탭에 들어올 때** 정한다(곡이 있으면 이 곡, 없으면
  전체) — 보는 중에 재생이 시작돼도 보기를 바꾸지 않는다(전체에서 ▶ 를 누르자 목록이 사라지는 일을 막는다). 사용자가 고른
  보기는 이 페이지가 살아 있는 동안 탭을 오가도 남는다(저장하지 않음). 음악 탭 ◆ 배지 · 지금 곡 배지는 그 곡으로 들어온다.
- **"이 곡" 은 한 목록인 관리 화면**: 머리에 "이 곡 · Moments N개" 와 **＋ 이 순간 저장**, 아래에 시점 순 줄(▶ · 관리 → 메모
  수정 · 삭제). 곡 제목 · 목록 링크 · 묶음 머리를 되풀이하지 않는다. 전체 · 최근 · 한 곡 보기는 그대로다.

**저장 모델 B (Part D)**

- 누르면 **시점만 잡는다**(영상 · 초 · 제목 스냅샷). 음악은 계속된다. 메모(선택) 뒤 **Moment 저장** 에서 처음 `moments.add`.
  취소하면 아무것도 남지 않는다. 저장 전 초안은 점선 테두리와 "저장 전", 저장된 줄은 "방금 저장" — 두 상태를 섞지 않는다.
  저장한 뒤의 메모 고치기는 보관함 줄의 관리에서만 한다(M11-3 의 "메모 추가/고치기" 는 없앴다).
- 초안은 **하나**이고 Pinia store `momentDraft` 에 있다 — 대시보드와 보관함 이 곡이 같은 초안을 본다(초안 E). 보관함을 닫아도
  남는다(초안 B). 저장하지 않으므로 새로고침하면 사라진다(저장 키 · 백업 형식 변경 없음).
- 곡이 바뀌어도 초안은 처음 영상 · 시점이다(초안 A) — "재생 중인 곡이 바뀌었어요 …" 를 보이고, 지금으로 바꾸는 것은
  **↻ 지금 시점으로 다시 잡기**뿐이다(메모는 지킨다).
- **한 번만 저장**(초안 D): 초안마다 요청 id `ext-web-<32자>` 를 만들어 `moments.add({ id })` 에 넘긴다 — M11-5 의 호출자 id
  계약(`isCallerMomentId`: `ext-` + 16–80자)을 그대로 쓴다. `web-` 이 확장 브리지 id 와 출처를 가른다. 저장 중에는 저장 ·
  다시 잡기 · 취소를 막는다. 다시 잡으면 새 id 다.
- 실패(초안 C): 충돌 · 잠금 대기 · id 충돌은 초안과 메모를 그대로 두고 "저장하지 않았어요 — 초안과 메모는 그대로" 로 말한다.
  보호 · 사용 불가 · 쓰기 실패는 store 가 메모리에 넣고 `persisted: false` 를 주므로(M9 계약) 초안을 닫되 "저장하지 못했어요 …
  새로고침하면 사라집니다" 경고다 — 성공 문구가 아니다.
- 키보드: 메모 칸 Enter = 저장, Shift+Enter = 줄바꿈, 한글 조합 중 Enter 는 저장하지 않는다(`isComposing` · 229).

**트랙 편집 C (Part F)**

- library store **`moveTrackTo(playlistId, trackId, toIndex)`** — 트랙 id 기준, 옮긴 뒤의 자리, 한 번에 바꾼다. 다른 변경과 같은
  `mutation`(Web Locks) · `staleGuard`(리비전)를 지난다. **저장소에 남길 수 없으면 `not-persisted` 로 거절하고 메모리도 그대로**
  둔다 — 먼저 쓰고, 쓰기에 성공했을 때만 메모리를 바꾼다(`commitIfPersisted`). 다른 변경의 "메모리에만 반영 + 경고" 계약은 그대로다.
  기존 `moveTrack(up|down)` 은 남겨 두었다(화면은 더 쓰지 않는다).
- 행 맨 앞 **끌기 손잡이(⠿)** — 포인터 이벤트(마우스 · 펜 · 손가락), 4px 넘게 움직여야 끌기, 놓일 자리에 선, Esc 취소, 스크롤
  칸 가장자리에서 자동 스크롤. 손잡이에만 `touch-action: none`. 마우스 화면은 늘, `(hover: none), (pointer: coarse)` 화면은
  **편집 모드**에서만 보인다.
- 키보드: 손잡이에서 ↑ ↓ 한 칸, Home · End 맨 위 · 맨 아래 — 옮긴 뒤 그 곡의 같은 단추(꺼졌으면 손잡이)에 포커스. 결과는 목록 위
  상태 줄(`role=status`, polite)로 "“곡” 을(를) N번째로 옮겼어요 (M곡 중)." / 거절 사유.
- **편집 모드**(✎ 편집 / 완료): 행마다 손잡이 · ↑ 위로 · ↓ 아래로 · ✎ 이름 · 삭제(44px, 둘째 줄), ▶ · 관리 · ◆ 는 잠시 숨는다.
- 관리 메뉴: 이름 바꾸기 · **맨 위로** · 위로 · 아래로 · **맨 아래로** · 삭제. 데스크톱 인라인 이름 바꾸기는 하지 않았다(행 아래
  폼 유지). 삭제 확인은 그대로이고, 포커스가 확인 단추 → 취소면 삭제 단추 · 지우면 다음(없으면 앞) 곡으로 간다.
- 재생: 큐는 스냅샷이라 그대로다. NOW PLAYLIST 가 "목록이 변경됐어요" 를 보이고 "새 순서로 이어 재생" 을 고를 때만 트랙 id 로
  맞춘다(플레이어 명령 없음 — 위치 유지).

**같은 영상의 대표 제목 (Part G) — 제안, 결정 아님**

- 지금: Moment 는 `videoId` 로 묶이고 저장 스키마 · 관계는 바꾸지 않았다. "이 곡" 은 제목을 되풀이하지 않으므로 이 화면에서는
  혼란이 없다. 전체 · 최근의 제목 정책(라이브러리 현재 제목 → Moment 스냅샷 → 대체 표기)은 바꾸지 않았다.
- 제안(사용자 승인 필요): 대표 제목 = ① 지금 재생 중이면 큐의 그 트랙 제목 ② 아니면 **선택된 목록**에 그 영상이 있으면 그 목록의
  첫 트랙 제목 ③ 아니면 라이브러리에서 그 영상을 가진 목록 중 **가장 앞 목록**의 첫 트랙 제목 ④ 가장 최근 Moment 스냅샷 ⑤
  `YouTube · <id>`. 모두 화면 계산이라 저장 변경이 없다. 고르기 전에는 지금 정책을 유지한다.

## 결과 (채택되면)

- 저장 키 · 백업 스키마 · 확장 저장 계약은 바뀌지 않는다. 새 상태는 메모리의 큐 출처뿐.
- 코디네이터 계약에 큐 읽기 전용 보기 · `playQueueIndex` · `resyncQueueFromSource` 가 더해진다(ADR 0009 — 라이브러리 화면은 여전히 계약만 안다).
- `PlaylistWidget` · `PlaylistTile` 이 NOW PLAYLIST 로 대체되고, `ArchivePlaylistNav` · `PlaylistEditor` · `TrackList` · `MomentsWidget` 의 역할이 바뀐다.
- ADR 0027 결정 2(헤더 입구 셋) · 5(Moments 위젯 최대 3행) · D2(바로 저장)를 대체한다.
- M11-7C: 새 store `momentDraft`(화면 상태) · library `moveTrackTo` 와 실패 사유 `not-persisted` 가 더해진다. 저장 키 · 백업 형식 ·
  확장 저장 계약(호출자 id 형식 포함)은 그대로다. ADR 0027 D2 의 "누르면 바로 저장" 은 저장 모델 B 로 대체된다(확장의 캡처 —
  ADR 0026 — 는 바뀌지 않는다).
