# 0010. 재생 상태는 라이브 리전이 아니라 부제에 적고, 토글 버튼은 상태에 맞는 이름을 쓴다

- 상태: 채택
- 날짜: 2026-11-03
- 구현: M3-3
- 관련: `docs/decisions/0004-unapplied-reference-rules.md`,
  `docs/product/MVP_SPEC.md` F3, `docs/architecture/SYSTEM_DESIGN.md` §4.7

## 배경

M3-3 에서 승인된 프로토타입의 트랜스포트를 옮기다가, 그대로 옮기면
**보조기기 사용자에게 나쁜** 두 지점을 만났다.

**1. 상태 메시지 영역이 전이 상태까지 읽는다.**

프로토타입은 `#status`(`role="status" aria-live="polite"`)에 재생 전이를
그대로 쓴다.

```js
if (evt.data === YT.PlayerState.PLAYING) setStatus('재생 중 · 곡이 끝나면 다음 영상을 재생합니다.')
else if (evt.data === YT.PlayerState.BUFFERING) setStatus('버퍼링 중…')
```

`aria-live` 영역은 **내용이 바뀔 때마다 읽힌다.** 한 곡을 듣는 동안
버퍼링 → 재생 → (일시정지 → 재생)\* → 종료가 이어지므로, 사용자가 아무것도
하지 않아도 스크린 리더가 계속 끼어든다. 곡을 넘길 때마다 또 반복된다.

**2. 토글 버튼의 접근성 이름이 상태를 말하지 않는다.**

```html
<button
  class="round main"
  id="playToggle"
  title="재생 또는 일시정지"
  aria-label="재생 또는 일시정지"
>
  ▶
</button>
```

보이는 기호는 `▶` ↔ `Ⅱ` 로 바뀌는데 **이름은 고정**이다. 눈으로 보는
사용자는 지금 누르면 무엇이 되는지 알지만, 이름만 듣는 사용자는 모른다.

## 결정

### 1. 라이브 리전에는 **의도적으로 띄운 안내만** 담는다

`.status` 의 내용은 `playback.statusMessage` 뿐이다. 비어 있으면
**큐가 아직 없을 때만** 승인된 기본 문구를 쓰고, 재생 중에는 비워둔다.

| 상황                 | `.status`                                                          |
| -------------------- | ------------------------------------------------------------------ |
| 큐 없음              | `재생 목록을 만들고 YouTube 링크를 추가해 보세요.` (승인된 기본값) |
| 재생·일시정지·버퍼링 | **비움** — 읽을 거리가 없다                                        |
| 큐 끝                | `마지막 곡까지 재생했습니다.`                                      |
| 오류 · 자동재생 차단 | 경고 어조로 사유                                                   |

`.status` 는 `min-height: 39px`(승인된 값) 이므로 비워도 레이아웃이
흔들리지 않는다. 내용이 같으면 Vue 가 DOM 을 건드리지 않아 다시 읽히지도
않는다.

**재생 상태는 `NOW PLAYING` 부제에 적는다.** 라이브 리전이 아니므로
바뀌어도 읽히지 않고, 필요할 때 읽으면 된다.

```
2 / 5 · YOUTUBE · 재생 중
```

### 2. 토글 버튼의 이름은 상태를 따라간다

`aria-label` 과 `title` 이 보이는 기호와 같은 뜻이다.

| 상태                                  | 기호 | 이름       |
| ------------------------------------- | ---- | ---------- |
| `playing` · `loading`                 | `Ⅱ`  | `일시정지` |
| `paused` · `idle` · `ended` · `error` | `▶`  | `재생`     |

`loading` 도 `Ⅱ` 인 이유: 사용자가 방금 재생을 눌러 플레이어가 올라오는
중이다. `▶` 를 보여주면 또 누르게 되고 그 누름은 아무 일도 하지 않는다.
`Ⅱ` 면 **시작을 취소**할 수 있다 — 어댑터의 `pause()` 가 보류한 재생
요청을 지운다 (ADR 0008).

## 대안

| 대안                                       | 탈락 이유                                                                                         |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| 프로토타입대로 전이 상태를 라이브 리전에   | 한 곡마다 서너 번, 큐 길이만큼 반복해서 읽힌다. 안내가 아니라 방해가 된다                         |
| `aria-live="off"` 로 바꾸고 전이 상태 유지 | 정작 알려야 할 오류·큐 끝도 안 읽힌다. `MVP_SPEC.md` F3 가 요구하는 `polite` 영역이 사라진다      |
| 상태를 라이브 리전에 두되 디바운스         | 타이밍으로 푸는 문제가 아니다. 느리게 읽어도 읽을 가치가 없는 내용이다                            |
| 토글 이름을 고정 `재생 또는 일시정지`      | 지금 누르면 무엇이 되는지 이름만으로 알 수 없다. 보이는 기호와 이름이 어긋난다                    |
| `aria-pressed` 로 토글 상태를 표현         | 이 버튼은 "눌린 상태"가 아니라 **다른 동작**으로 바뀐다. 토글 버튼 패턴이 아니라 이름 교체가 맞다 |

## 결과

- 승인된 레퍼런스와 **렌더 결과가 달라지는 지점**이 둘 생겼다.
  `.status` 가 재생 중 비어 있고, 토글의 `aria-label` 이 바뀐다.
  보이는 색·크기·간격·기호는 그대로다.
- 둘 다 **사람의 확인이 필요한 항목**으로 보고했다. 되돌리려면
  `useTransport.ts` 의 `statusText` 와 `toggleLabel` 만 바꾸면 된다.
- 이 결정은 ADR 0004 의 기준("작성된 의도가 있으면 의도를")과 **다르다.**
  거기서는 색이 문제였고 의도가 분명했다. 여기서는 작성된 의도를 그대로
  따르면 접근성이 나빠진다. 의도를 버리는 것이 아니라, **같은 의도(상태를
  알린다)를 더 나은 수단으로** 구현한다.
