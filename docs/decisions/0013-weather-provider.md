# 0013. 날씨는 Open-Meteo 에서 키 없이 받고, 위치는 서울로 고정한다

- 상태: 채택
- 날짜: 2026-11-03

## 배경

`MVP_SPEC.md` F7 은 MVP 기능 중 가장 미확정이었다. 승인된 디자인은
**레이아웃만** 확정했고 값은 고정 예시였다 (`☁ 18° 조금 흐림 H 22° / L 12°`,
주석 `WEATHER / 디자인 예시 · 실제 API 연결 전`).

닫아야 할 것이 넷이었다.

1. **제공자** — 39page 는 클라이언트 전용이다 (`SYSTEM_DESIGN.md` §1).
   API 키가 필요한 제공자를 고르면 키가 번들에 들어간다. 그걸 피하려면
   서버나 프록시가 필요하고, 그것은 §1 의 결정을 뒤집는 일이다.
2. **위치** — 사용자의 현재 위치를 추정해 확정된 위치처럼 보여주면 안 되고,
   위치 권한을 자동으로 요구해서도 안 된다.
3. **실패 표시** — 가짜 날씨를 정상 결과처럼 보여주면 안 된다.
4. **요청 제한** — 무료 제공자를 쓰면서 예의를 지켜야 한다.

## 결정

### 1. 제공자는 Open-Meteo

```
https://api.open-meteo.com/v1/forecast
  ?latitude=37.5665&longitude=126.978
  &current=temperature_2m,weather_code
  &daily=temperature_2m_max,temperature_2m_min
  &timezone=Asia/Seoul&forecast_days=1
```

고른 이유:

- **API 키가 없다.** 클라이언트 전용 구조를 유지할 수 있다. 서버·프록시를
  들이지 않는다.
- **CORS 가 열려 있다** (`access-control-allow-origin: *`). 실제로 확인했다.
- 승인된 디자인이 필요한 값이 **정확히** 있다 — 현재 기온, 날씨 코드,
  오늘 최고/최저.
- 비상업적 사용이 무료다.
- **npm 패키지를 추가하지 않는다.** `fetch` 와 `URLSearchParams` 로 끝난다
  (`AGENTS.md` 규칙 8의 (b) — 기존 의존성으로 가능하다).

날씨 코드는 WMO 4677 이다. 코드 → 아이콘·설명 표는 우리가 만든다
(`src/widgets/weather/weatherCodes.ts`). 코드 2 의 표시는 승인된 디자인의
예시(`☁` · `조금 흐림`)와 **같다** — 디자이너의 의도와 어긋나지 않는다는
확인이 된다.

### 2. 위치는 서울 고정, 화면에 밝힌다

좌표는 `37.5665, 126.978` 고정이다. **`navigator.geolocation` 을 쓰지
않는다.** 권한 창을 띄우지 않고, IP 기반 추정도 하지 않는다.

위치는 `.weather-note` 에 적는다. 프로토타입에서
`WEATHER / 디자인 예시 · 실제 API 연결 전` 이던 자리가
`WEATHER / SEOUL · OPEN-METEO` 가 된다. **새 UI 를 만들지 않고** 위치와
출처를 밝혀야 하는 요구를 만족시킨다 (`AGENTS.md` 규칙 6).

도시 선택 UI 를 만들지 않는 이유: 승인된 디자인에 그 컨트롤이 없다. 시계도
`SEOUL, KOREA` 고정이므로 두 위젯이 같은 곳을 가리켜 일관된다. 사용자 선택을
도입할 때는 컨트롤 디자인과 영속화를 함께 확정해야 한다 (백로그).

단위는 **°C 고정**이다 (`MVP_SPEC.md` F7 TODO 해소). 승인된 디자인의 표기가
`18°` 이고 대상 지역이 한국이다.

### 3. 실패는 실패로 보여준다

상태는 셋이다. 네 칸(아이콘 · 기온 · 설명 · 최고/최저)은 어느 상태에서도
같은 자리에 있어 레이아웃이 흔들리지 않는다.

| 상태      | 아이콘 | 기온  | 설명                |
| --------- | ------ | ----- | ------------------- |
| `loading` | `·`    | `--°` | 날씨를 불러오는 중… |
| `ready`   | 코드별 | 실제  | 코드별              |
| `error`   | `!`    | `--°` | 사정별 (아래)       |

실패 사유를 셋으로 가른다. 사용자가 할 수 있는 일이 다르다.

- `network` — 요청 자체가 실패했다 (오프라인·DNS·CORS)
- `http` — 응답이 왔지만 2xx 가 아니다 (제공처 장애)
- `malformed` — 2xx 인데 기대한 숫자가 없다

**응답을 믿지 않는다.** 네 값(기온·코드·최고·최저) 중 하나라도 유한한 숫자가
아니면 `malformed` 다. 부분적으로 채워 보여주지 않는다 — 최고·최저가 없는데
기온만 보이면 사용자는 그것이 결측인지 알 수 없다.

**실패하면 이전 값을 지운다.** 오래된 기온을 지금 날씨처럼 보여주는 것이
가짜 데이터를 보여주는 것과 같다.

### 4. 요청 제한은 두 겹

- **모듈 캐시** — 마지막 성공 응답을 5분간 신선하다고 본다. 위젯이 다시
  마운트되어도 즉시 다시 받지 않는다.
- **간격** — 성공 뒤 15분, 실패 뒤 2분에 다시 시도한다.

실패 재시도가 더 짧은 이유: 사용자가 누를 **재시도 버튼이 없다**(승인된
디자인에 없다). 스스로 다시 시도하지 않으면 일시적인 네트워크 장애가 15분
동안 오류 화면으로 남는다. 2분은 그 사이의 타협이다.

하루 요청 수: 탭을 하루 종일 열어두면 성공 경로로 약 96회. 오프라인이 계속
되면 약 720회. Open-Meteo 의 무료 한도(일 1만 회) 안이다.

### 5. Pinia store 를 만들지 않는다

날씨 상태는 위젯 하나만 쓰고 다른 기능이 읽지 않는다. 기능 간 공용 상태
경계가 아니므로 store 로 올리지 않는다 (`AGENTS.md` 규칙 2).
composable (`useWeather`) 이 들고, 모듈 캐시만 인스턴스보다 오래 산다.

## 대안

| 후보                    | 키   | 왜 택하지 않았는가                                                                                  |
| ----------------------- | ---- | --------------------------------------------------------------------------------------------------- |
| **Open-Meteo**          | 없음 | **채택.** 키 없음 · CORS 열림 · 필요한 필드가 정확히 있음 · 패키지 추가 불필요                      |
| OpenWeatherMap          | 필요 | 클라이언트 전용 구조에서 키가 번들에 노출된다. 프록시를 두면 `SYSTEM_DESIGN.md` §1 을 뒤집어야 한다 |
| WeatherAPI.com          | 필요 | 같음                                                                                                |
| 기상청 단기예보 API     | 필요 | 키 문제에 더해 격자 좌표 변환이 필요하고 응답 구조가 복잡하다. MVP 한 위젯에 과하다                 |
| wttr.in                 | 없음 | JSON 형식이 비공식이고 한도가 불명확하다. 의존하기에 근거가 약하다                                  |
| 가짜 데이터 유지        | —    | 승인된 디자인의 주석 자체가 "실제 API 연결 전" 이다. 실제 데이터를 보여주는 것이 M4 의 요구다       |
| 좌표를 사용자 입력으로  | —    | 승인된 디자인에 컨트롤이 없다. 도입하려면 디자인과 영속화를 함께 확정해야 한다 (백로그)             |
| `navigator.geolocation` | —    | 권한 창을 자동으로 띄우면 안 된다. 거부되면 보여줄 것도 없다                                        |

## 결과

- 날씨 위젯이 **실제 데이터**를 보여준다. 가짜 값이 남지 않았다.
- **새 npm 의존성이 없다.** `package.json` 은 그대로다.
- 위치가 화면에 적혀 있고, 위치 권한을 요청하는 코드가 **아예 없다**
  (정적 검사로 고정했다).
- 실패가 조용히 지나가지 않고, 가짜 숫자로 덮이지도 않는다.
- 외부 서비스 의존이 하나 생겼다. 제공처가 사라지면 위젯은 오류 상태로
  남고 **나머지 기능은 영향받지 않는다** — 날씨는 재생·라이브러리·테마와
  어떤 상태도 공유하지 않는다.
- 테스트는 네트워크에 나가지 않는다. 전역 `fetch` 를
  `tests/setup/noNetwork.ts` 가 막고, 날씨 spec 만 필요한 응답을 세운다.
