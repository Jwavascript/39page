# 0007. 읽지 못한 라이브러리 원본은 보호 상태로 두고 덮어쓰지 않는다

- 상태: 채택
- 날짜: 2026-11-03
- 관련: `docs/architecture/SYSTEM_DESIGN.md` §7.1, §7.2,
  `docs/product/MVP_SPEC.md` F9

## 배경

M1-1의 저장 계층은 "읽기는 저장소를 건드리지 않는다"를 보장한다. 손상된
데이터나 상위 버전 데이터를 만나도 지우지 않고 기본값을 돌려준다.

그런데 그 다음이 문제다. 복원이 기본값으로 떨어진 뒤 사용자가 **평범한 수정**
(플레이리스트 하나 생성)을 하면, 그 시점의 저장 호출이 읽지 못했던 원본을
조용히 덮어쓴다. 읽기는 안전했는데 **첫 쓰기에서 데이터를 잃는다.**

테마 설정은 이래도 괜찮다. 값이 하나뿐이고 다시 고르면 그만이다.
라이브러리는 다르다. 사용자가 직접 축적한 데이터이고 복구할 방법이 없다.

## 결정

**라이브러리 store 에 `status` 를 두고, 원본을 읽지 못했으면 쓰기를 막는다.**

| `status`      | 언제                                 | 쓰기          |
| ------------- | ------------------------------------ | ------------- |
| `ready`       | 정상 복원 또는 저장값 없음           | 허용          |
| `unavailable` | 저장소 접근 불가                     | 시도해도 실패 |
| `protected`   | 원본을 읽지 못했거나 **일부만** 복구 | **차단**      |

`protected` 의 이유(`protectedReason`)는 네 가지다.
`malformed` · `invalid` · `version-mismatch` · `partial-recovery`.

**수정은 메모리에서 계속 된다.** 이번 세션에서 할 수 있는 일을 빼앗지 않는다.
다만 저장되지 않으며, 액션의 반환값 `persisted: false` 로 호출자에게 알린다.

### 일부 복구도 보호한다

불량 항목을 버리고 나머지를 살린 경우(`partial-recovery`)도 막는다.
살린 것만 저장하면 **버린 항목이 영구히 사라진다.** 메모리에서 활용하는 것과
원본을 대체하는 것은 다른 문제다.

판정 기준은 **데이터 손실 여부**다. 정규화가 플레이리스트나 트랙을 하나라도
버렸으면 보호한다. 반면 `selectedPlaylistId` 가 존재하지 않는 목록을 가리켜
첫 목록으로 보정한 경우는 **보호하지 않는다.** 잃은 데이터가 없고, 이것까지
막으면 선택이 깨진 사용자가 영영 저장할 수 없게 된다.

## 대안

| 대안                                                    | 탈락 이유                                                                                          |
| ------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 복원 실패 시 그냥 빈 상태로 두고 평소처럼 저장          | 첫 수정에서 원본이 사라진다. 이 ADR 이 막으려는 바로 그 문제                                       |
| 복원 실패 시 손상된 값을 백업 키로 복사해두고 저장 허용 | 키가 늘어나고 백업의 생애주기(언제 지우나)를 또 정해야 한다. MVP 에 과하다                         |
| 복원 실패 시 앱을 멈추고 오류 화면                      | 테마·재생 등 나머지 기능까지 못 쓴다. 저장 실패를 앱 전체 오류로 전파하지 않는다는 방침과 어긋난다 |
| 읽기 시점에 손상 데이터를 지우고 새로 시작              | M1-1 의 보장(읽기는 쓰지 않는다)을 깬다. 복구 가능성을 없앤다                                      |

## 결과

- 손상·상위 버전·일부 복구 상황에서 **원본이 보존된다.** 사용자가 직접
  `localStorage` 를 열어 꺼내거나, 나중에 복구 도구로 되살릴 수 있다.
- 그 상태에서는 저장이 조용히 실패한다. **사용자에게 알리는 UI 가 필요하다.**
  M2-2 의 드로어가 `status === 'protected'` 를 읽어 배너나 안내를 띄우고,
  "기존 데이터를 버리고 새로 시작" 같은 명시적 조작을 제공해야 한다.
  그 확인 UI 와 강제 초기화 액션은 이번 범위에 없다.
- `persisted: false` 를 무시하는 호출자는 저장되지 않은 것을 모른 채 넘어간다.
  반환 계약을 지키는 것이 UI 쪽 책임이 된다.
- 정상 경로에는 영향이 없다. 저장값이 없거나 온전하면 `ready` 다.
