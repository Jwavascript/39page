# 0042. 공유 입구(지금 재생 카드 · 데크 아이콘)와 공유 카드의 내 앨범아트

- 상태: 채택 — 사용자 요청 (2026-11-20), 브랜치 `feat/share-entry-points`
- 관련: ADR 0040 (공유 링크), ADR 0041 (공유 카드 — §3 의 앨범아트 TODO 를 정한다), ADR 0012 §6 (대체),
  ADR 0033 (곡별 앨범아트), `docs/product/MVP_SPEC.md` F3

## 배경

공유는 보관함 안에서만 열 수 있었다 — 목록 "관리" → "이 목록 공유", 곡 "관리" → "공유", Moments 목록. 사용자가 요청했다
(2026-11-20).

- 사용자 앨범아트를 카드에 넣어 달라 (ADR 0041 의 TODO).
- 지금 재생 카드의 "YouTube에서 열기" 단추 대신 **그 자리에** 공유 단추를 **아이콘으로**.
- 플레이리스트 공유는 **카세트 위젯 쪽에** 아이콘으로.

## 결정

1. **지금 재생 카드** — `YOUTUBE에서 열기 ↗` 자리(재생 조작 줄 끝)에 공유 아이콘. 다른 둥근 단추와 같은 44px 원이고 이름은
   `aria-label` · `title` 의 "이 곡 공유" 다. 누르면 공유 대화상자를 **지금 곡**(큐의 출처 목록 · 그 트랙)으로 연다 — 기존
   `SHARE_DIALOG` 를 그대로 쓴다.
   - 곡이 없으면 그리지 않는다.
   - 지금 곡이 보관함 목록에 없으면(재생 중인 목록이 지워짐 · 목록 밖 영상의 Moment 재생) 누를 수 없고, 이유를 이름으로 말한다:
     "보관함 목록에 있는 곡만 공유할 수 있어요".
   - 보관함을 연 좁은 배치(쌓기 · 옆)에서는 셔플 · 반복처럼 숨긴다 — 그 배치는 제목 | 재생 조작만 둔다.
2. **YouTube 링크는 재생 오류 때만** — 늘 보이던 링크(ADR 0012 §6)를 없애고, 플레이어가 알린 오류 안내가 떠 있을 때만
   상태 줄 아래에 글 링크 "YouTube에서 열기 ↗" 로 띄운다. 오류 안내("YouTube 에서 열어보세요")가 가리킬 곳이 남는다 —
   `MVP_SPEC.md` F3 의 "재생 실패 시 외부 링크" 그대로다. 안내가 지워지면(다음 곡 · 다시 재생 · 큐 편집) 함께 사라진다. 새 창 ·
   `noopener noreferrer` 는 그대로.
   - 판단은 플레이어 상태(`error`)가 아니라 **안내의 출처**(`playback.statusCause === 'player-error'`)로 한다. 실제 Chrome 확인에서
     YouTube 플레이어가 오류(150)를 알린 뒤 상태를 또 보내 `error` 가 곧 덮이는 것을 봤다 — 안내는 남는데 링크가 사라졌다.
3. **데크(카세트 · LP)** — 데크 아래 안내 줄("카세트를 누르면 …") 옆에 공유 아이콘. 데크 라벨과 같은 목록 — 재생 큐의 출처
   목록, 큐가 없으면 보관함에서 고른 목록 — 을 **목록 전체**로 연다. 이름은 "지금 목록 공유 — <목록 이름>".
   - 빈 목록 · 목록 없음 · 출처를 모르는 큐는 누를 수 없고 이유를 이름으로 말한다.
   - 아트(SVG) 위에 겹치지 않는다 — 두 테마의 그림을 가리지 않고, 한 열 배치의 작은 데크 띠(아트 약 118–164px)에서도 같은
     자리(안내 오른쪽)다. 판단은 `useDeckShare` 가 한다 (규칙 3).
4. **카드의 내 앨범아트** — 공유 대상의 트랙들 가운데 앞에서부터 **처음 만나는 사용자 그림**(custom)을 넣는다.
   - 찾는 순서: 목록은 곡 순서, 곡은 그 곡, Moment 는 같은 영상의 트랙들(고른 목록 먼저 — 공유 화면이 곡 이름을 찾는 순서).
   - 그 트랙에서 고른 맞춤(채우기 · 맞추기, 위치, 확대)을 앱과 같은 계산으로 따른다 (`artworkPlacement` — CSS 의
     `object-fit` → `object-position` → `scale`). 움직이는 GIF 는 첫 장면이다.
   - 카드 칸의 "내 앨범아트 넣기"(그림이 있을 때만 보인다, 처음엔 켜짐)로 끈다 — 끄면 39page 기본 그림이다.
   - YouTube 썸네일은 여전히 넣지 않는다 (YouTube 정책, ADR 0041 §3).
   - 그림을 읽지 못하면 기본 그림으로 그리고, 미리보기 아래 정보("카세트 J카드 · 앨범아트 · 1080×1350 PNG")에서 "앨범아트" 가 빠진다.

   | 틀           | 그림 자리                                                                         |
   | ------------ | --------------------------------------------------------------------------------- |
   | 카세트 J카드 | 앞면 오른쪽 232px — 테이프 릴 대신. 제목 폭이 658 → 616px                         |
   | LP 뒷면      | 오른쪽 위 224px 재킷 — 모서리 레코드가 뒤로 비죽 나온다. 제목 폭 700 → 640px      |
   | 싱글 Kawaii  | 가운데 560px 칸 — 도트 카세트 대신                                                |
   | 싱글 Mono    | 재킷(최대 520px) + 오른쪽으로 나온 레코드                                         |
   | 영수증       | 종이 맨 위 가운데 240px — 높이 +270px, 3,240px 상한 안에 드는 곡 수가 그만큼 준다 |

5. **보내지 않는다** — 그림 바이트는 이 브라우저의 IndexedDB 에서 읽어 캔버스에 그릴 뿐이다. 서버로 보내지 않고, 공유 링크에는
   여전히 그림이 들어가지 않는다(받는 사람에게는 썸네일). 카드를 복사 · 저장해 올리는 것은 사용자가 한다 — 그 그림의 권리는 올린
   사람의 몫이다(ADR 0041 리서치 §4).

## 대안

- **데크 아트 모서리에 아이콘을 겹치기** — 카세트 그림의 장식을 가리고, 작은 띠에서는 누를 수 없는 크기가 된다.
- **지금 재생 카드의 제목 줄 오른쪽 위** — "그 자리에" 라는 요청과 다르다.
- **YouTube 링크를 아예 없애기** — 재생 오류 안내가 갈 곳을 잃는다 (F3).
- **목록 카드에 여러 그림(2×2 모자이크)** — 실제로 써 본 뒤 판단한다. 지금은 처음 만나는 하나.
- **카드에 그림을 늘 넣기(끄기 없음)** — 그림이 개인 사진일 수 있다. 끌 수 있게 했다.

## 결과

- 새 의존성 · 새 저장 상태 없음. 저장 키 · 라이브러리 · 백업 형식 · 확장 계약은 그대로다.
- 계약 변경:
  - `ShareCardRenderer(model, art)` — 그림 바이트(`Blob | null`)를 둘째 인자로 받는다. `ShareCardModel.art`, `ShareCardImage.art`.
  - `receiptHeight({ …, art })` · `receiptRowsThatFit(…, art)`.
  - `PlayerTransport` 의 `youtubeUrl` prop → `shareable` · `shareLabel` prop 과 `share` 이벤트.
  - `useTransport().youtubeUrl` → `youtubeFallbackUrl` (오류 안내가 떠 있을 때만 값이 있다).
  - `playback.setStatus(message, tone, cause?)` 와 `playback.statusCause` — 코디네이터가 플레이어 오류 안내에 `'player-error'` 를
    단다. 안내가 바뀌거나 지워지면 따라 지워진다.
- 지금 재생 카드의 공유 아이콘은 넓은 3열 화면에서 재생 단추 줄 아래 줄로 내려간다(옛 링크와 같다). 폰 폭에서는 같은 줄 끝이다.
