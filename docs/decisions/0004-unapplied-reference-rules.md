# 0004. 승인된 레퍼런스에서 적용되지 않는 규칙은 작성된 의도를 따른다

- 상태: 채택
- 날짜: 2026-11-02
- 관련: `docs/architecture/THEME_SYSTEM.md` §4.6, `AGENTS.md` 규칙 6

## 배경

M1-2에서 `design/references/two-themes-v09.html`의 색을 CSS 토큰으로 옮기던 중,
Kawaii Synth Cassette 값이 **작성되어 있지만 브라우저에 적용되지 않는** 규칙을
2건 발견했다.

| #   | v09 작성 내용                                                                                                                                                        | 왜 적용되지 않는가                                                                                                         |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 1   | `.theme-kawaii .modal{background:#19374a;border-color:#8fd8cb;color:#d8fff2}` 와 `.theme-kawaii .modal input{background:#0e2a39;border-color:#6aada8;color:#ecfff9}` | 실제 마크업은 `class="add-modal"`과 `class="field"`다. `.modal` 클래스를 가진 요소가 없다. 선택자가 아무것도 맞히지 못한다 |
| 2   | `.theme-kawaii .rule{border-color:#456b78}` (`.header`, `.info`, `.footer`와 같은 그룹 선택자)                                                                       | `.rule`은 `height:1px; background:#534c42`로 그리는 1px 요소다. `border`가 없으므로 `border-color`가 무효다                |

결과적으로 레퍼런스를 kawaii 테마로 열면 **모달과 구분선만 mono의 갈색**으로
남는다. 민트 배경 위에 `#23201b` 모달과 `#534c42` 구분선이 보인다.

`AGENTS.md` 규칙 6은 승인된 디자인을 임의로 변경하지 말라고 한다.
그런데 "승인된 디자인"이 **렌더 결과**인지 **작성된 값**인지가 갈린다.

## 결정

**작성된 값(의도)을 따른다.** kawaii 토큰에 `#19374a`, `#8fd8cb`, `#d8fff2`,
`#0e2a39`, `#6aada8`, `#ecfff9`, `#456b78`을 넣는다.

판단 근거:

1. **색 자체는 승인된 파일에서 가져온 값이다.** 디자이너가 kawaii 테마를 위해
   직접 작성했다. 우리가 만들어낸 색이 아니므로 규칙 6의 "임의 변경"이 아니다.
   깨진 것은 선택자와 속성이며 색이 아니다.
2. **1번은 전용 블록에 3개 선언 + 입력 요소 스타일까지 작성되어 있다.**
   의도가 분명하다. 클래스 이름 불일치는 단순 오기로 보인다.
3. **2번은 `.header`, `.info`, `.footer`와 같은 그룹에 들어 있다.** 같은 그룹의
   나머지 3개는 모두 정상 적용된다. `.rule`만 구현 방식(background) 때문에
   빠진 것이다.
4. 민트 테마에서 모달과 구분선만 갈색인 것은 디자인 의도로 보기 어렵다.

**토큰 파일에 `[의도]` 주석으로 표시한다.** 되돌리려면 해당 값을 mono 값으로
바꾸면 되고, 그 외 코드 변경은 필요하지 않다.

## 대안

| 대안                                       | 탈락 이유                                                       |
| ------------------------------------------ | --------------------------------------------------------------- |
| 렌더 결과를 그대로 보존 (갈색 모달·구분선) | 민트 테마의 일관성이 깨진다. 디자이너가 작성한 값을 버리게 된다 |
| 레퍼런스 HTML을 수정해 선택자를 고친다     | 규칙 6이 금지한다. 레퍼런스는 읽기 전용이다                     |
| 토큰을 비워두고 M1-6 이후로 미룬다         | 두 테마의 토큰 집합이 어긋난다. 전환 시 빈 값이 된다            |

## 결과

- Kawaii 테마의 모달·입력·구분선이 민트 계열로 렌더된다.
  **레퍼런스를 브라우저로 열었을 때와 이 부분만 다르다.**
- 사람의 확인이 필요한 항목으로 보고했다. 확인 결과에 따라 토큰 값만 바꾼다.
- 같은 종류의 문제를 또 만나면 이 ADR의 기준을 적용한다.
  **작성된 의도가 있으면 의도를, 없으면 렌더 결과를 따른다.**
- 작성된 의도가 **없어서** 렌더 결과를 보존한 항목(kawaii가 재정의하지 않아
  mono 값이 보이는 토큰 20개)은 `THEME_SYSTEM.md` §4.7에 따로 기록했다.
