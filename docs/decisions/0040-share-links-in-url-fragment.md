# 0040. 첨부 파일 없이 공유하는 링크 — 내용을 주소 조각에 압축해 싣고, 받는 사람이 미리보기에서 고른다

- 상태: 채택 — 사용자 요청 (2026-11-20), 로컬 브랜치 `feat/playback-queue-ux`
- 고르는 칸(곡 이름 · Moments · 메모)은 [ADR 0043](0043-share-dialog-and-backup-only-data-dialog.md) 에서 없앴다 — 대상이 정한다.
- 관련: ADR 0023 (수집 링크 — 조각에 싣고 승인 뒤 저장), ADR 0034 (ZIP 공유 패키지), ADR 0029 (oEmbed 제목), ADR 0011 (가시성 가드),
  ADR 0038 (큐가 출처 목록을 따른다)

## 배경

커뮤니티 게시판에 목록 · 곡을 공유하고 싶은데, 그 게시판은 첨부 파일을 올릴 수 없고 노래 게시판은 사이트의 YouTube 검색으로만 글을
올린다. 지금 39page 의 공유는 ZIP 파일(ADR 0034)뿐이다. 최선은 이미지를 올리고 그 이미지에 링크를 거는 것 — 링크만으로 목록 · 곡 ·
Moment 를 넘길 수 있어야 한다. 서버 · 계정은 없다 (장기 비전의 공개 링크는 서버가 생긴 뒤의 일).

## 결정

1. **형식** — `https://39page.com/#share?v=1&d=<base64url(raw DEFLATE(UTF-8 JSON))>`. 압축은 이미 쓰는 fflate(ZIP 공유)를 쓴다 —
   새 의존성이 없다. JSON 은 짧은 키다.

   | 키  | 뜻                                                          |
   | --- | ----------------------------------------------------------- |
   | `k` | `p` 목록 · `t` 곡 하나 · `m` Moment 하나                    |
   | `n` | 목록 이름 (`p` 일 때만, 선택)                               |
   | `t` | `[[영상 ID, 제목?], …]` — 순서 그대로, 제목은 선택          |
   | `m` | `[[곡 자리, 초, 메모?], …]` — 선택, 곡 자리는 `t` 안의 위치 |

   `v` 는 의미가 바뀔 때만 올린다. 같은 버전 안에서 모르는 키는 무시한다. 같은 내용이면 같은 링크다(키 순서 · 압축 수준 고정).

2. **조각(`#` 뒤)에 싣는다** — 서버로 가지 않는다 (ADR 0023 결정 2 와 같다). 39page 서버 · 요청 기록에 내용이 남지 않는다. 링크는
   **그 순간의 사본**이다 — 보낸 사람이 나중에 목록을 바꿔도 링크는 그대로다.
3. **무엇이 들어가나** — 영상 ID 는 늘, 곡 이름은 기본 켬(끄면 받는 쪽이 oEmbed 로 제목을 찾는다), 목록 이름(목록일 때), Moments 와
   그 메모는 **고를 때만**. 이름을 지은 적 없는 곡의 기본 이름(`YouTube · <id>`)은 싣지 않는다. 앨범아트(직접 올린 그림)는 싣지
   않는다 — 너무 크다. 그림까지 넘기려면 ZIP 공유를 쓴다.
4. **길이** — 주소 2,000자를 넘으면 "일부 게시판에서 잘릴 수 있어요" 와 곡 이름을 뺀 길이를 알린다(만들 수는 있다). `d` 16,000자 ·
   곡 1,000개 · Moment 1,000개를 넘으면 만들지도 읽지도 않는다(파일 공유를 권한다). 실측(실제 Chrome, 로컬 주소 기준): 3곡 목록
   229자 · 곡 이름 빼면 165자 · Moment 하나(메모 포함) 166자 · 50곡(겹치지 않는 한글 제목) 3,807자 · 곡 이름 빼면 791자.
5. **읽기 검증** — 조각은 누구나 만들 수 있다. 조각 모양 → 길이 → 매개변수 중복 · 버전 → base64url → 압축 해제(**실제로 풀린 양을
   세며 128 KB 에서 멈춘다** — 압축 폭탄) → UTF-8(엄격) → JSON → 형식 · 개수 · 글자를 모두 본 뒤에만 내용을 쓴다. 하나라도 어기면
   전체를 받지 않는다(일부만 받지 않는다). 글자 규칙은 수집 링크 · 브리지와 같다 — C0 · C1 제어 문자와 양방향 재정의 · 격리 문자를
   거절하고, 메모만 줄바꿈을 받는다. 상한은 라이브러리 · Moments 입력 상한(이름 60 · 곡 이름 100 · 메모 500 · 시점 999,999초)과 같다.
   만들 때는 같은 규칙으로 걷어내고 자르므로, 39page 가 만든 링크는 읽기를 통과한다.
6. **받는 쪽** — 링크를 열면 대시보드 위에 미리보기 대화상자가 뜬다(처음 온 사람도). 이미 열린 탭에 붙여 넣어도(`hashchange`) 뜬다.
   **누르기 전에는 아무것도 저장 · 재생하지 않는다.** 내용은 일반 텍스트로만 그린다(HTML 해석 · 자동 링크 없음).

   | 종류   | 첫째 단추              | 둘째 단추   | 넣을 곳 기본값                |
   | ------ | ---------------------- | ----------- | ----------------------------- |
   | 목록   | 보관함에 추가하고 듣기 | 추가만 하기 | 새 목록 (이름이 겹치면 "(2)") |
   | 곡     | 바로 듣기 (저장 안 함) | 목록에 추가 | 보관함에서 고른 목록          |
   | Moment | 그 순간부터 듣기       | Moment 저장 | — (Moment 만 저장)            |

   같은 영상은 기본으로 건너뛴다. 곡 구성이 같은 목록이 이미 있으면 알린다. 재생은 대화상자를 **닫은 뒤** 한다 — 덮인 플레이어로 소리를
   내지 않는다 (ADR 0011). 닫으면(어떤 결과든) 주소의 조각을 지운다 — 새로고침에 다시 뜨지 않게. 곡 이름이 빠진 링크는 YouTube oEmbed
   로 제목을 찾는다 — 링크로 곡을 추가할 때와 같은 조회(ADR 0029: 영상 주소만, 쿠키 · 리퍼러 없음), 동시 4개 · 최대 200곡, 닫으면 멈춘다.
   받는 쪽 화면(`ShareLinkDialog`)은 따로 내려받는 묶음이다 — 보통 방문의 첫 화면 묶음을 키우지 않는다.

7. **보내는 쪽** — 공유 묶음(데이터 · 백업 대화상자의 SHARE)이 "링크로 공유" 와 "파일로 공유 (ZIP)" 를 함께 보인다. 대상(목록 · 곡)을
   고르면 링크가 바로 만들어지고, "링크 복사" 를 누를 때만 클립보드에 쓴다. 막히면 링크 칸을 골라 두고 직접 복사하라고 말한다.
   무엇이 링크에 들어가는지(링크를 가진 누구나 본다)와 앨범아트는 빠진다는 것을 적는다. Moment 하나는 Moments 탭의 관리 →
   "링크로 공유" 로 공유한다(링크로만).
8. **메모를 링크에 싣는 것과 M10-4 의 관계** — 수집 링크(확장 → 웹앱)는 메모를 주소로 받지 않는다. 다른 사이트가 사용자 **자신의**
   메모를 미리 채워 저장하게 만들 수 있어서다. 공유 링크의 메모는 **다른 사람이 쓴 내용**으로 미리보기에 그대로 보이고, 받는 사람이
   저장을 누를 때만 들어간다. 보내는 쪽에서는 기본으로 꺼져 있다.

## 대안

- **서버의 짧은 링크(`39page.com/s/abc`)** — 짧고 갱신할 수 있지만 서버 · 저장 · 관리가 필요하다. 장기 비전(계정 · 커뮤니티)의 몫.
  지금 형식의 내용(영상 ID · 이름 · Moment)은 그대로 옮길 수 있다.
- **YouTube 임시 재생목록 링크(`watch_videos?video_ids=`)** — 39page 없이 듣지만 50곡 한도 · 비공식 기능. 사용자가 고르지 않았다.
- **링크 단축 서비스** — 목록 내용이 제3자에게 넘어간다. 권하지 않는다.
- **곡 ID 를 이진으로 묶기** — JSON + DEFLATE 와 길이 차가 작고(영상 ID 는 무작위라 어느 쪽이든 약 11자/곡) 형식이 덜 읽힌다.

## 결과

- 저장 키 · 라이브러리 형식 · 백업 형식 · 확장 계약은 바뀌지 않는다. 새 저장 상태가 없다 — 링크는 만들어 복사할 뿐이다.
- 계약 변경: `ShareTarget` 에 Moment(`{ momentId }`)가 더해졌다. `useShare.ts` 의 새 목록 이름 규칙을 `uniquePlaylistName` 으로
  꺼내 두 가져오기가 같이 쓴다.
- 받는 쪽은 처음 방문에도 동작한다(기본 목록 "MY RECORDS" 와 함께 새 목록이 생긴다).
