# 0045. 셋째 테마 Custom — 데크 자리에 사용자 그림 · 움짤, 다섯 색으로 만드는 테마

- 상태: 채택 — 사용자 요청 (2026-11-21 "새로운 테마는 custom … 추천안으로 가고 구현해줘"), 브랜치 `feat/custom-theme`
- 관련: ADR 0001 (테마 전환 — `data-theme` 교체) · ADR 0031 (기본 테마) · ADR 0033 · 0034 (앨범아트 저장 · 전체 백업) ·
  ADR 0035 (표시 구도) · ADR 0041 (공유 카드) · ADR 0044 (설명 글 줄이기)

## 배경

사용자가 셋째 테마 `custom` 을 원했다. 카세트(1) · LP(2) 자리에 사용자가 고른 그림이나 움짤(PNG · JPG · GIF)을 두고 **하는
일은 같게**, 전체 색은 사용자가 정한다. 추천안 네 가지를 그대로 채택했다.

1. 색은 다섯 가지만 고르고 나머지는 자동.
2. 전체 백업에 색과 그림을 넣는다.
3. 커스텀 테마의 공유 카드도 고른 색.
4. 그림이 없으면 빈 데크에 "이미지 넣기".

## 결정

1. **테마 키 `custom`** — `THEME_KEYS` 의 셋째(표시 `03 / CUSTOM`). 앞 두 테마의 키 · 순서 · 기본 테마는 그대로다. 테마 저장
   형식(`39page.theme`)도 그대로이고 값만 하나 늘었다.
2. **다섯 색 → 토큰** — 배경 · 카드 · 글자 · 강조 · 선. 나머지 토큰(다른 테마와 **같은 집합**, 시험이 지킨다)은
   `src/themes/custom/tokens.css` 가 CSS `color-mix()` 로 만든다. 강조색 위 글자색만 JS 가 대비로 고른다(검정 · 흰색).
   - 색은 문서 루트의 인라인 CSS 변수(`--custom-*`)다. **테마가 무엇이든 늘 걸어 둔다** — 다른 테마의 토큰은 그 변수를
     읽지 않으므로, 테마 전환은 여전히 `data-theme` 교체 하나다(플레이어 노드 · 재생 그대로, ADR 0001).
   - 저장은 `localStorage` `39page.customTheme` (`{ version: 1, data: { colors } }`). 테마 키와 **따로**다 — 테마를 바꿔도 고른
     색이 남는다. 기본값은 어두운 바탕에 주황 강조(`themes/custom/defaults.css` = `DEFAULT_CUSTOM_COLORS`, 시험이 같은지 본다).
   - 첫 그림 전 깜빡임: `index.html` 의 인라인 스크립트가 저장된 테마가 `custom` 이면 형식이 맞는 색(`#rrggbb`)만 미리 건다.
   - 대비 점검: 글자 4.5:1, 강조 3:1 (WCAG) 아래면 설정 창이 알린다. 막지는 않는다.
3. **데크 그림은 따로 된 IndexedDB `39page-theme`** — 레코드 하나(`id: 'deck'`). 앨범아트 저장소에 넣지 않는다: 그 저장소는
   어느 곡도 쓰지 않는 그림을 지우고(`cleanUp`), 전체 백업 복원이 연결을 통째로 바꾼다 — 곡에 붙지 않은 데크 그림이 거기서
   사라진다. 검증(매직 바이트 · 디코딩 · 한도 · GIF 첫 프레임 포스터 · SHA-256)과 표시 구도(맞춤 · 위치 · 확대)는 앨범아트의
   것을 그대로 쓴다. 쓰기는 수정 번호로 탭 간 충돌을 거절하고(`conflict`), 다른 탭에는 `BroadcastChannel` 로 알린다.
4. **데크의 하는 일은 같다** — 그림(900 × 570 틀, 두 데크 SVG 와 같은 비율)을 누르면 음악 보관함, 그림 왼쪽 아래 ■ · ▶ 가
   정지 · 재생. 그림에는 그려진 키가 없으므로 둘은 **보이는** 단추다. 움짤은 **재생 중에만 움직이고** 멈추면 첫 프레임이다
   (카세트 릴 · LP 가 재생 중에만 도는 것처럼, 움직임 줄이기 설정이면 늘 첫 프레임). 작은 데크 띠(700px 이하)도 같다.
5. **설정 창** — 헤더 테마 단추 옆 팔레트 아이콘(커스텀일 때만)과 빈 데크의 "이미지 넣기" 가 연다. 그림 고르기 · 빼기 ·
   구도, 다섯 색, 기본 색. 고르는 색은 **저장 전에 화면 전체에 미리** 보이고 취소하면 되돌아간다. 저장은 그림(IndexedDB)
   → 색 순서이고, 그림 저장이 실패하면 아무것도 저장하지 않는다.
6. **백업**
   - JSON 백업: `preferences.customTheme`(선택 설정, `schemaVersion` 그대로). 가져올 때 테마와 **같은 스위치**로 적용한다.
   - 전체 백업(ZIP): 데크 그림이 있으면 `theme.json`(그림 메타 · 표시)과 `assets/<sha256>.<ext>` 를 넣고 `formatVersion` 3.
     그림이 없으면 2 그대로라 이전 39page 도 읽는다. 읽을 때 그림을 다시 검증하고, 문제가 있으면 그림만 받지 않는다.
7. **공유 카드** — 커스텀 테마의 카드는 Kawaii 틀(J카드 · 싱글 · 영수증)에 고른 색을 입힌다. 종이 위 글자는 4.5:1 을 넘지
   못하면 더 어두운 잉크로 바꾼다(어떤 색을 골라도 읽힌다).

## 대안

- **토큰 100여 개를 다 고르게** — 고르기 어렵고 틀리기 쉽다. 다섯 색이면 충분하다는 데 사용자가 동의했다.
- **강조색 하나만** — 더 쉽지만 바탕을 바꿀 수 없다.
- **데크 그림을 앨범아트 저장소에** — 정리 · 복원 규칙을 예외로 고쳐야 한다. 따로 두는 편이 안전하다.
- **그림을 `localStorage` 에 Base64 로** — 5 MB 한도 · 문자열 부풀림. 앨범아트와 같은 이유로 쓰지 않는다(ADR 0033).

## 결과

- 새 의존성 없음. 새 저장소 둘: `localStorage` `39page.customTheme`, IndexedDB `39page-theme`. 기존 저장 형식 변경 없음.
- 확장: 웹앱의 카세트 토큰만 쓰므로 영향 없음 (확장 시험 430 그대로).
- `mono-vinyl/deck.css` — LP 아트는 `data-theme` 가 없을 때의 바탕이라 기본 표시다. 커스텀에서도 숨기도록 한 줄 더했다
  (실제 Chrome 확인에서 찾음).
