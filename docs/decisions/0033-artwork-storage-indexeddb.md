# 0033. 곡별 Artwork 는 (playlistId, trackId) 연결과 내용 해시 자산으로 IndexedDB 에 둔다

- 상태: **채택 — M12-1 설계 (2026-11-15)** · 구현 M12-3
- 관련: ADR 0007 (보호 상태) · 0019 (Moment 는 영상을 가리킴) · 0024 · 0025 (탭 간 일관성 · 잠금),
  `docs/architecture/ARTWORK_DESIGN.md` §2 ~ §6

## 배경

사용자가 곡마다 이미지 · GIF 를 지정한다. 이미지는 수 MB 이고, 지금 저장소(`localStorage`, 약 5 MB, 문자열만)에 넣을 수 없다.
같은 영상이 여러 목록에 있을 수 있고 목록마다 다른 그림을 원할 수 있다. 가져온 백업은 목록끼리 같은 트랙 id 를 가질 수 있다.

## 결정

1. **연결 키 = (playlistId, trackId).** trackId 만으로는 가져온 백업에서 유일하지 않다. videoId 로 하면 같은 영상의 트랙들을
   구분하지 못한다. 배열 인덱스는 쓰지 않는다 — 순서를 바꿔도 연결이 따라간다.
2. **선호 세 가지**: auto(레코드 없음 — 썸네일 → 기본) · default(39page 기본 그림) · custom(자산). 레코드가 없으면 auto 이므로
   **기존 데이터를 고치지 않는다.**
3. **IndexedDB `39page-artwork`** 에 `assets`(메타) · `blobs`(바이트 · 포스터) · `assignments`(연결, `assetId` 색인) · `meta` 를 둔다.
   라이브러리 · Moments 의 `localStorage` 키 · 형식 · 잠금은 그대로다. Base64 를 라이브러리에 넣지 않는다.
4. **자산 id = SHA-256(내용)**. 같은 파일은 한 번만 저장되고, 참조 수는 색인으로 센다 (따로 세는 값이 없어 어긋나지 않는다).
5. 그림 바꾸기는 **한 readwrite 트랜잭션** (자산 · 바이트 · 연결 · 옛 자산 정리). 실패하면 통째로 취소돼 이전 그림이 남는다.
6. **탭 간**: 트랜잭션이 직렬화하고, 설정 화면은 연 순간의 `revision` 과 다르면 `conflict` 로 거절한다 (마지막 쓰기 승리 아님).
   쓰기 뒤 `BroadcastChannel` 로 알린다.
7. 트랙 · 목록 삭제는 라이브러리 저장 **성공 뒤** 연결을 지우고 아무도 안 쓰는 자산을 지운다. 라이브러리가 보호 · 불가 상태면
   고아 정리를 하지 않는다.
8. 썸네일은 저장하지 않는다 (`i.ytimg.com` 직접, 실패하면 기본).
9. 이미지는 매직 바이트 · 실제 디코딩으로 검증하고 SVG · HTML · 동영상 · 움직이는 WebP 는 받지 않는다 (움직이는 WebP 는 검증
   수단이 생길 때까지 TODO).

## 대안

- 연결을 라이브러리 트랙에 필드로 넣기(`track.artwork`) — 기각: 라이브러리 저장 형식 · 확장 계약 · 백업 스키마가 바뀌고, 이미지와
  연결이 다른 저장소에 있어 한 트랜잭션으로 바꿀 수 없다.
- 이미지를 Cache Storage / OPFS 에 — 기각: 연결과 한 트랜잭션으로 묶이지 않는다. OPFS 는 Safari 지원 차이가 있다.
- `idb` 같은 래퍼 라이브러리 — 기각: 필요한 것은 열기 · 트랜잭션 몇 개라 직접 쓴다 (새 런타임 의존성 없음).

## 결과

- 사용자 이미지는 브라우저 데이터와 함께 지워질 수 있다 → ZIP 전체 백업이 같은 빌드에 있어야 출시할 수 있다 (ADR 0034).
- 시험은 `fake-indexeddb`(개발 의존성)로 실제 트랜잭션 의미를 확인한다. 실제 Chrome 에서 한 번 더 확인한다.
