# 0039. 곡 찾기는 API 키 없이 YouTube 검색 결과 페이지를 새 탭으로 연다

- 상태: 채택 — 사용자 선택 (2026-11-20), 로컬 브랜치 `feat/playback-queue-ux`
- 관련: ADR 0029 (링크 추가 시 oEmbed 제목 미리 채우기), ADR 0023 · 0028 (확장 저장), ADR 0038

## 배경

운영 사용 피드백: 39page 에서 곡을 추가할 때 YouTube 링크를 따로 구해 오는 일이 번거롭다. 39page 안에서 검색하려면 YouTube Data API
v3 가 필요하다. 그런데 API 키가 브라우저 코드에 드러나고, 검색 1회가 할당량 100 단위라 기본 할당량(하루 10,000)으로 하루 약 100회뿐이다.
키를 숨기려면 서버가 필요하다. 비공식 검색 우회는 불안정하고 YouTube 약관 문제가 있다.

## 결정

1. 보관함의 링크 추가 양식 아래에 **"링크가 없으면 — YouTube에서 찾기"** 검색 칸과 **"YouTube에서 검색 ↗"** 단추를 둔다
   (`YouTubeSearch.vue`). 누르거나 Enter 를 치면 `https://www.youtube.com/results?search_query=<검색어>` 를 **새 탭**
   (`noopener,noreferrer`)으로 연다. API 키 · 서버 · 새 의존성이 없다.
2. 39page 는 검색어를 **보내거나 저장하지 않는다.** 주소를 만들어 브라우저가 열게 할 뿐이다. 검색어는 공백을 정리하고 200 글자에서
   자른 뒤 인코딩한다 (`youtubeSearchUrl`). 비어 있으면 YouTube 첫 화면이다. 검색어는 양식과 함께 열리고 닫힌다(메모리).
3. 찾은 영상은 YouTube 화면에서 **39page 확장 프로그램으로 바로 담거나**, 주소를 복사해 링크 칸에 붙여 넣는다 (안내 문구). 담긴 곡은
   ADR 0038 로 재생 중인 큐에도 바로 반영된다.
4. 검색은 링크 양식과 **따로 된 `<form role="search">`** 다 — 검색 칸의 Enter 가 링크 추가를 제출하지 않는다.
5. 링크 칸에 주소가 아닌 글(곡 이름 등)을 적고 추가를 누르면 오류 대신 그 글을 검색 칸으로 옮기고 "링크가 아니에요. 아래 'YouTube에서
   검색' 으로 찾아보세요." 라고 말한다. 주소처럼 생긴 글(`youtube.com/…`, `www.` 등)은 지금처럼 "올바른 YouTube 영상 링크" 오류다.
   이 안내가 실제 브라우저에서 나오도록 링크 양식에 `novalidate` 를 둔다 — `type="url"` 의 기본 검사가 제출을 먼저 막고 있었다
   (실제 Chrome 확인에서 발견, jsdom 은 기본 검사를 하지 않는다).

## 대안

- **YouTube Data API v3 (키를 브라우저에 두고 리퍼러 제한)**: 하루 약 100회 한도, 키 노출 · 관리. 사용자가 고르지 않았다.
- **키를 숨기는 서버(프록시)**: 새 서버 도입 — 사용자 승인 없이는 하지 않는다.
- **비공식 검색 · 페이지 긁기**: 불안정하고 약관 문제.

## 결과

- 저장 키 · 라이브러리 형식 · 백업 형식 · 확장 계약은 바뀌지 않는다. 외부로 나가는 요청을 39page 가 만들지 않는다(사용자가 여는 새 탭뿐).
- 개인정보 처리방침에 적을 새 데이터 흐름은 없다 — 검색은 사용자가 YouTube 를 직접 여는 것과 같다.
- 확장 프로그램이 없는 사용자는 주소를 복사해 붙여 넣어야 한다(안내 문구가 두 길을 모두 말한다).
