# 0046. 가사 위젯(LRCLIB), 목록 칸 높이 고정, 푸터 삭제

- 상태: 채택 — 사용자 요청 (2026-11-22), 브랜치 `feat/lyrics-widget`
- 관련: ADR 0002 (플레이어 노드 고정 — 배치는 CSS 로만) · ADR 0005 (그리드 영역) · ADR 0020 (재생 위치) · ADR 0030 (대시보드 배치) ·
  ADR 0044 (설명 글 줄이기 — 남겨 둔 푸터 TODO)

## 배경

사용자 요청 (2026-11-22, 화면 두 장과 함께):

- 가사 위젯을 더한다. 가로(넓은) 화면은 둘째 열 재생 상자 **아래**의 빈자리, 세로(두 열) 화면은 데크(카세트 · LP ·
  커스텀 그림) **아래**. LRCLIB 를 쓸 수 있는가.
- 곡 · Moment 수에 따라 페이지 높이가 바뀐다. 목록이 가장 길 때의 높이로 고정한다.
- 화면 맨 아래 "SYNTH CASSETTE · PIXEL × KAWAII / RECORD LIBRARY / PLAYLIST FIRST" 를 지운다.

## LRCLIB 확인 (2026-11-22, 공개 문서 `https://lrclib.net/docs.txt` · 실제 요청)

- 키 없이 쓰는 공개 API. `Access-Control-Allow-Origin: *` — 브라우저에서 바로 부른다(사전 요청이 `lrclib-client` 머리를 허용).
- 클라이언트를 밝혀야 한다. 브라우저는 `User-Agent` 를 바꿀 수 없어 문서가 정한 대안 `Lrclib-Client` 를 쓴다.
- 대략 IP 당 분당 45 ~ 90 요청. 429 · 503 이면 `Retry-After`(+ 흔들기)를 지켜야 한다. 요청 사이 200 ~ 500ms 를 권한다.
- **검색은 라틴 글자 낱말만 맞춘다.** "アストロノーツ" · "밤편지" · "メズマライザー" 로는 엉뚱한 곡이 나오거나 0건이고,
  "Astronauts siinamota" · "Through the Night IU" · "Mesmerizer 32ki" 로는 맞는 곡(싱크 가사 포함)이 나온다. 곡은 대부분
  있다(일본어 제목 레코드도 있다) — 찾는 말이 문제다.

## 결정

1. **가사 위젯** (`src/features/lyrics/`, 위젯 종류 `lyrics`)
   - 곡이 바뀌면 0.7초 기다린 뒤(빠르게 넘기는 동안 묻지 않는다) 찾는다. 이 탭에서 영상별로 결과를 기억한다.
   - 검색어: 제목에서 꼬리표(Official MV · 가사 · feat. 등)를 뗀 **라틴 낱말**, 없으면 정리한 제목. 많아야 두 번.
   - 고르기: 곡 길이 ±4초(플레이어가 아는 영상 길이), 곡 이름의 라틴 낱말 절반 이상 또는 한자 · 가나 · 한글 덩어리가 제목과
     겹칠 것. 가수 이름 조각과 "(feat. …)" 는 곡 이름에서 뺀다 — 실측에서 같은 가수의 다른 곡("少女A")이 붙던 것을 막는다.
     길이를 모르면 가수까지 겹쳐야 믿는다. 싱크 가사를 먼저 고른다.
   - 실측(사용자 화면의 8곡): 자동 6곡(アストロノーツ · 普通に歳をとるコトすら · フューチャー・イヴ · 砂の惑星 · Through the
     Night 등), 못 찾음 2곡(한국어 제목 · 한 글자 "Q"). 못 찾으면 **돋보기로 직접** 찾아 고르고, 고른 것은 그 곡에 기억한다
     (`localStorage` `39page.lyrics`, 영상 id → LRCLIB id). "자동으로 찾기" 로 되돌린다.
   - 싱크 가사는 재생 중 0.25초마다 위치를 묻고(코디네이터 `captureClock` — 새 메서드, 초를 내리지 않고 영상 길이도 준다)
     지금 줄을 밝혀 **칸 안에서** 가운데로 내린다. 사용자가 막 스크롤했으면 4초 동안 따라가지 않는다.
   - 요청은 한 번에 하나씩, 사이 300ms, `Lrclib-Client: 39page (https://39page.com)`, `referrerPolicy: no-referrer` ·
     `credentials: omit`. 가사 글자는 텍스트로만 넣는다.
   - 위젯 제목 옆에 출처 링크 "LRCLIB".
2. **자리** — 위젯은 그리드의 직계 자식이고 DOM 부모는 그대로다 (ADR 0002).
   - 넓은 화면: 둘째 열 전체를 걸치되 **플레이어 높이만큼 내려** 시작하고, 다른 열이 정한 바닥까지 늘인다.
   - 두 열: 첫 행 왼쪽(데크 아래). NOW PLAYLIST 는 데크 + 약 240px.
   - 한 열: Moments 다음, NOW PLAYLIST 앞에 260px.
   - 플레이어 · 데크 높이는 열 폭에 따라 바뀌어 `WidgetHost` 가 `ResizeObserver` 로 재서 CSS 변수로 건다. 여러 행을 걸치는
     칸의 높이 분배 때문에 행을 더하는 CSS 만으로는 데크 아래나 재생 카드 아래에 틈이 생겼다. 가사 칸은 크기 봉쇄
     (`contain: size`)라 가사 길이가 행 높이를 정하지 않는다.
3. **목록 칸 높이 고정** — 700px 넘는 배치에서 NOW PLAYLIST · Moments 위젯을 `clamp(300px, 46vh, 470px)` 로 고정하고,
   안의 줄 칸이 남는 높이를 채우며 스크롤한다. 곡 2곡 · 순간 0개와 30곡 · 20개에서 페이지 높이가 같다(실제 Chrome).
   한 열(700px 이하)은 그대로다 — 손가락 스크롤이 칸에 걸리지 않게 안쪽 스크롤 없이 "펼치기" 로 늘인다 (M11-3 U19).
   보관함의 재생 띠에서는 Moments 고정을 푼다.
4. **푸터 삭제** — `AppFooter` 와 테마 메타데이터의 `footerLabel` 을 지웠다. ADR 0044 가 남긴 TODO 를 사용자가 정했다.
   `--footer-*` 토큰은 승인된 토큰 집합이라 그대로 둔다.
5. **개인정보 처리방침** — LRCLIB 에 곡 제목에서 만든 검색어(직접 검색은 입력한 말)가 간다는 것, 직접 고른 가사 번호를
   `localStorage` 에 둔다는 것을 적었다.

## 대안

- **한국어 · 일본어 제목을 로마자 · 영어 제목으로 바꿔 찾기** — 사전 · 번역이 필요하다(새 의존성 · 외부 서비스). 직접 찾기로 덮는다.
- **가사를 저장소에 두기** — 저작물 사본을 쌓게 된다. 고른 id 만 두고 글자는 매번 받는다.
- **위치를 1초마다(Moments 와 같이)** — 한 줄이 1초 늦게 바뀐다. 0.25초로 묻고 0.25초 일찍 밝힌다.
