# 0036. 대시보드 헤더 접힘은 페이지 메모리에서만 유지하고 F11과 독립적으로 동작한다

- 상태: 채택 · 사용자 지시 (2026-11-15), `m12-6-header-collapse`
- 관련: ADR 0002 (iframe 영속), 0030 (헤더 전역 메뉴), 0035 (화면 상태와 데이터 구분)

## 결정

1. 기본은 펼침이다. 접으면 사이트명·보관함·데이터·테마 영역을 `hidden`으로 숨기고 동일한 네이티브 버튼만 남긴다.
   펼치면 기존 DOM을 다시 표시한다. 메뉴와 ThemeSwitcher를 재마운트하지 않는다.
2. 버튼에 `aria-expanded`, `aria-controls`, 헤더 접기/펼치기 이름을 제공한다. 터치 목표는 44px 이상이며 전환 후 포커스를 유지한다.
   숨긴 메뉴는 Tab 순서와 접근성 트리에서 빠진다. Enter·Space는 네이티브 button 동작을 사용한다.
3. 상태는 DashboardShell 생애 동안만 유지한다. 테마·보관함 전환에는 유지하고 새로고침하면 펼친다.
   기존 설정은 테마와 Library/Moments 데이터용이며 범용 화면 설정 스키마가 없다. 보관함처럼 메모리 UI 상태로 두는 것이 최소 변경이다.
   localStorage/sessionStorage 키·사용자 데이터·백업 스키마·ZIP 버전을 추가하지 않는다.
4. 헤더가 접히면 헤더 높이와 셸 위 여백·워크스페이스 위 간격을 줄인다. 워크스페이스 전체가 올라가서 확보된 높이를 사용한다.
   위젯의 배치·크기·부모·순서는 그대로다. 플레이어와 Now Playing 카드의 상대 배치를 바꾸지 않는다.
5. 전환에는 높이 애니메이션을 넣지 않는다. 첫 페인트 동안 셸의 자동 scroll anchoring을 억제하고 포커스는 preventScroll로 유지한다.
   헤더가 보이면 기존 scrollY를 유지한다. 헤더가 이미 화면 위로 나갔으면 워크스페이스의 viewport 좌표를 유지하도록 scrollY를 보정한다.
   문서 끝의 유효 스크롤 범위는 브라우저가 제한한다.
6. 보관함이 열려 있으면 기존 strip 높이/stack·side 경계만 다시 잰다. 다시 열거나 초기화하지 않고 자동 스크롤 경로도 부르지 않는다.
7. 앱은 Fullscreen API와 F11 키를 제어하지 않는다. 브라우저 전체화면은 사용자 선택이며 헤더 상태와 독립적이다.
