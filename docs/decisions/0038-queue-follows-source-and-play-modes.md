# 0038. 재생 큐는 출처 목록을 따르고, 목록 바꾸기는 바로 재생하며, 셔플 · 반복을 메모리 모드로 둔다

- 상태: 채택 — 운영 사용 피드백에 대한 사용자 결정 (2026-11-20), 로컬 브랜치 `feat/playback-queue-ux`
- 관련: ADR 0009 (라이브러리와 재생은 코디네이터로만), ADR 0011 (가시성 가드), ADR 0030 (NOW PLAYLIST · 큐의 출처),
  ADR 0002 (플레이어 노드 영속). `MVP_SPEC.md` 0.1 · 0.3 (반복 · 셔플 MVP 제외), `BACKLOG.md` §5.

## 배경

운영 사용에서 세 가지가 불편했다.

1. 재생 중 NOW PLAYLIST 의 "목록 바꾸기" 로 다른 목록을 고르면 "지금 ○○ 을(를) 재생 중이에요. 이 목록의 곡을 누르면 …"
   안내가 먼저 떴다. 고른 목록을 듣고 싶은 것인데 한 번 더 눌러야 했다.
2. 재생 중인 목록에 곡을 추가하면(확장 저장 포함) "목록이 변경됐어요 … 새 순서로 이어 재생" 안내가 떴다. 큐가 재생을 시작할 때의
   스냅샷이라서다 (M3 ~ M11-7B).
3. 셔플 · 반복이 없었다 (MVP 제외 항목).

사용자 결정: (1) 목록을 고르는 순간 그 목록을 처음부터 재생, (2) 곡 추가 · 순서 변경 · 삭제를 **모두 바로 반영**,
(3) 셔플과 반복을 함께 넣는다.

## 결정

1. **큐는 출처 목록을 따른다.** 코디네이터가 큐의 출처 목록(`queueSource.playlistId`)의 트랙 배열을 **동기 관찰자**로 지켜보고,
   바뀌면 큐를 목록의 지금 모습으로 다시 맞춘다. 보관함 편집 · 확장 저장 · 다른 탭의 변경이 모두 같은 길이다. 안내를 띄우지 않는다.
   - 지금 곡이 바뀐 목록에 있으면 **트랙 id** 로 찾아 그 자리에 선다. 플레이어에는 명령을 보내지 않는다 — 소리 · 재생 위치가 끊기지
     않는다 (M11-7B 의 "새 순서로 이어 재생" 과 같은 동작을 자동으로).
   - 지금 곡이 지워지면 **지운 곡 다음 곡**으로 간다. 소리가 나던 중이면 그 곡을 재생하고(가시성 가드를 지난다), 아니면 소리 없이
     올려 둔다(`load(…, { autoplay: false })` — 화면의 "지금 곡" 과 플레이어가 어긋나지 않게). 뒤에 곡이 없으면 전체 · 한 곡 반복은
     처음 곡으로, 반복이 꺼져 있으면 앞쪽의 마지막 곡에 서서 멈춘다(큐 끝과 같다). 목록이 비면 멈추고 큐를 비운다.
   - 출처 목록이 **지워지면** 따라갈 것이 없으므로 큐는 그대로 끝까지 재생되고, 기존 안내("이 목록은 보관함에서 지워졌어요")를 둔다.
   - 백업 복원(`libraryReplaced`)은 지금처럼 멈추고 큐를 비운다.
   - 큐 트랙은 여전히 라이브러리 객체의 **복사본**이다. playback store 는 library 를 import 하지 않는다 (관찰은 코디네이터가 한다).
2. **목록 바꾸기 = 바로 재생.** 재생 큐가 있을 때 "목록 바꾸기" 로 다른 목록을 고르면 고른 목록을 저장하고(`selectPlaylist`) 그 목록을
   처음부터 재생한다(`playPlaylist`). 재생 중인 목록을 다시 고르면 큐를 보일 뿐 다시 틀지 않는다. 빈 목록이거나 영상이 가려져 재생하지
   못하면 그 목록을 "재생 대기" 로 보이고(빈 목록 → 링크 추가로, 가려짐 → 기존 안내 문구), 부제에 "지금 재생: ○○" 을 짧게 적는다.
   재생 큐가 없을 때 고르면 지금처럼 "재생 대기" 로 보일 뿐이다 — 아무것도 재생하지 않던 상태에서 소리를 내지 않는다.
3. **셔플 · 반복.** playback store 에 `shuffle: boolean` · `repeat: 'off' | 'all' | 'one'` 과 큐의 목록 순서(`queueListOrder`)를 둔다.
   `queue` 는 실제 재생 순서다.
   - 셔플을 켜면 지금 곡을 맨 앞에 두고 나머지를 섞는다(Fisher–Yates). 끄면 목록 순서로 돌아가 지금 곡의 자리에 선다. 어느 쪽도
     플레이어에 명령하지 않는다. 셔플 중 "처음부터 재생" 은 무작위 곡으로 시작하고, 곡을 고르면 그 곡부터 나머지가 섞인다.
   - 셔플 중 목록이 바뀌면 섞인 순서를 지키고(지운 곡만 빼고 · 이름은 새것), 새 곡은 지금 곡 뒤 **아직 듣지 않은 자리**에 무작위로 끼운다.
   - 반복 `all` 은 큐 끝 ↔ 처음을 잇는다(자동 전환 · ⏭ · ⏮). `one` 은 곡이 끝나면 같은 곡을 처음부터 다시 적재하고, ⏭ · ⏮ 는 평소처럼
     옮긴다(끝과 처음은 잇는다). `off` 는 M3-0.1 그대로 — 큐 끝에서 멈추고 "마지막 곡까지 재생했습니다." 다.
   - **저장하지 않는다.** 큐가 메모리에만 있는 것과 같다(새 저장 키 · 백업 형식 변경 없음). 백업 복원으로 큐를 비워도 모드는 남는다.
4. **화면.** Now Playing 카드의 재생 단추 **양옆, 같은 줄**에 셔플 · 반복 단추(44px, 직접 그린 SVG)를 둔다 — `🔀 ⏮ ▶ ⏭ 🔁`
   (사용자 지시 2026-11-20: 두 줄로 나누지 않는다). 다섯 단추 사이를 4px 로 좁혀 한 줄이 243px 다. 카드가 400px 이하라 그림 옆 칸에
   이 줄이 들어가지 않으면 조작 묶음(단추 줄 · 안내)을 그림 아래 전체 폭으로 내린다 — 390 · 360 · 320px 폰에서도 한 줄이다. 켜짐은 테두리 · 강조색 · 아래 점 ·
   `aria-pressed` 로, 한 곡 반복은 모서리 "1" 배지로 구분한다. 반복 단추의 접근성 이름은 "반복: 전체 반복 (누르면 한 곡 반복)" 처럼
   지금 모드와 다음 모드를 말한다. 큐가 없어도 누를 수 있다(다음 큐부터 적용). 보관함이 열린 좁은 배치(쌓기 · 옆)의 한 줄 카드에서는
   숨긴다. NOW PLAYLIST 부제에 "· 셔플 · 전체 반복" 을 적는다 — 줄 번호가 재생 순서라는 것을 함께 알린다.

## 계약 변경 (`playbackCoordinator.ts`)

- 더함: `PlaybackModes` (`modes` · `setShuffle` · `setRepeat`), `REPEAT_LABEL`, 공용 타입 `RepeatMode`.
- 없앰: `trackRemoved` (M3-5 — 관찰이 대신한다), `resyncQueueFromSource` · `QueueResync*` · `QueueView.canResync` ·
  `QueueSourceState` 의 `'changed'` (M11-7B — 큐가 늘 목록을 따르므로 생기지 않는다).
- `createPlaybackCoordinator(options?)` 가 셔플 난수(`random`)를 받는다 — 테스트용. 기본은 `Math.random`.

## 대안

- **삭제된 지금 곡을 끝까지 듣고 넘어가기**(대형 음악 앱 다수의 동작). 큐에 목록에 없는 곡을 남겨야 해서 "큐 = 목록" 이 깨지고
  표시 · 비교 규칙이 복잡해진다. 사용자가 "삭제 바로 반영" 을 골랐으므로 택하지 않았다.
- **곡 추가만 자동 반영, 순서 · 삭제는 안내 유지.** 처음 제안했지만 사용자가 셋 다 바로 반영을 골랐다.
- **셔플 · 반복 저장.** 새로고침하면 큐가 사라지는데 모드만 남으면 어긋나고, 저장 키 · 백업 정책을 정해야 한다. 사용자가 기억하지
  않아도 된다고 확인했다 (2026-11-20).

## 결과

- 저장 키 · 라이브러리 형식 · 백업 형식 · 확장 저장 계약은 바뀌지 않는다. 새 상태는 메모리의 모드 둘과 목록 순서뿐이다.
- 테마 전환은 모드에 닿지 않는다(playback store 를 theme 이 모른다 — 규칙 5).
- 검증: 단위 · 통합 테스트(로컬), 실제 Chrome(로컬 빌드 · 임시 프로필) — `docs/development/PLAYBACK_QUEUE_UX_REPORT.md`.
