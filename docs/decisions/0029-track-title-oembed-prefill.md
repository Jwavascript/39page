# 0029. 링크로 곡을 추가할 때 제목 칸을 YouTube oEmbed 로 미리 채운다 — 칸만, 사용자가 쓴 제목과 저장된 제목은 건드리지 않는다

- 상태: 채택 — **M11-4 후속 (2026-11-12)**
- 관련: **ADR 0008** (음악을 틀지 않는 방문에 외부 요청을 만들지 않는다), **ADR 0013** (날씨 — 키 없는 외부 API),
  **ADR 0015** (정적 배포 — 키를 둘 곳이 없다), `M11_UX_DESIGN.md` §12 (D5 · U13)

## 배경

링크만 넣고 제목 칸을 비우면 곡이 `YouTube · <영상 ID>` 로 남는다 (U13). 확장으로 담으면 플레이어에서 제목을
읽어 오지만, 웹앱의 링크 추가 양식에는 제목을 얻을 길이 없었다. 서버 · 계정은 범위 밖이다.

## 조사와 실측 (2026-11-12)

| 경로                      | 사실                                                                                                                                                                                         | 판단                                       |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| IFrame Player API         | 제목을 주는 **문서화된** 함수가 없다 (`getVideoData` 는 문서에 없다). 또 영상을 불러와야 한다                                                                                                | 기각                                       |
| YouTube Data API          | API 키가 필요하다 — 정적 사이트에 둘 수 없다 (ADR 0015)                                                                                                                                      | 기각                                       |
| 제3자 프록시 (noembed 등) | 다른 회사에 영상 ID 를 보낸다                                                                                                                                                                | 기각                                       |
| **YouTube oEmbed**        | 키 없음. YouTube 가 영상 페이지에 `<link rel="alternate" type="application/json+oembed">` 로 알리는 발견 엔드포인트이고, oEmbed 제공자 목록에도 있다. Google 개발자 문서의 API 목록에는 없다 | **채택** — 가장 공식에 가까운 키 없는 경로 |

실제 Chrome 157 (origin `http://127.0.0.1`, 격리 프로필) 에서 `fetch` 로 잰 값:

- 정상 영상 200 · 제목 · 88–197ms. CORS 로 읽힌다(응답을 읽을 수 있었다 — `Access-Control-Allow-Origin` 은 스크립트에 노출되지
  않는 헤더라 값으로는 보이지 않는다). 퍼가기 제한 영상(재생 오류 150)도 제목은 준다
- 없는 영상 ID → **400** (404 가 아니다). 비공개 영상은 재지 못했다 — 문서상 401/403 이라 함께 다룬다
- `credentials: 'omit'` · `referrerPolicy: 'no-referrer'` 로 보내면 실제 요청에 **Cookie · Referer 없음**, Origin 만
- 오프라인 → 즉시 `TypeError`, 지연 6초 망 → 4초 한도에서 그만둠

## 결정

1. 링크 추가 양식에서 **사용자가 링크를 넣었고, 제목 칸이 비어 있고 손대지 않았을 때만** 400ms 뒤 한 번 oEmbed 를 묻는다.
   화면을 열기만 해서는 요청이 나가지 않는다 (ADR 0008 의 정신 — 사용자가 그 영상을 다루려는 순간에만).
2. 결과는 **제목 칸만** 채운다. 저장은 사용자가 "이 목록에 추가" 를 눌러야 한다. 제목 칸 아래에 "YouTube 에서 가져온 제목이에요.
   고쳐도 돼요." 라고 출처를 밝힌다.
3. **사용자가 쓴 제목을 덮지 않는다.** 제목 칸에 입력이 있었으면 묻지 않고, 묻는 중에 입력하면 결과를 버린다. 링크를 바꾸면
   **우리가 채운** 제목만 거둔다.
4. **추가는 조회를 기다리지 않는다.** 조회 중에 추가하면 지금 칸의 값(비었으면 `YouTube · <ID>`)으로 저장하고, 늦게 온 결과는
   버린다. 실패하면 이유를 한 줄로 말하고 칸을 비워 둔다.
5. **저장된 제목을 바꾸지 않는다** — 이미 `YouTube · <ID>` 인 곡을 일괄로 고치지 않는다. 그런 곡은 사용자가 "관리 → 이름
   바꾸기" 로 고친다 (후속 후보: 이름 바꾸기 양식에 "YouTube 제목 가져오기" 단추 — TODO, 사용자가 누를 때만).
6. 보내는 것은 표준 시청 주소(영상 ID)뿐이다 — 붙여 넣은 주소의 다른 매개변수는 보내지 않는다. 쿠키 · 리퍼러 없음, 4초 한도,
   같은 영상은 이 탭에서 한 번만 묻는다(메모리, 저장 안 함).

## 결과

- 새 외부 요청이 하나 생긴다 — 링크를 넣을 때 그 영상 ID 가 YouTube 로 간다. 곡을 재생하면 어차피 YouTube 로 가는 정보이고
  그보다 앞설 뿐이다. 웹앱 개인정보 안내를 쓰게 되면 이 요청을 적는다 (TODO — 지금 웹앱에는 개인정보 안내 페이지가 없다).
- 저장 키 · 스키마 · 백업 형식 변경 없음. 라이브러리 store 는 네트워크를 모른다 (조회는 `features/library/youtubeTitle.ts` 한 곳).
- YouTube 가 oEmbed 를 바꾸거나 막으면 칸이 채워지지 않을 뿐 — 지금과 같은 동작(영상 ID 대체 표기)으로 돌아간다.
- 시험은 네트워크에 나가지 않는다 (`tests/setup/noNetwork.ts`, 이 기능의 시험은 `fetch` 를 흉내 낸다).
