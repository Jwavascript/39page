# 0017. 데크에 그려진 트랜스포트를 네이티브 버튼으로 덮어 동작하게 한다

- 상태: 채택
- 날짜: 2026-11-04

## 배경

승인된 데크 아트에는 재생 컨트롤이 **그려져 있다.**

| 테마                  | 그려진 것                         | 좌표 (viewBox 900×570)    |
| --------------------- | --------------------------------- | ------------------------- |
| Mono Vinyl            | 금속 키 1개 + `START / STOP` 글자 | 원 cx 103 · cy 478 · r 30 |
| Kawaii Synth Cassette | `■ STOP` / `▶ PLAY` 글자          | x 70 · x 274, y 504       |

M1-6 에서 이식할 때 내부 컨트롤의 `role="button"` / `tabindex` 를 **제거**했다.
"동작하지 않는 버튼을 만들지 않는다" 는 원칙에 따른 것이고, 금속 하드웨어는
데크 본체 디자인의 일부로 봤다.

실기기 검증에서 사용자가 **두 번** 지적했다. "카세트나 LP의 play, stop 버튼이
존재만 하고 동작하지 않는다."

원칙을 잘못 적용했다. 그 원칙은 **없는 기능의 버튼을 만들지 말라**는 것이지,
**있는 기능을 그림으로만 두라**는 것이 아니다. 재생·일시정지는 이미 구현돼
있고(M3-3 트랜스포트), 데크에는 그 동작을 가리키는 그림이 있다. 누를 수 있어
보이는 것이 동작하지 않는 것은 그 자체로 결함이다.

## 결정

### 1. SVG 를 수정하지 않고, 네이티브 `<button>` 을 그 위에 겹친다

승인된 SVG 는 읽기 전용이다 (규칙 6). 그래서 `.deck-open`(M2-2 의 라이브러리
열기 트리거)과 **같은 방식**을 쓴다 — SVG 밖의 네이티브 버튼을 좌표에 맞춰
절대 위치로 놓는다. `.deck-art` 가 `width: 100%; height: auto` 이고 viewBox 가
고정이므로 퍼센트가 viewBox 단위에 선형으로 대응한다.

네이티브 버튼이라 Tab · Enter · Space 가 기본 동작하고, 비활성 테마의 버튼은
`display: none` 이라 Tab 순서에서도 빠진다.

### 2. 상자를 글자보다 넉넉하게 잡는다

카세트의 글자는 15px 이라 글자 폭(약 54 단위)만 덮으면 데크가 400px 일 때 터치
목표가 24px 아래로 내려간다. 84 × 60 단위로 잡으면 같은 폭에서 약 37 × 27px 이
된다. 넓혀도 겹치는 것이 없다 — 카세트 열기 버튼은 y 467 에서 끝나고 본체는
y 536 까지다.

### 3. 트랜스포트 키를 열기 버튼보다 **뒤**에 둔다

Mono Vinyl 의 `START / STOP` 키 상자(x 67‥139, y 442‥514)가 LP 열기 원
(x 125‥565, y 60‥499)과 모서리에서 겹친다. 둘 다 절대 위치이므로 같은
`z-index` 에서는 **나중 형제가 위**에 온다. 원형 클리핑에 기대지 않고 DOM
순서로 보장한다.

### 4. 큐가 없으면 **선택된 플레이리스트를 처음부터** 재생한다

플레이어의 트랜스포트는 `canToggle = currentTrack !== null` 이다 — 큐가 이미
있을 때의 조작이다. 데크의 ▶ 는 그보다 앞선 자리에 있다. 아직 아무것도 고르지
않은 상태에서 눌리는 첫 버튼이다.

| 상태                    | ▶ 를 누르면                            |
| ----------------------- | -------------------------------------- |
| 큐가 있다               | `togglePlay()` — 그 자리에서 이어서    |
| 큐가 없다               | `playPlaylist(선택된 목록)` — 처음부터 |
| 목록이 선택돼 있지 않다 | 아무 일도 하지 않고 이유를 알린다      |

이것이 세로 화면에서 드로어를 열지 않고도 음악을 시작하는 경로다 (보고 5번과
같은 방향).

### 5. ■ 는 멈춰 있을 때 아무 일도 하지 않는다

`togglePlay()` 를 그대로 쓰면 멈춰 있을 때 ■ 가 **재생을 시작한다.** 그림과
동작이 어긋나므로 소리가 날 때만(`playing` · `loading`) 명령을 보낸다.

### 6. 접근성 이름이 실제 동작을 말한다

레퍼런스의 글자는 `STOP` 이지만 우리 동작은 **일시정지**다. 재생 위치를 버리지
않는다. 그림의 글자는 바꿀 수 없으므로(규칙 6) `aria-label` 이 사실을 말한다.
▶ 도 상태에 따라 `재생` / `선택한 목록을 처음부터 재생` 으로 달라진다.

### 7. 판단은 composable 에, 자리와 이름은 컴포넌트에

`src/features/deck/useDeckTransport.ts` 가 상태를 읽고 명령을 고른다.
`DeckWidget.vue` 는 좌표와 이름만 정한다 (규칙 3). 데크는 여전히 `PlayerAdapter`
도 YouTube API 도 모르고 코디네이터만 부른다 (규칙 4).

### 8. 속도 키(33/45)는 그대로 그림으로 둔다

재생 속도 변경은 구현되지 않았고 MVP 범위도 아니다. 없는 기능이므로 M1-6 의
판단이 그대로 맞다.

## 대안

| 대안                                 | 왜 아닌가                                                                                |
| ------------------------------------ | ---------------------------------------------------------------------------------------- |
| 누를 수 없음을 시각적으로 드러낸다   | 기능이 늘지 않는다. 사용자는 **동작하기를** 원했고, 동작할 수 있는 기능이다              |
| SVG 안에 `role="button"` 을 되살린다 | 승인된 레퍼런스를 수정하게 된다 (규칙 6). 포커스 링·히트 영역도 직접 만들어야 한다       |
| 데크 아래에 별도 컨트롤 행을 만든다  | 플레이어에 이미 트랜스포트가 있다. 세 번째 컨트롤 행이 생기고, 그려진 ▶ 는 여전히 죽는다 |
| ■ 를 진짜 정지(큐 되감기)로 만든다   | 코디네이터에 없는 명령을 새로 만들어야 한다. 일시정지가 사용자 기대에 더 가깝다          |
| 큐가 없을 때 ▶ 를 비활성으로         | 투명한 오버레이 버튼이라 비활성임이 보이지 않는다. 죽은 버튼으로 보이는 것과 같다        |

## 결과

### 좋아진 것

- 데크의 ▶ / ■ 가 동작한다. 세로 화면의 재생 경로가 하나 더 늘었다
- `DashboardShell` 에서 떼어낸 재생 계약이 **데크로 옮겨가지 않았다** — 데크는
  코디네이터 계약 파일만 가져온다

### 비용

- 보이는 글자(`STOP`)와 실제 동작(일시정지)이 다르다. 접근성 이름이 사실을
  말하지만, 눈으로 보는 사용자에게는 레퍼런스의 글자가 그대로 남는다
- 투명한 오버레이 버튼은 **어디를 눌러야 하는지 그림에 의존한다.** hover 와
  focus 에서만 드러난다

### 아직 확인되지 않은 것

실기기에서 터치 목표가 실제로 24px 이상인지, 데크가 작게 렌더되는 폭에서도
글자 위를 정확히 누를 수 있는지는 확인하지 못했다.
