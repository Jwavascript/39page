# 0026. Moment 캡처는 누른 순간 플레이어를 한 번에 읽고, 확정되지 않은 시점을 0 으로 만들지 않는다

- 상태: 채택 — **M10-4 (2026-11-11)**
- 관련: **ADR 0023** (확장 → 웹앱은 수집 화면 URL), **ADR 0019** (Moment 도메인),
  **ADR 0020** (재생 시점 — 웹앱 플레이어), **ADR 0025** (탭 간 쓰기 잠금),
  `docs/architecture/EXTENSION_DESIGN.md` §5-1 · §13

## 배경

YouTube 에서 듣다가 "지금 이 순간" 을 39page Moment 로 남기고 싶다. 확장 팝업에서 누르면
그 순간의 영상과 시점을 고정하고, 메모는 39page 에서 쓰고 저장한다.

어려운 점:

- YouTube 시청 페이지는 SPA 다. 주소 · 제목 · 플레이어가 서로 다른 시각에 바뀐다
  (M10-2 실측). 영상 ID 와 시점이 서로 다른 영상에서 오면 엉뚱한 Moment 가 된다.
- 플레이어는 광고 · 시작 전 · 불러오는 중에도 "시점" 을 돌려준다. 그 값을 그대로 쓰면
  **지어낸 0초**나 광고의 시점이 저장된다.
- 메모를 주소로 넘기면 다른 사이트가 메모를 미리 채운 링크를 만들 수 있다.

## 결정

1. **메인 세계에서 한 번에 읽는다.** `capturePlaybackInPage` 가 `#movie_player` 의
   `getVideoData()` · `getCurrentTime()` · `getPlayerState()` · `getDuration()` · 광고
   클래스 · 라이브 표시를 **같은 동기 실행 안에서** 읽는다. 플레이어 메서드는 격리된
   세계에서 보이지 않으므로 content script 가 아니라 Background 가 `scripting.executeScript
({ world: 'MAIN' })` 로 실행한다. 유한하지 않은 수는 `null`.
2. **판정은 순수 함수 하나** (`decideCapture`). 플레이어 영상이 주소의 영상과 다르면
   `page-changed`, 광고면 `ad`, 라이브면 `live`, 시작 전(-1) · 대기(5) · 1초 미만의
   버퍼링이면 `not-started`, 못 읽으면 `unreadable`. 재생 · 일시정지 · 1초 이상의 버퍼링 ·
   끝이면 `atSeconds = floor(시점)`. **재생·일시정지 중의 0초는 확인된 0** 이라 받는다.
3. **Shorts · 라이브 · 임베드는 MVP 범위 밖.** 팝업이 버튼을 끄고 이유를 적는다.
4. **계약 v1 에 `kind=moment` 와 `atSeconds` 를 더한다.** 0 이상 정수, 6자리 이하, 한 가지
   표기만(부호 · 소수점 · 지수 · 공백 · 앞자리 0 거절). 확장은 0 이상 정수가 아니면 주소를
   만들지 않는다. `track` 에 `atSeconds` 가 있으면 거절한다.
5. **메모는 주소로 받지 않는다.** `note` · `memo` 가 주소에 있으면 어느 종류든 거절한다.
   메모는 수집 화면에서 쓰고(500자, 넘기면 저장하지 않음 — 자르지 않는다), 화면을 연 것만으로
   저장하지 않는다.
6. **저장은 기존 Moments store 의 `add`** — 대시보드와 같은 검증 · 같은 탭 간 잠금
   (ADR 0025). 별도 저장 구조를 만들지 않는다. 수집 화면도 갈림길 전에 Moments 를 복원하고
   다른 탭의 저장을 듣는다.
7. **빠른 연속 클릭** — 팝업은 한 번에 하나, Background 는 같은 탭 · 같은 영상의 캡처를 같이
   쓰고, 5초 안 같은 영상 · 같은 시점이면 열어 둔 수집 탭을 앞으로 가져온다.
8. **권한은 그대로다** — `activeTab` · `scripting`.

## 실측에서 정한 것

- 재생한 적 없는 플레이어에 이동만 하면(`seekTo`) 상태가 -1(시작 전)인 채 시점은 이동한 값이다.
  이 값은 사용자가 고른 지점일 수도 있지만, SPA 이동 직후의 낡은 값과 구분할 수 없다.
  **보수적으로 거절**하고 "재생한 뒤 다시 눌러 주세요" 라고 한다.
- 재생 직후 이동하고 곧바로 멈추면 버퍼링을 거쳐 시작 전(-1)으로 돌아갈 수 있다 — 같은 거절.

## 대안

| 대안                                            | 기각 이유                                                                                            |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| content script 가 `<video>.currentTime` 을 읽음 | 광고 영상 · 다음 영상의 `<video>` 와 구분할 수 없고 영상 ID 와 함께 오지 않는다                      |
| 시작 전이라도 이동한 시점이면 받기              | SPA 이동 직후의 낡은 시점과 구분하지 못한다 — 엉뚱한 Moment 보다 거절이 낫다                         |
| 메모를 팝업에서 쓰고 주소로 넘기기              | 다른 사이트가 메모를 미리 채운 링크를 만들 수 있다. 팝업은 포커스를 잃으면 닫혀 쓰던 메모가 사라진다 |
| 확장이 직접 저장                                | 확장은 39page origin 에 접근 권한이 없다 (ADR 0023)                                                  |

## 결과

- 누른 순간의 영상 · 시점이 함께 고정되고, 확정되지 않은 시점은 저장되지 않는다.
- 라이브 · Shorts 는 아직 Moment 로 남길 수 없다 (TODO).
- 사람이 직접 누르는 Chrome · 실기기에서의 시점 정확도는 검증하지 못했다.
