# 0043. 공유는 따로 된 공유 대화상자, 데이터 · 백업은 옮기기 전용 — 고르는 칸 · 설명 글 · 파일(ZIP) 공유를 없앤다

- 상태: 채택 — 사용자 요청 (2026-11-20, ADR 0042 배포 뒤 실제 사용), 브랜치 `feat/share-dialog`
- 관련: ADR 0040 (공유 링크) · 0041 (공유 카드) · 0042 (공유 입구 · 카드 앨범아트) · 0034 (ZIP 전체 백업 · **파일 공유** — 파일
  공유 부분을 대체) · 0027 결정 7 (데이터 대화상자)

## 배경

ADR 0042 를 배포한 뒤 사용자가 써 보고 짚었다 (2026-11-20).

- 공유 단추를 누르면 데이터 · 백업 대화상자가 열리고 백업이 먼저 보인다. 공유는 아래로 내려야 있어 헷갈린다.
- 그 대화상자는 글이 너무 많고, 무엇이 어떤 기능인지 바로 알기 어렵다.
- 데이터 쪽은 "전체 백업 내보내기" 와 "백업 가져오기" 단추만 남기고 설명을 모두 없앤다. 백업은 다른 기기로 옮길 때만 쓴다.
  맨 아래 "파일로 공유(ZIP)" 는 없앤다.
- 목록 공유는 곡 이름 · Moments 넣기 같은 고르기 없이 이미지 카드와 링크만. 곡 이름만 잘 들어가면 된다.
- 곡 하나 공유는 Moments · Moments 메모를 기본으로 넣고, 39page 기본 그림을 뺀다 — 곡 이름과 시점별 Moment 메모만 보이게. 높이가
  줄어도 된다. (그때 카드에는 Moment 메모가 들어가지 않았다.)
- 두 카드 모두 "39page 에서 듣기" 글을 빼고 재생 표시만 남긴다 — 사이트 광고처럼 보일 수 있다.

## 결정

1. **공유 대화상자를 따로** — 공유 단추(지금 재생 카드 · 데크 · 보관함의 목록 "이 목록 공유" · 곡 "공유" · Moments "링크로 공유")가
   `ShareDialog` 를 연다. 데이터 · 백업 대화상자와 겹치지 않는다. 연 동안만 마운트되고, Esc · × · 배경으로 닫으면 연 단추로 포커스가
   돌아온다. Esc 는 받은 공유 → 공유 → 데이터 → 보관함 순으로 닫는다.
2. **공유 대화상자의 내용** — 무엇을 공유하는지 한 줄(종류 · 이름 · 곡 수 / Moment 수 / 시점), 이미지 카드(미리보기 · 이미지 복사 ·
   이미지 저장), 링크(링크 칸 · 링크 복사). 목록 · 범위를 다시 고르는 칸, 곡 이름 · Moments · 메모 · 앨범아트 넣기 칸, 설명 글,
   크기 표기를 두지 않는다. 남기는 글은 "링크를 가진 누구나 내용을 볼 수 있어요" 한 줄과, 그때만 뜨는 경고(링크가 김 · 곡 이름을
   뺐음 · 너무 많음)뿐이다.
3. **무엇이 들어가는지는 대상이 정한다**

   | 대상   | 곡 이름 | Moments              | 메모   | 카드                              |
   | ------ | ------- | -------------------- | ------ | --------------------------------- |
   | 목록   | 넣는다  | 넣지 않는다          | —      | J카드 · LP 뒷면 · 영수증 (그대로) |
   | 곡     | 넣는다  | 그 곡의 Moments 모두 | 넣는다 | 싱글 — 곡 이름 + 시점별 메모 목록 |
   | Moment | 넣는다  | 그 Moment            | 넣는다 | 싱글 — 곡 이름 + 그 시점 · 메모   |

   목록 링크가 담을 수 있는 길이를 넘으면 **링크에서만** 곡 이름을 빼고(받는 쪽이 YouTube 에서 찾는다) 그렇다고 한 줄로 말한다. 그래도
   넘으면 링크를 만들지 않는다. 카드에는 늘 곡 이름이 있다. 사용자 앨범아트는 있으면 늘 넣는다(ADR 0042 의 끄는 칸을 없앴다).

4. **싱글 카드** — 39page 기본 그림(도트 카세트 · 레코드)을 넣지 않는다. 곡 이름(세 줄까지) 아래에 Moment 줄: 시점(Kawaii 는 분홍
   테두리 알약 "▶ 1:23", Mono 는 "◆ 1:23") · 메모(네 줄까지, 시점 칸 옆에 맞춰). 높이는 내용만큼 — 최소 640, 최대 3,240(넘치면
   "+N개 더"). 사용자 그림이 있으면 그것만 넣는다(Kawaii 400px 가운데, Mono 360px 재킷 + 레코드).
5. **"39page 에서 듣기" 글을 뺀다** — J카드 · 싱글은 분홍 원 안의 ▶, LP 뒷면 · Mono 싱글은 바닥 줄 오른쪽 테두리 원 안의 ▶, 영수증은
   먹색 원 안의 ▶. 위쪽의 "39PAGE" 표기 · J카드의 `39page.com` 은 그대로다.
6. **데이터 · 백업은 옮기기 전용** — 단추는 "전체 백업 내보내기"(앨범아트까지 담은 ZIP) · "백업 가져오기"(ZIP · JSON) 둘뿐. 범위
   설명 · 저장 상태 표 · 평문 고지 · 개수 · JSON 안내 · 도움말 · 앨범아트 저장 공간 칸(사용량 · 정리 · 오래 보관 요청)을 없앤다.
   가져오기 미리보기 · 승인 · 섹션별 결과, 저장 이상 경고는 그때만 뜨므로 남긴다. JSON 내보내기는 저장된 데이터를 읽지 못했을 때의
   "복구본 내보내기" 로만 남는다(ADR 0018 의 명시적 확인 그대로).
7. **파일(ZIP) 공유를 없앤다** — "공유 파일 만들기" · "공유 파일 가져오기" 와 그 코드(`useShare.ts` · `sharePackage.ts`)를 지웠다.
   전체 백업 ZIP 은 그대로다. 전체 백업 가져오기는 공유 패키지(`39page-share`)를 계속 거절한다(형식 판별은 `packageFormat.ts` 에
   남는다). 받은 목록 이름 규칙(`uniquePlaylistName`)은 링크 받기가 쓰므로 `playlistName.ts` 로 옮겼다.

## 대안

- **데이터 대화상자를 탭(백업 · 공유)으로 나누기** — 공유 단추를 눌렀는데 백업 이름이 붙은 창이 뜨는 것은 그대로다.
- **고르는 칸을 "더 보기" 로 접기** — 칸이 남으면 글도 남는다. 사용자가 고르기 자체를 원하지 않았다.
- **곡 카드에 메모를 끄는 칸** — 사용자가 "기본으로" 를 원했다. 대신 미리보기에 메모가 그대로 보이고, 개인정보 처리방침에 메모가
  함께 들어간다고 적었다.
- **파일 공유를 다른 자리로 옮기기** — 링크 · 이미지 카드로 대신한다. 앨범아트까지 넘기는 길은 전체 백업뿐이다.

## 결과

- 새 의존성 · 새 저장 상태 없음. 저장 키 · 라이브러리 · 백업 형식 · 공유 링크 형식 · 확장 계약 그대로.
- 계약 변경: `ShareCardModel.moment` → `moments`(싱글의 Moment 목록), 싱글의 `height` 는 그릴 때 정한다. `useShareLink` 의
  `titles` · `includeMoments` · `notes` · `availableMoments` · `lengthWithoutTitles` 를 없애고 `titlesDropped` 를 더했다.
  `useShareCard` 의 `hasArt` · `includeArt` 를 없앴다. `DataDialog` 의 `shareRequest` prop 을 없앴다.
- 지운 것: `SharePanel.vue` · `useShare.ts` · `sharePackage.ts` · `ArtworkStoragePanel.vue` 와 파일 공유 시험(`share-package.spec.ts`).
  앨범아트 store 의 사용량 · 정리 · 오래 보관 요청 함수는 남겼다(시험이 있다) — 화면에서 부르는 곳은 없다.
- 시험: 평소의 JSON 내보내기 시험은 화면 단추 대신 같은 composable 을 부른다(`tests/support/jsonExport.ts`).
