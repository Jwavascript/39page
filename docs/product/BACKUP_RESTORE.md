## 1. 사용자가 해결하려는 문제

| 상황                                     | 지금    | 백업 이후       |
| ---------------------------------------- | ------- | --------------- |
| 새로고침 · 브라우저 재시작               | 보존    | 변화 없음       |
| **브라우저 사이트 데이터 삭제 · 시크릿** | 유실    | 파일로 되살린다 |
| **다른 기기 · 다른 브라우저**            | 안 보임 | 파일로 옮긴다   |
| **주소(origin) 변경**                    | 안 보임 | 파일로 옮긴다   |

`localStorage` 는 **origin 단위**다. 계정·서버 없이 이 셋을 해결하는 유일한
방법이 파일이다.

## 2. 기능

### F10. 라이브러리 내보내기 — 구현 완료 (M8-2)

자리는 **레코드 편집 시트의 바닥**이다. 편집 버튼과 선으로 끊고 `DATA` 라는
다른 머리말을 붙인다 — 이 목록을 고치는 일과 앱 전체 데이터를 꺼내는 일은
성격이 다르다.

- 한 번의 조작으로 **JSON 파일 하나**를 내려받는다
- 파일 이름: `39page-backup-20261106-1321.json` (로컬 시각)
- 담기는 것: 플레이리스트와 트랙, 선택된 목록, 현재 테마
- 담기지 않는 것: 재생 중인 큐·위치, 플레이어 상태, 화면 상태
- 저장소 상태와 무관하게 **항상 내보낼 수 있다.** 데이터가 깨져 보호 상태일
  때도 메모리에 있는 것은 꺼낼 수 있다
- 보호·접근 실패 상태에서는 버튼이 **`복구본 내보내기`** 로 바뀌고, 누르면
  **확인 단계**를 거친다. 받은 파일에는 복구본 표시(`integrity`)가 들어간다 —
  나중에 온전한 백업으로 오인해 덮어쓰는 일을 막는다
- 저장은 실패했지만 복원은 정상이었던 경우는 **복구본이 아니다.** 그때 파일은
  저장소보다 더 온전하다. 대신 "이 세션의 변경이 저장되지 않았습니다. 지금
  내보내면 파일에는 포함됩니다" 를 알린다

### F11. 라이브러리 가져오기

1. 파일을 고른다
2. 앱이 검사하고 **미리보기**를 보여준다
3. 사용자가 승인하면 반영한다

미리보기에 적는 것:

| 항목                   | 예                                         |
| ---------------------- | ------------------------------------------ |
| 내보낸 시각            | `2026-11-06 13:21`                         |
| 가져올 플레이리스트    | `4개 (총 37곡)`                            |
| 설정                   | `테마: Kawaii Synth Cassette` — 끌 수 있다 |
| **가져오지 못하는 것** | `트랙 2곡 (영상 ID 형식 오류)`             |
| **지금 데이터**        | `플레이리스트 2개 (총 11곡) — 교체됩니다`  |

### F12. 가져오기 전 안전장치

- 확인 단계에 **"지금 데이터를 먼저 내보내기"** 버튼을 둔다. 한 번 누르면
  현재 상태가 파일로 떨어진다
- 저장 데이터가 보호 상태(읽을 수 없음)면 **"읽을 수 없는 원본 내려받기"** 를
  함께 제공한다. 앱이 해석하지 못해도 사용자는 보관할 수 있다

## 3. 정책

### 3-1. 승인 전에는 아무것도 바뀌지 않는다

파일을 고르고, 검사하고, 미리보기를 보는 동안 **저장된 데이터는 손대지
않는다.** 사용자가 승인 버튼을 누른 뒤에 처음 쓴다.

### 3-2. 전체 교체만 지원한다 (M8)

가져오기는 **지금 라이브러리를 파일의 것으로 바꾼다.** 기존 목록에 더하는
병합은 M8 범위가 아니다.

이유: 병합은 "같은 id 를 어떻게 하나", "같은 곡이 두 번 들어가도 되나",
"같은 이름을 어떻게 구분해 보이나", "선택 상태는 누구 것인가" 를 모두 정해야
하고, 결과를 사용자가 예측하기 어렵다. 백업·복원의 목적은 교체로 달성된다.

확인 문구가 **교체라는 사실과 지금 데이터의 개수**를 함께 말한다.

### 3-3. 일부만 유효한 백업도 가져올 수 있다

500곡 중 1곡의 영상 ID 가 깨졌다고 복원을 포기하게 만들지 않는다. 단
**버리는 항목의 개수와 이유를 미리보기에 적고**, 그것을 본 상태에서 승인해야
한다. 조용히 버리지 않는다.

파일은 사용자 손에 그대로 남으므로 되돌릴 수 있다 — 그래서 허용한다. 반대로
`localStorage` 원본이 일부만 읽힌 경우에는 덮어쓰기를 **막는다**(기존 정책).
원본이 영구히 사라지기 때문이다.

### 3-4. 열 수 없는 파일은 이유를 말한다

| 사용자가 보는 것                             | 상황                         |
| -------------------------------------------- | ---------------------------- |
| "JSON 파일이 아닙니다"                       | 파싱 실패                    |
| "39page 백업 파일이 아닙니다"                | 식별자 불일치                |
| "더 새 버전의 39page 에서 만든 파일입니다"   | 파일 버전이 미래             |
| "파일이 너무 큽니다 (최대 8 MB)"             | 크기 초과                    |
| "이 버전에서 가져올 수 없는 항목이 있습니다" | 모르는 섹션 · 미래 섹션 버전 |

어느 경우에도 **기존 데이터는 변하지 않는다.** 파일도 변하지 않는다.

### 3-5. 저장이 실패하면 기존 데이터를 지킨다

| 결과                        | 사용자에게                                              |
| --------------------------- | ------------------------------------------------------- |
| 용량 초과                   | "저장 공간이 부족합니다. 기존 데이터는 그대로입니다"    |
| 저장소 접근 불가            | "저장할 수 없습니다. 기존 데이터는 그대로입니다"        |
| 라이브러리 성공 · 테마 실패 | "라이브러리를 복원했습니다. 테마는 적용되지 않았습니다" |

가치가 큰 것(라이브러리)을 먼저 쓴다. 뒤가 실패해도 앞을 되돌리지 않는다 —
테마는 다시 고르면 되는 값이고, 되돌리면 사용자가 방금 승인한 복원을 앱이
취소하는 것이 된다.

### 3-6. 파일은 평문이다

사용자에게 알린다. 플레이리스트 이름과 YouTube 영상 ID 가 그대로 보인다.
암호를 걸거나 서버에 올리지 않는다.

## 5. UI 자리 — 결정됨 (M8-2)

**레코드 편집 시트의 바닥**이다. 후보 셋 중 둘째를 골랐다.

| 후보                        | 장점                       | 단점                                   |
| --------------------------- | -------------------------- | -------------------------------------- |
| 헤더 (테마 전환 옆)         | 늘 보인다                  | 헤더가 붐빈다. 자주 쓰는 기능이 아니다 |
| **레코드 편집 시트의 바닥** | 라이브러리 맥락과 가깝다   | 세로에서 시트가 좁다                   |
| 플레이리스트 위젯의 머리말  | 플레이리스트가 사는 곳이다 | 위젯이 더 복잡해진다                   |

레퍼런스에 없는 영역이므로 **승인된 값을 하나도 바꾸지 않는 방식**을 골랐다 —
드로어가 쓰는 토큰만 재사용하고 새 색·새 치수를 만들지 않는다. 그래서 두 테마
에서 자동으로 맞는다.

세로에서 시트가 좁은 것은 시트가 **안에서 스크롤**하므로 문제가 되지 않는다.
실측에서 버튼 높이 36px 로 터치 목표를 지켰다.

> 가져오기(M8-3)는 같은 패널에 들어간다. `DATA` 머리말 아래에 내보내기와
> 가져오기가 나란히 서는 모양이 된다.
