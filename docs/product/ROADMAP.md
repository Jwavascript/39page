### M0 — 프로젝트 초기화 (완료)

디렉터리 구조와 문서 틀. 기능 구현 없음.

### M1 준비 — 디자인 레퍼런스 반영 (완료)

`design/references/`의 프로토타입 2종을 검토해 제품·아키텍처 문서를 갱신하고,
확정된 결정 3건을 ADR로 기록했다. Git 초기 기준점을 `main`에 커밋하고
MVP 범위를 정정해 확장 항목을 백로그로 분리했다. **UI 구현은 포함하지 않았다.**

### M1 — 앱 셸 · 두 테마 · 테마 전환 · Widget Host · 플레이어 영속성 구조

테마를 전환해도 **플레이어 인스턴스와 DOM 구조가 유지되는지** 검증하는 것이
목표다. 플레이어 iframe은 부모가 바뀌기만 해도 재로드되므로, 이 제약을 만족하는
DOM 골격을 가장 먼저 확정한다.

M1은 `FakePlayerAdapter` 기반의 **구조 검증**에 집중하고, 실제 YouTube IFrame API
동작은 M3로 분리한다.

### M8 — JSON 백업·복원 (운영 배포 완료)

계정·서버 없이 데이터를 꺼내고 되살린다. `localStorage` 는 origin 단위이므로
브라우저 데이터 삭제·기기 이전·주소 변경에서 유실되는데, 파일이 그 셋을 모두
해결한다.

**M8-3 가져오기까지 끝났다.** 레코드 편집 시트 바닥의 `DATA` 패널에서 JSON
파일을 내려받고 가져온다.

- 내보내기 — 보호 상태에서는 복구본으로 구분해 내보낸다
- 가져오기 — 미리보기에서 교체 전후를 비교하고 `교체하고 가져오기` 로 승인한다.
  **승인 전까지 저장소에 아무것도 쓰지 않는다**
- 복원하면 재생을 멈추고 재생 목록을 비운다 (큐가 가리킬 라이브러리가 사라졌다)

Chromium 실측: 내보내기 27개 · 가져오기 9단계 25개 · 반응형 5폭×2테마 160개
항목 통과. 성능은 1,000곡에서 47ms, 30,000곡에서 2.3초로 측정됐다.

#### 운영 배포 (2026-11-06)

`main` 에 네 커밋(`1f06b3b` · `b9c22b2` · `98d33ad` · `62d9a19`)을
fast-forward 푸시했고, Cloudflare Workers Builds 가 받아 배포했다. 이력
재작성이나 강제 푸시는 없다.

배포본이 이 저장소의 코드라는 근거는 해시다 —
`https://39page.com/assets/index-CLfAKeJC.js` 의 SHA-256 이 로컬
`npm run build` 산출물과 **바이트 단위로 같다.**

**운영 `https://39page.com` 에서 실제로 확인한 것** (전용 브라우저 프로필 ·
테스트 데이터 · 실제 다운로드). 로컬 검증과 구분해 적는다.

#### ⚠ 배포 후 발견해 고친 것 — 좁은 드로어의 가로 스크롤바

운영 스크린샷에서 드로어 본문에 가로 스크롤바가 보였다. 1440px 가로
화면에서 드로어는 339px 짜리 좁은 열인데 트랙 행이 31px 더 넓었다. 영상
ID 를 접는 기준이 **뷰포트** 질의여서, 뷰포트가 1440px 인 가로 화면에서는
"넓다"고 답했기 때문이다. `.track-list` 를 인라인 크기 컨테이너로 선언하고
`@container` 질의를 더했다 (뷰포트 질의는 구형 브라우저용 보루로 남겼다).

데이터 손실 위험은 아니다. M8-4 반응형 점검이 문서 루트와 패널만 재고
**내부 스크롤 컨테이너를 재지 않아** 놓쳤다 —
`IMPLEMENTATION_PLAN.md` M8-4 에 정정으로 적었다.

빌드와 바이트 동일하고 운영 스모크 44항목이 통과했다 (`DEPLOYMENT.md` §5
"M9 운영 배포"). 남은 것은 Android Chrome · iOS Safari 실기기 확인이다.

명세는 [`MUSIC_MOMENTS.md`](MUSIC_MOMENTS.md) (F13–F17 구현),
설계는 [`../architecture/MOMENTS_DESIGN.md`](../architecture/MOMENTS_DESIGN.md),
작업 분해는 [`../development/IMPLEMENTATION_PLAN.md`](../development/IMPLEMENTATION_PLAN.md) M9 다.

정한 것 넷.

1. **Moment 는 `videoId` 를 가리킨다** — 트랙을 지워도 남는다 (ADR 0019)
2. **전용 저장 키 `39page.moments`** — 백업 복원이 Moments 를 지우지 않고,
   캐시된 옛 빌드가 복원해도 그 브라우저의 Moments 는 살아남는다
3. **시점 조회·이동은 어댑터 계약에 넣는다** — `position()` · `seek()` ·
   `load({ startSeconds })`. UI 는 코디네이터만 부른다 (ADR 0020)
4. **백업에서 "섹션 없음" 과 "빈 섹션" 은 다르다** — 없으면 유지, 비었으면
   0개로 교체. 구분하지 않으면 **지금 있는 모든 백업**을 복원할 때마다
   Moments 가 사라진다 (`BACKUP_FORMAT.md` §6-2)

파일 `schemaVersion` 은 **1 그대로다.** 선택 섹션 추가는 올리지 않는다.

M9-2 에서 더 정한 것 셋 (ADR 0019 결정 7·8·9) — 메모 입력 상한 500자,
빈 제목 스냅샷은 대체 표기로 채우지 않음, 해석 안 되는 날짜 때문에 Moment
전체를 버리지 않음.

> M9-5 전(M9-2 ~ M9-4 시기)에 받은 백업 파일에는 Moment 가 없다. 그런 파일을
> 가져오면 지금 Moments 는 **그대로 남고**, 미리보기가 "Moments 가 생기기 전에
> 만든 파일" 이라고 먼저 알린다 (M9-5).

> ⚠ 코드로 막지 못하는 경로가 하나 남는다. **옛 빌드에서 새로 내보낸 파일에는
> Moments 가 없다.** 배포된 번들은 고칠 수 없으므로, M9 쪽에서 그런 파일을
> 읽을 때 안내하는 것으로 다룬다 — M9-5 에서 구현했다.

### M10 — Chrome 확장을 통한 수집 (진행)

YouTube 에서 찾은 음악을 링크 복사 없이 39page 플레이리스트에 담는다
(Quick Add). 다음은 지금 보는 영상의 시점·메모를 Moment 로 남기는 캡처다.
**백업 파일을 확장과의 실시간 동기화 수단으로 쓰지 않는다** (ADR 0018 결정 12).

| 단계  | 상태                                                                                                                            |
| ----- | ------------------------------------------------------------------------------------------------------------------------------- |
| M10-1 | ✔ 설계 — 독립 프로젝트 `extension/` (ADR 0022), 수집 화면 URL + 웹앱 승인 (ADR 0023)                                            |
| M10-2 | ✔ 골격 — MV3 · 팝업 · YouTube 인식. 저장 없음. 실제 Chromium · 실제 YouTube 33/33                                               |
| M10-3 | ✔ Quick Add — 탭 간 덮어쓰기 해결(ADR 0024) · 수집 화면 · 팝업 "39page 에 추가". 실제 Chromium 33/33. 로컬 브랜치 — 운영에 없음 |

| M10-5 | 단축키 · 추가 UX                                                                                                                |
