## 2. 지켜야 할 장점

- **두 테마의 정체성** — Mono Vinyl · Kawaii Synth Cassette 의 데크 · 질감. 승인된 레퍼런스(`design/references/`)는 바꾸지 않는다.
- **한 화면의 고요함** — 대시보드는 "보는 곳" 이다. 관리 화면이 늘어도 대시보드를 관리 도구로 만들지 않는다.
- **끊기지 않는 재생** — 플레이어 iframe 은 한 번만 마운트되고(ADR 0002), 가려지면 멈춘다(ADR 0011). 어떤 새 패널도 이 둘을 깨면 안 된다 — 이것이 대안 평가의 첫 번째 거름망이다.
- **데이터 보호** — 손상 · 상위 버전 원본을 덮어쓰지 않는다(ADR 0007), 탭 간 잠금(ADR 0025), 가져오기 승인 전 읽기 전용(ADR 0018).
- **Moments 의 영상별 묶음과 "목록에 없음" 재생** — 데이터는 독립, 표시만 이어 붙이는 현재 구조가 맞다.
- **수집 화면의 승인 모델** — 링크로 연 화면은 누를 때만 저장한다(ADR 0023). 확장 패널도 같은 원칙.

## 3. 새 정보 구조 (IA)

네 가지 역할로 나눈다 — 지시서의 안을 받아들이되, **화면 넷이 아니라 "한 화면 + 두 서랍 + 한 대화상자"** 로 담는다 [제안].

| 역할                 | 하는 일                                                                                         | 자리                     | 빈도      |
| -------------------- | ----------------------------------------------------------------------------------------------- | ------------------------ | --------- |
| **Dashboard**        | 듣기 · 재생 조작 · 지금 곡 · 지금 곡의 Moments 미리보기와 빠른 저장 · 시계 · 날씨 · 마스코트    | 기본 화면 (그대로)       | 항상      |
| **보관함 · 음악**    | 플레이리스트 탐색 · 곡 추가/수정/삭제 · 재생 큐 · 곡별 Moments 보기                             | 보관함 서랍 "음악" 탭    | 자주      |
| **보관함 · Moments** | 전체 Moments 탐색 · 음악별 묶음 · 검색 · 필터 · 시점 재생 · 메모 수정/삭제 · 어느 목록에 있는지 | 보관함 서랍 "Moments" 탭 | 가끔~자주 |
| **데이터**           | JSON 백업 내보내기 · 가져오기 · 저장 상태 · 짧은 도움말                                         | 헤더 "데이터" → 대화상자 | 드물게    |

헤더(모든 폭에서 같은 이름, 같은 순서):

```
39page        [♪ 음악]  [◆ Moments]  [⇩ 데이터]          01 / MONO VINYL · 02 / SYNTH CASSETTE
```

- 버튼에는 **글자 이름**을 단다. 좁은 폭에서도 아이콘만 남기지 않는다 (U4 · U5).
- "음악" · "Moments" 는 같은 보관함 서랍의 다른 탭을 연다. "데이터" 는 대화상자를 연다.
- 대시보드의 진입점(플레이리스트 타일, Moments 미리보기의 "모두 보기")도 같은 서랍 · 같은 탭으로 간다 — 한 기능에 한 자리.

## 4. 화면 구조 대안 비교

정적 비교 시안: `design/mockups/m11-1/index.html` (두 테마 토큰 · 데스크톱 1440 · 모바일 390 · **구현 아님** 표시).

### 4-1. 세 가지 안

**A. 대시보드 유지 + 기능별 서랍** — 지금 구조에 "Moments 서랍" · "데이터 서랍" 을 더한다. 각 서랍은 오른쪽 덮개(넓은 폭) · 아래 시트(좁은 폭).

**B. 대시보드는 미리보기, 관리는 별도 화면** — `#library` · `#moments` · `#data` 화면으로 바꿔 넘어간다. 대시보드는 작아진다.

**C. 음악 중심 통합 보관함** — 라이브러리와 Moments 를 **한 서랍의 두 탭**으로 합치고 서로 건너간다 (곡 → 그 곡의 Moments, Moment 묶음 → 그 곡이 든 목록). 데이터는 대화상자.

### 4-4. 추천: C — 통합 보관함 (A 의 서랍 껍데기 위에)

**선택 근거**

1. **재생을 끊지 않는다.** B 는 관리 화면에서 플레이어가 사라져 가시성 가드에 걸린다. C 는 보관함이 열려도 플레이어가 보인다.
2. **데이터는 독립, 탐색은 통합** — 지시서의 목표 문장과 같은 모양이다. Moments 가 플레이리스트의 하위 항목이 되지 않으면서(ADR 0019) 곡 ↔ Moments 를 한 번에 오간다.
3. **정보 밀도를 확보한다.** 서랍 340px 은 Moments 탐색에 너무 좁다(U6). 열린 동안 그리드를 바꿔 넓힌다.
4. **변경 범위가 감당할 만하다.** 새 화면 · 라우터 · 미니 플레이어가 없다. 서랍 하나와 그리드 상태 하나.

**데스크톱 "보관함 열림" 그리드** [제안 — M11-2 에서 실측으로 확정]

```
닫힘 (지금):  deck   | player | info            열림:  player | 보관함 ──────────────
              playlist | mascot | moments                (데크 · 셸프 · 마스코트 · 정보 열은 CSS 로 접힘)
```

- `WidgetHost` 의 `grid-template-areas` 만 바꾼다. 위젯은 `v-if` 로 지우지 않고 CSS 로 감춘다 — **플레이어 노드는 움직이지 않는다** (ADR 0002 의 금지 목록 준수).
- 플레이어 칸은 최소 360px(지금의 `minmax(360px, …)`)을 지킨다. 보관함은 나머지 폭(1440px 에서 약 700px).
- 닫으면 원래 배치. 열림 상태는 저장하지 않는다.

**포기한 대안의 장단점**

| 대안 | 버린 이유                                                                      | 아까운 점 (C 에 옮긴 것)                                                |
| ---- | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| A    | 340px 폭에 Moments 검색 · 묶음이 들어가지 않는다. 서랍 셋의 열림 규칙이 얽힌다 | 가장 작은 변경 — C 는 A 의 서랍 껍데기 · 시트 · 가림 통지를 그대로 쓴다 |
| B    | 관리 화면에서 플레이어가 안 보여 멈춘다. 미니 플레이어 · 화면 전환이 크다      | 넓은 화면과 분명한 이름 — C 는 그리드를 넓히고 헤더에 이름을 단다       |

**사용자가 고를 수 있게 남긴 것** — §10 "결정이 필요한 UX 항목".

## 5. Music Moments 관리 UX

데이터 모델은 **그대로**다 (ADR 0019): Moment 의 외부 참조는 `videoId` 하나, 플레이리스트에서 곡을 지워도 남는다.
아래는 모두 표시 계층에서 `videoId` 로 이어 붙인다 — `momentsView.ts` 가 이미 라이브러리 제목을 찾는 방식과 같다.

### 5-1. 대시보드 — "이 곡의 Moments"

| 지금                                      | 바꿈 [제안]                                                                                                               |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 전체/이 곡 필터 + 긴 목록 + 인라인 편집   | **지금 곡의 Moments 최대 3개** (시점 순) + "＋ 이 순간 저장" + "모두 보기 (N)"                                            |
| 저장 버튼 → 메모 폼이 목록 자리를 덮는다  | 저장 버튼 → **바로 저장**하고 "1:23 저장됨 · 메모 쓰기" 안내 (메모는 보관함 편집으로) — 또는 지금처럼 폼 (결정 필요, §10) |
| 메모 수정 · 삭제가 위젯 안에서            | 위젯에서는 하지 않는다. 행을 누르면 그 시점부터 재생, "모두 보기" 는 보관함 Moments 탭(이 곡 필터)                        |
| 재생 전에는 버튼이 꺼지고 아래 한 줄 안내 | 그대로 — "재생을 시작하면 이 순간을 저장할 수 있어요"                                                                     |

결과: 위젯 안에 스크롤이 없다(최대 3행) → U6 · U7 이 대시보드에서 사라진다.

### 5-2. 보관함 · Moments 탭

```
[ 검색: 제목 · 메모            ]   [전체] [최근] [이 곡]        정렬: 묶음 안 시점 순
─────────────────────────────────────────────────────────────
▾ Never Gonna Give You Up · 4개 · 목록: MY RECORDS, 드라이브     ▶ 처음 Moment
    ▶ 0:43   후렴 직전 — 베이스가 들어오는 곳                      ⋯
    ▶ 1:52   …
▸ Me at the zoo · 1개 · 목록에 없음
─────────────────────────────────────────────────────────────
                                   묶음 30개 표시 · 아래로 더 불러오기
```

| 요소          | 규칙 [제안]                                                                                                                                 |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 묶음          | 음악(`videoId`)별. 묶음 순서 = 가장 최근에 저장한 Moment 순 (지금 규칙). 묶음 안 = 시점 순                                                  |
| 접기 · 펼치기 | 묶음 머리를 누르면 토글. 기본: "이 곡" · 검색 결과는 펼침, 전체 보기에서 묶음이 6개를 넘으면 최근 3개만 펼침                                |
| 검색          | 제목(라이브러리 제목 · 스냅샷)과 메모. 대소문자 · 한글 정규화(NFC) 무시. 입력 150ms 뒤 적용. 결과는 묶음째 펼쳐 보이고 일치 부분을 강조     |
| 필터          | **전체**(묶음) · **최근**(묶음 없이 저장 시각 역순 평면 목록) · **이 곡**(재생 중 영상 하나)                                                |
| 재생          | 행의 ▶ 시점 = 그 시점부터 재생 (`playMoment`, 라이브러리에 없는 곡도). 44px                                                                 |
| 메모 수정     | 행의 `⋯` → "메모 수정" → **행이 펼쳐져** 높이가 자라는 입력란(내부 스크롤 없음) + 저장 · 취소가 입력란 바로 아래 고정. 목록 스크롤은 하나뿐 |
| 삭제          | `⋯` → "삭제" → 그 행 자리에서 확인 (지금처럼 인라인 확인, 단 수정 버튼과 떨어진 메뉴 안)                                                    |
| 목록 연결     | 묶음 머리의 "목록: A, B" — 누르면 음악 탭의 그 목록 · 그 곡으로. 없으면 "목록에 없음 · 목록에 담기"                                         |

### 5-3. 10 · 100 · 1,000 · 5,000 개

M9-6 실측 결론: **데이터 처리는 병목이 아니다** (5,000개 복원 16.5ms · 묶기 7ms). **행 배치(DOM)가 병목이다** (1,000행 전체 다시 그리기 2–3초).

| Moments | 묶음(곡) 수 예상 | 화면                                                                                 | 한 번에 그리는 행    |
| ------- | ---------------- | ------------------------------------------------------------------------------------ | -------------------- |
| 10      | 2–5              | 모두 펼침. 검색창은 보이되 강조하지 않음                                             | 10                   |
| 100     | 10–40            | 최근 3묶음만 펼침, 나머지는 머리만                                                   | 머리 ≤40 + 행 ≤30    |
| 1,000   | 50–300           | 모두 접힘(이 곡 제외). 묶음을 **30개씩** 그리고 끝에 닿으면 다음 30개 (점진 표시)    | 머리 30–60 + 펼친 행 |
| 5,000   | 200–1,000        | 같음. 검색이 주된 탐색. 검색 결과가 200행을 넘으면 앞 200행 + "검색어를 좁혀 주세요" | ≤ 약 260             |

**점진 표시 방식 비교**

| 방식                               | 장점                                                               | 단점                                                                                         | 판단                                |
| ---------------------------------- | ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------- | ----------------------------------- |
| **묶음 접기 + 30묶음씩 더 그리기** | 의존성 없음. 행 높이가 달라도 됨. 화면 낭독기 · 페이지 찾기와 맞음 | 아주 많이 펼치면 다시 무거워진다                                                             | **채택 [제안]**                     |
| 가상 스크롤                        | 행 수와 무관하게 가볍다                                            | 메모 길이로 행 높이가 다르다 · 펼침/편집과 충돌 · 페이지 찾기 불가 · 라이브러리 추가(규칙 8) | 보류 — 5,000개 실측에서 필요할 때만 |
| 페이지 번호                        | 단순                                                               | 묶음이 페이지에 걸쳐 잘린다 · 검색과 어울리지 않는다                                         | 기각                                |
| `content-visibility`               | CSS 한 줄                                                          | M9-6 에서 행이 37px 튀어 기각됨                                                              | 기각 (재확인 불필요)                |

필요한 범위: **검색 · 필터 · 묶음 접기 · 점진 표시**는 M11 에서 한다. **페이지 번호는 필요 없다.** 가상 스크롤은 5,000개 실측 뒤 판단 (TODO).

### 5-4. 라이브러리와의 연결

- **음악 탭의 곡 행** — 그 영상의 Moments 수를 배지로 (`◆ 3`). 누르면 Moments 탭이 그 곡으로 걸러져 열린다.
- **음악 탭의 곡 상세** (행 펼침) — 전체 제목(자르지 않음, U12) · 영상 ID · 그 곡의 Moments 3개 미리보기.
- **Moments 묶음 머리** — "목록: A, B" (그 `videoId` 를 가진 플레이리스트). 같은 영상이 한 목록에 여러 번 있으면 한 번만.
- **재생 중 표시** (U14) — 음악 탭의 곡 행과 Moments 묶음에 같은 "재생 중" 표시. 재생 상태는 store 경유(규칙 4)로 읽는다.

## 7. 처음 방문한 사용자

튜토리얼 화면을 만들지 않는다. **이름 · 자리 · 빈 상태 · 한 줄 도움말**로 세 작업을 발견하게 한다.

| 작업                          | 발견 경로 [제안]                                                                                                                                                      |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. 음악을 플레이리스트에 추가 | 첫 실행의 빈 "MY RECORDS" 타일 = "곡 추가 ＋" 빈 상태. 누르면 보관함 음악 탭이 **링크 입력란에 초점**을 둔 채 열린다. 새 목록을 만들면 같은 입력란으로 이어진다 (U15) |
| 2. 재생 중 Moment 저장        | 대시보드 "이 곡의 Moments" 의 "＋ 이 순간 저장" 이 항상 같은 자리. 재생 전에는 꺼진 이유를 한 줄로                                                                    |
| 3. 전체 데이터 JSON 백업      | 헤더 "데이터" (글자) → 내보내기. 데이터가 하나도 없으면 "아직 백업할 것이 없어요"                                                                                     |

마스코트(M12)는 이번에 설계하지 않는다. 자리만 지킨다: 데스크톱 4행 2열(플레이어 아래) · 모바일 맨 아래 전체 폭 · 최소 높이 112px (지금 `MascotPanel`). 보관함이 열린 동안은 데크와 함께 접힌다.

LP · 카세트 클릭 (U2): 데크 클릭은 계속 "플레이리스트 펼치기" 다. 대신 **펼쳐짐이 보이게** — 누르면 레코드 · 테이프가 짧게 반응(눌림 · 회전 시작)하고, 툴팁은 `(hover: hover)` 에서만, 터치에서는 데크 아래 안내 문구가 상태에 따라 "펼치기 / 접기" 로 바뀐다 [제안 — 애니메이션 세부는 M12 와 함께].

## 8. 웹앱과 확장 프로그램의 통합 흐름

### 8-1. 목표 흐름

```
YouTube 시청
  └ 확장 아이콘 · Alt+Shift+Y (음악) · Alt+Shift+M (Moment, 누른 순간 고정)
      └ YouTube 위 플로팅 패널 (확장 페이지 iframe · 오른쪽 아래 360×≤540)
          ├ [음악 담기]  목록 고르기 / 새 목록 이름 → "플레이리스트에 담기"
          └ [Moment 저장] 고정된 시점 · 메모(선택) → "Moment 저장"
              └ 저장 확인됨 → 패널 닫기 (Esc · ×) → 계속 시청
브리지를 쓸 수 없으면 → "39page 수집 화면으로 열기" (M10 새 탭 — 검증된 대체 경로)
```

- 저장은 **39page 웹앱 store** 가 한다. 확장은 요청을 나르고 결과를 보일 뿐이다 (ADR 0028).
- 패널은 **확장 페이지를 iframe 으로** YouTube 위에 띄운다. YouTube 페이지는 다른 origin 인 패널 안을 읽거나 누를 수 없다 — 플레이리스트 이름 · 메모가 YouTube 에 노출되지 않는다.
- 단축키 · 영상 인식 · 시점 판정(광고 · 라이브 · 시작 전 거절, ADR 0026)은 M10 그대로다.

### 8-2. 플로팅 패널 구성

```
┌ 39page ─────────────────────── × ┐
│ Never Gonna Give You Up            │   ← 플레이어 getVideoData 제목 (텍스트로만)
│ dQw4w9WgXcQ · 0:43                 │
│ [ 음악 담기 ][ Moment 저장 ]       │   ← 서로 독립
│ ○ MY RECORDS        12곡  이미 3번째│   ← 같은 영상 안내 (막지 않음)
│ ● 드라이브           4곡           │
│ ○ 새 플레이리스트 [________]       │   ← 즉석 생성
│ [   플레이리스트에 담기   ]        │
│ ✔ ‘드라이브’ 5번째에 담았어요       │   ← 저장소를 다시 읽어 확인한 뒤에만
│   [이 순간도 Moment 로 저장]        │
│ 39page 수집 화면으로 열기           │   ← 대체 경로
└────────────────────────────────────┘
```

- 목록이 8개를 넘으면 맨 위에 거르기 입력란. 마지막에 고른 목록을 기억하지 않는다(확장은 데이터를 갖지 않는다) — 대시보드의 선택 목록이 기본값.
- 키보드: 열리면 첫 동작 버튼에 초점, Esc 로 닫기, 패널 안 Tab 순환. 결과는 `status`, 실패는 `alert`.
- 크기: 360×최대 540, 화면이 작으면 `calc(100vw - 32px)`. 위치 이동(끌기)은 M11 범위 밖 (TODO).

### 8-3. 즉석 플레이리스트 생성

| 상황                                    | 패널                                                                                                                                                                                                     |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 새 목록 이름 + 담기                     | 한 요청 `playlist/create-and-add` — 브리지가 `createPlaylist` 뒤 `addTrack`                                                                                                                              |
| 둘 다 저장 확인                         | "‘드라이브’ 1번째에 담았어요 · 새 플레이리스트를 만들었어요"                                                                                                                                             |
| **목록은 생겼고 곡은 실패 (부분 성공)** | 전체 성공이라 하지 않는다: "‘드라이브’ 목록은 만들었지만 곡은 담지 못했어요 + 이유" + **[‘드라이브’에 다시 담기]** — 다시 "만들고 담기" 를 하면 같은 이름 목록이 하나 더 생기므로 **만든 목록에** 담는다 |
| 같은 이름 목록이 이미 있음              | 막지 않는다 (지금 웹앱도 허용). 목록에 이미 있다고 한 줄 알림 [제안]                                                                                                                                     |
| 이름이 비었거나 60자 초과               | 버튼이 꺼진다 / 입력란 최대 60자                                                                                                                                                                         |
| 같은 영상이 고른 목록에 있음            | "이미 N번째" 를 행에 보이고 막지 않는다 (M10 수집 화면과 같음)                                                                                                                                           |
| 다른 탭과 충돌 · 잠금 대기              | "다른 39page 탭이 먼저 바꿨어요 / 저장 중이에요" + 다시 시도 (새 요청 ID)                                                                                                                                |

⚠ 지금 store 의 `createPlaylist` 는 새 목록을 **선택**한다 — 확장에서 목록을 만들면 대시보드의 선택 목록이 바뀐다(PoC 단위 시험이 고정). 선택을 바꾸지 않는 옵션을 더할지 결정 필요 (§10).

### 8-4. Moment 저장과 음악 추가의 관계

- **서로의 필수 단계가 아니다.** Moment 만 저장해도 되고(라이브러리에 없는 곡도 Moments 에 "목록에 없음" 으로 남는다), 곡만 담아도 된다.
- 한쪽을 마치면 다른 쪽을 **제안만** 한다: Moment 저장 뒤 "이 곡을 플레이리스트에도 담기", 곡 담기 뒤 "이 순간도 Moment 로 저장".
- Alt+Shift+M 은 누른 순간을 고정하고 패널을 Moment 탭으로 연다(새 탭 없음). 고정한 시점은 "지금 시점으로 다시" 로만 바뀐다.

## 11. 아직 검증하지 못한 것

- 실기기 터치 · 세로 회전 · iOS Safari 의 iframe 크기와 백그라운드 재생 — 모바일 C 안의 "플레이어를 위에 남기는 시트" 는 실기기에서 200px 하한을 확인해야 한다.
- 보관함 열림 그리드의 실제 폭(1280 · 1440 · 1920)과 테마별 시각 — M11-2 에서 실측.
- 5,000개 Moments 의 점진 표시 성능 — M9-6 에서 브라우저가 그리기 전에 멈췄다. M11-4 에서 다시 잰다.
- 사람이 직접 쓰는 사용성 시험(첫 방문자 3작업) — 설계 기준일 뿐 측정하지 않았다.
