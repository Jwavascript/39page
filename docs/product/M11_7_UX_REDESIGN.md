## 3. 진입점 정리 — 유지 · 통합 · 제거 [제안]

원칙: **대시보드 = 듣기와 빠른 조작 · 보관함 = 관리 · 데이터 = 백업.** 입구를 다 없애는 것이 아니라, 남는 입구마다 그 자리에서만
의미 있는 **문맥**이 있게 한다.

| 입구 (지금)                       | 처리           | 이유                                                                                      |
| --------------------------------- | -------------- | ----------------------------------------------------------------------------------------- |
| 헤더 "♪ 음악" · "◆ Moments"       | **통합**       | → "▤ 보관함" 하나. 마지막으로 쓴 탭으로 열린다. 첫 방문은 음악 탭                         |
| 헤더 "⇩ 데이터"                   | **유지**       | 사용자가 원함. 이름을 "⇩ 데이터 · 백업" 으로 — 무엇이 있는지 말한다                       |
| 테마 전환                         | **유지**       | 정체성. 위치 그대로                                                                       |
| LP · 카세트 본체 누름             | **유지(문맥)** | 음악 보관함을 **지금 재생 중인 목록**으로 연다. 데크 키(▶)와 누름 영역을 겹치지 않게(§8)  |
| PLAYLISTS 카드 · "모든 목록 보기" | **제거**       | NOW PLAYLIST 로 바뀐다. 목록 고르기는 "목록 바꾸기 ▾", 관리는 "보관함에서 이 목록 편집 ↗" |
| 카드의 "＋ 새 목록"               | **이동**       | 보관함 목록 칸의 "＋ 새 목록" 하나만. 빈 상태 대시보드에만 "＋ 새 목록 만들고 링크 추가"  |
| Moments "모두 보기 (n)"           | **유지(문맥)** | 보관함 Moments 탭을 연다                                                                  |

결과: 음악 보관함 입구 5 → **3**(헤더 · 데크 · "이 목록 편집"), Moments 입구 3 → **2**(헤더 → 탭 · "모두 보기"). 셋 다 서로 다른
출발점에서 같은 화면의 **다른 자리**로 간다.

## 5. NOW PLAYLIST 위젯 [제안]

### 5-1. 세 개념을 나눈다

| 개념                       | 어디에 있나 (지금)                                               | 저장             | 이 위젯에서의 역할                                                         |
| -------------------------- | ---------------------------------------------------------------- | ---------------- | -------------------------------------------------------------------------- |
| **재생 큐**                | `playback.queue` — 재생을 시작할 때 목록의 **스냅샷** [코드]     | 메모리           | **보여 주는 것** (있으면 늘)                                               |
| **큐의 출처 목록**         | **없다** — 큐는 `Track[]` 뿐, 어느 목록에서 왔는지 모른다 [코드] | —                | 위젯 제목. **새로 기록해야 한다**(메모리만, 저장 안 함)                    |
| **고른 목록**              | `library.selectedPlaylistId` — 보관함에서 보고 있는 목록 [코드]  | 저장(라이브러리) | 큐가 **비었을 때만** "재생 대기" 로 보여 준다. 큐가 있으면 한 줄로만 알림  |
| **마지막으로 재생한 목록** | 없다                                                             | —                | **두지 않는다**(권고). 새로고침 뒤에는 큐가 비므로 고른 목록이 "재생 대기" |

"마지막 재생 목록" 을 기억하려면 저장 키를 더하거나 라이브러리 스키마에 필드를 넣어야 한다 — **이번 범위 밖, 승인 필요**(§12 #2b).

### 5-2. 상태별 표시

| 상태                                 | 머리말                                                                         | 줄                                     | 아래                                                     |
| ------------------------------------ | ------------------------------------------------------------------------------ | -------------------------------------- | -------------------------------------------------------- |
| 재생 중 · 일시정지                   | `NOW PLAYLIST · 재생 중` / 출처 목록 이름 / `2 / 4곡`                          | 큐의 곡. 지금 곡 강조 + "♪ 재생 중" 글 | "보관함에서 이 목록 편집 ↗"                              |
| 큐 ≠ 고른 목록                       | 위와 같고 한 줄 더: `보관함에서 보는 목록: MY RECORDS`                         | 큐의 곡 (고른 목록은 보이지 않음)      | 같음                                                     |
| 출처 목록이 바뀜(순서 · 추가 · 삭제) | 안내: "보관함에서 이 목록이 바뀌었어요. 지금은 시작할 때의 순서로 이어집니다." | 큐의 곡 (옛 순서)                      | **[새 순서로 이어 재생]** — 지금 곡 · 시점은 그대로      |
| 출처 목록이 지워짐                   | 안내: "이 목록은 지워졌어요. 지금 큐는 끝까지 재생할 수 있어요."               | 큐의 곡                                | "보관함 열기"                                            |
| Moment 재생으로 목록 밖 영상 하나    | `목록 밖 영상`                                                                 | 그 한 곡                               | "보관함 열기"                                            |
| 큐 없음 (첫 방문 · 새로고침 뒤)      | `NOW PLAYLIST · 재생 대기` / 고른 목록 이름                                    | 고른 목록의 곡 — 누르면 그 곡부터 재생 | **[▶ 처음부터 재생]** · "보관함에서 편집 ↗"              |
| 목록이 하나도 없음                   | "재생할 목록이 아직 없어요"                                                    | —                                      | **[＋ 새 목록 만들고 링크 추가]** (보관함 링크 입력으로) |
| 고른 목록이 비어 있음                | 고른 목록 이름                                                                 | "이 목록은 비어 있어요…"               | 보관함으로                                               |

- **줄을 누르면 그 곡을 재생한다.** 큐 안에서는 **큐 안의 자리로 옮긴다**(스냅샷을 다시 뜨지 않는다 — 들리는 순서와 보이는 순서가
  같게). 대기 상태에서는 그 목록을 큐로 만들고 그 곡부터.
- **목록 바꾸기 ▾**: 목록 이름 · 곡 수 · "지금 재생 중" 표시, 8개를 넘으면 이름 찾기. 고르면 **그 목록을 처음부터 재생**한다 — 이
  위젯은 "듣는 것" 이라 "고르기만" 은 두지 않는다(그것은 보관함의 일).
  - ⚠ **위젯 밖으로 띄우는 팝오버는 플레이어를 덮을 수 있다**(701–1100px 배치에서 NOW PLAYLIST 아래가 영상). 가시성 측정은 우리
    UI 가 덮은 것을 알지 못하므로(`playerVisibility.ts`) 구현에서는 **위젯 안에서 펼치는 목록**(아래로 밀어내기)으로 한다. 시안의
    팝오버는 비교용이다.
- 긴 제목: 두 줄까지, 넘으면 말줄임(제목 전체는 `title`/낭독기 이름). 번호는 고정폭.
- 곡이 많을 때: 데스크톱은 **고정 높이 안쪽 스크롤**(260–340px), 지금 곡을 칸 안에서만 보이게 맞춤(페이지는 움직이지 않음), 위아래
  흐림 + "아래에 n개 더" 글로 더 있음을 알림, `overscroll-behavior: contain`. **모바일(≤700px)은 안쪽 스크롤을 쓰지 않는다** —
  지금 곡 주변 5곡 + "전체 n곡 펼치기"(M11-3 U19 의 교훈).
- 관리(이름 바꾸기 · 삭제 · 정렬)는 넣지 않는다.

### 5-3. 보관함 쪽 표시

- **고른 목록 = 행 강조(테두리 · 배경)**, **재생 중인 목록 = "♪ 재생 중인 목록" 글**. 짐작이 아니라 큐의 출처로 정한다 — 같은 곡이
  여러 목록에 있어도 하나만 표시된다.

## 6. 음악 보관함 [제안]

### 6-1. 데스크톱 — 2열

| 왼쪽 (목록, 0.8fr · 최소 200px)                          | 오른쪽 (상세, 1.6fr)                                                                  |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 머리말 "플레이리스트 n" · **＋ 새 목록**                 | 고른 목록 이름 · `n곡 · ♪ 지금 재생 중인 목록`                                        |
| 8개 넘으면 **이름 찾기**                                 | **▶ 전체 재생** · **＋ 링크 추가** · (편집 — 정렬 방식에 따라)                        |
| 행 = 고르기 · 곡 수 · 재생 중 글                         | 링크 추가 양식 — **추가 뒤에도 칸이 남고 포커스가 돌아온다**(지금의 연속 추가 그대로) |
| 행 끝 **⋯** → 이름 바꾸기 · 목록 삭제…(행 아래에서 확인) | 곡 줄 (§9)                                                                            |
| **각자 스크롤** — 목록이 50개여도 오른쪽은 그대로        | **각자 스크롤**, 머리말은 고정                                                        |

- 새 목록 → 이름 → **만들고 링크 추가** → 오른쪽 링크 입력에 포커스(지금의 U15 흐름 유지).
- 목록 3 · 10 · 30 · 50개, 곡 1 · 10 · 30 · 100곡을 시안에서 바꿔 볼 수 있다(데이터 양). 30개 이상에서도 페이지 번호 · 가상 스크롤은
  필요 없다(행 48px × 50 = 2,400px, 안쪽 스크롤). 곡 100개도 같은 판단(M11-4 의 5,000개 Moments 측정 근거).
- 낮은 데스크톱(높이 620): 보관함 높이 = 화면 − 180, 두 칸 모두 안쪽 스크롤. 머리말이 두 줄이 되면 단추가 줄바꿈된다(시안 확인).

### 6-2. 모바일 — 두 단계

1. **목록** — 영상 아래 시트(지금의 쌓기 배치 그대로), 목록 · ＋ 새 목록 · 찾기 · ⋯.
2. **상세** — 위에 **‹ 목록** 단추와 `보관함 › 음악 › 목록 이름` 위치 표시. 고르면 상세로, ‹ 로 돌아온다.

낮은 가로 화면(844×390)은 지금의 옆 배치(영상 왼쪽 · 보관함 오른쪽)에서 같은 두 단계를 쓴다.

## 8. 데크 (LP · 카세트) [제안]

- 본체 누름 = **음악 보관함을 재생 중인 목록으로** 연다. 아트의 재생 키(LP ▶ · 카세트 STOP/PLAY) = 재생 · 일시정지.
- 지금도 키는 열기 영역보다 위에 쌓인다 [코드: `DeckWidget.vue` "열기 버튼보다 뒤에 둔다"]. LP 의 START/STOP 키 상자가 열기 원의 모서리와
  겹친다는 기록이 있다 → 구현에서 **열기 영역을 원판 안쪽으로 줄이고**(키의 44px 바깥 띠와 겹치지 않게) 시안의 "데크 누름 영역 보기" 로
  확인한 모양을 기준으로 한다.
- 데크 아래 문구에 두 동작을 함께 적는다: "LP를 누르면 음악 보관함이 열려요 · 아래 키 = 재생".
- 중복 평가: 데크 키 ▶ 와 영상 아래 ▶ 가 같은 일을 한다. 데크 키는 **정체성 장치**(M6-6 사용자 요청으로 살렸다)라 남기고, 주 조작은
  영상 아래 트랜스포트로 둔다.
- 대안: 데크 본체 = 재생/일시정지, 보관함은 헤더로만 — 입구가 하나 줄지만 M7 이후 굳은 "LP 를 누르면 보관함" 을 바꾼다(§12 #8).

## 9. Moment 저장 — A · B 비교 [제안 — 사용자가 고른다]

시안 **3 Moment 저장 A/B** 에서 두 모델을 나란히 눌러 볼 수 있다(저장소 쓰기가 일어나는 순간이 기록에 남는다).

| 기준                | A 바로 저장 + 메모 자동 열림                | B 시점 잡기 + 최종 저장                                       |
| ------------------- | ------------------------------------------- | ------------------------------------------------------------- |
| 시점 정확성         | 누른 순간                                   | 누른 순간(저장을 늦게 눌러도 잡은 시점)                       |
| 상태의 명확성       | "저장됨" 인데 메모 칸이 열림 — U1 이 그대로 | 점선 카드 = 저장 안 됨 · ✓ = 저장됨                           |
| 메모 없이           | **1번**                                     | 2번 (잡기 → 저장)                                             |
| 메모와 함께         | 2번 + 입력                                  | 2번 + 입력(Enter = 저장)                                      |
| 취소                | 메모만 취소, Moment 는 남음                 | 아무것도 남지 않음                                            |
| 잘못 누름           | 데이터가 생김 → 보관함에서 지움             | 취소 1번, 두어도 저장 안 됨                                   |
| 연속 저장           | **1번씩**                                   | 2번씩                                                         |
| 저장 실패 · 다른 탭 | Moment 가 생기지 않고 메모 칸도 없음        | 카드 · 메모가 남아 다시 저장                                  |
| 잊어버림            | 이미 저장됨                                 | 저장 안 됨 — 곡이 바뀌어도 카드가 남아 "아직 저장 안 됨" 표시 |
| 확장 패널과 일관성  | 다름                                        | **같음** (ADR 0028 결정 15)                                   |
| 모바일              | 저장 직후 키보드가 영상을 가릴 수 있음      | 같은 문제 — 메모 칸은 자동 포커스하지 않음                    |

**권고: B.** U1 의 혼란이 "지금이 저장 전인지 후인지" 이므로 상태를 둘(잡음 · 저장됨)로 나누는 B 가 직접 답한다. 확장 패널과 같은 흐름이
된다. 대가는 메모 없는 저장이 1번 → 2번. B 에서 잡은 상태로 캡처 단추를 다시 누르면 **시점을 다시 잡는다**(저장하지 않는다).

## 10. 트랙 편집 [제안]

시안 **4 트랙 정렬** 에서 셋을 직접 끌어 볼 수 있다(마우스 · 터치 · 키보드).

| 기준               | A 핸들 + ⋯ 메뉴                | B 편집 모드            | **C 혼합 (추천)**                                       |
| ------------------ | ------------------------------ | ---------------------- | ------------------------------------------------------- |
| 5칸 올리기         | 끌기 1번                       | 편집 · 끌기 · 완료 3번 | 데스크톱 1번 · 모바일 3번                               |
| 맨 위로            | ⋯ → 맨 위로 2번                | 편집 · 끌기 · 완료     | ⋯ → 맨 위로 2번                                         |
| 발견 가능성        | ≡ 가 늘 보임                   | "편집" 글자            | 데스크톱 ≡ · 모바일 "편집"                              |
| 긴 제목            | 핸들 · ▶ · ⋯ 가 폭을 씀        | 평소 넓음              | 데스크톱 A · 모바일 B                                   |
| 터치 · 스크롤 충돌 | 핸들 밖은 스크롤 · 오조작 위험 | 편집 중에만 끌기       | 편집 중에만 끌기                                        |
| 실수로 삭제        | 메뉴 → 확인                    | ✕ → 확인               | 같음                                                    |
| 키보드 · 낭독기    | ≡ Space+화살표 · ⋯             | ↑ ↓ 단추               | ≡ Space+화살표 · ⋯ 메뉴 · 편집 ↑ ↓ — 결과를 소리로 알림 |

- 지금(M11-6)은 관리 → 위로 × 5 = 6번.
- **끌기 중 재생 변경 방지**: 끌기는 ≡ 에서만 시작(`touch-action: none` 은 핸들에만), ▶ 와 떨어져 있다. 놓을 때 **한 번만** 저장하고, 끄는
  동안 큐 · 재생은 그대로(큐는 스냅샷이므로 원래 흔들리지 않는다 — 대신 §5-2 의 "바뀌었어요" 안내).
- **여러 탭**: 놓을 때 `moveTrackTo(목록, 곡, n)` 한 번 — 지금의 탭 간 잠금 · 개정 번호 확인을 그대로 지난다. 다른 탭이 먼저 바꿨으면 지금처럼
  거절하고 새로 읽는다. 저장 형식은 같다(배열 순서).
- **라이브러리 검토 (AGENTS 규칙 8)**: 의존성은 `vue` · `pinia` 뿐이다. 후보 — (1) **직접 구현**(Pointer Events + 핸들, 시안의 약 80줄과 같은
  방식), (2) SortableJS(~45KB, 터치 지원이 성숙하지만 DOM 을 직접 옮겨 Vue 렌더링과 다투고 래퍼가 필요), (3) HTML5 DnD(터치 미지원). 행이
  고정 높이 · 한 목록 안 이동뿐이므로 **(1) 을 권한다.** 자동 스크롤 · iOS 롱프레스 충돌이 실기기에서 문제가 되면 (2) 를 다시 본다.

### 11-3. 데이터 · 상태 안정성

- **저장 키 · 백업 스키마**: 그대로. 새 상태(`queueSource`)는 메모리뿐, `moveTrackTo` 는 배열 순서만 바꾼다.
- **Web Locks · 개정 번호**: 새 쓰기(`moveTrackTo`)도 기존 쓰기 관문을 지난다. 끌기 중에는 쓰지 않고 놓을 때 한 번.
- **고른 목록 ≠ 재생 큐**: 위 §5. 확장의 D4 결정(확장이 만든 목록은 선택 · 큐를 바꾸지 않음)과 충돌 없음.
- **순서 변경 뒤 재생 위치**: 큐는 그대로, "새 순서로 이어 재생" 은 지금 곡 id 의 새 위치로 옮기고 시점을 유지한다. 지금 곡이 목록에서
  지워졌으면 지금처럼 멈추고 알린다(`trackRemoved`).
- **같은 videoId 의 다른 제목(P12)**: 권고 — 대시보드 "이 곡" 은 **지금 큐의 곡 제목**, 보관함 Moments 그룹은 **큐 출처 목록 → 고른 목록 →
  라이브러리 순**으로 보고 첫 제목, 다른 제목이 더 있으면 "다른 이름 n개" 를 덧붙인다. 저장 스냅샷은 그대로 둔다(§12 #9).
- **새로고침 · 여러 탭**: 큐는 탭마다 메모리라 새로고침하면 비고, NOW PLAYLIST 는 "재생 대기" 가 된다. 다른 탭이 목록을 바꾸면 지금처럼
  storage 이벤트로 라이브러리가 갱신되고 §5-2 의 "바뀌었어요" 안내가 뜬다.
- **테마 전환**: 위젯 · 플레이어 인스턴스 그대로(ADR 0001 · 0002). 시안에서 테마를 바꿔도 재생 상태 유지 확인.

### 11-4. 확장 프로그램 영향

- 저장 계약(`bridge/call` 의 `library/list` · `track/add` · `playlist/create-and-add` · `moment/add`)과 데이터 모델은 **바뀌지 않는다**.
  웹앱 보관함이 2열이 돼도 브리지는 store 를 쓰므로 화면과 무관하다.
- Moment B 모델을 고르면 웹앱과 확장 패널의 흐름이 같아진다(문구 통일만 필요). A 를 고르면 지금처럼 다르다.
- 패널의 "39page 에서 보기" 류 링크가 생기면 보관함 탭 기억과 맞춰야 한다 — 지금은 없다.
- **이번 단계에서 `extension/` 은 바꾸지 않았다.**

  맞춘다(`ResizeObserver` — 페이지는 움직이지 않는다).
- **NOW PLAYLIST 와 Moments 위젯**: 서로 모른다. 둘 다 코디네이터 계약(`nowPlaying` · `queue`)만 읽는다. "이 곡" 은 `nowPlaying.videoId`.
- **트랙 편집**: 적용 위치는 보관함 상세 칸의 `TrackList`(지금 "관리 → 위로/아래로"). 상세 칸은 머리말 고정 · `.editor-body` 한 곳
  스크롤이므로 끌기의 자동 스크롤은 그 요소를 기준으로 한다. 순서를 바꾸면 NOW PLAYLIST 가 "목록이 변경됐어요" 를 띄운다 —
  `moveTrackTo` 를 더해도 그대로 동작한다(견주기는 순서 전체).
- **스크롤 · 포커스 제약**: 음악 탭 본문은 스크롤하지 않는다(두 칸 각자). 입력란 포커스는 `preventScroll`. 좁은 보관함의 단계 전환은
  포커스가 숨은 요소에 남을 때만 옮긴다.
- **남은 Proposed**: Moments 위젯 "이 곡 전체", 마지막 재생 목록 기억, 데크 본체 누름, 같은 영상의 다른 제목.
