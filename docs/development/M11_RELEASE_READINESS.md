  개인 키는 저장소에 없고 필요 없다(압축해제 설치는 공개 키만 쓴다). 참고: CDP 로 올린 압축해제 확장은 Chrome 을 다시 켜면
  돌아오지 않았다(시험 방식의 성질) — 사람이 `chrome://extensions` 로 올린 경우의 재시작 유지는 §8 에서 본다.
- 운영 빌드에는 `key` 를 넣지 않는다 — 검사기가 막는다. 운영 웹앱 빌드에 개발 ID 를 넣으면 **빌드가 멈춘다**(D5).

### 6-2. 정식 ID 확보 — 미공개 업로드 [문서 · 실행하지 않음]

- Chrome 공식 절차: 확장 ZIP 을 개발자 대시보드에 **올리되 게시하지 않는다** → Package 탭의 "View public key" 로 공개 키를 얻는다 →
  그 키를 개발 manifest 의 `key` 로 쓰면 로컬 압축해제 설치가 **스토어 ID 와 같은 ID** 가 된다.
- 공개 범위: Public · **Unlisted**(목록 없음, 주소를 아는 사람만) · **Private**(지정한 테스터 · Google 그룹). 모두 같은 정책 · 같은
  심사를 거친다. 시험판은 이름에 "BETA" 등을 붙이라고 한다.
- 필요: 개발자 계정(등록 수수료), Listing · Privacy 탭 작성. 초안 업로드 시점에 ID 가 정해지는지는 공식 문서에 적혀 있지 않다(TODO —
  실제 업로드 때 확인).
- 연계: 정식 ID 를 얻으면 (1) 개발 manifest 의 `key` 를 그 공개 키로 바꿀지 결정, (2) 운영 웹앱 빌드 변수에 정식 ID, (3) 개발 ID 는
  시험 빌드에만 남긴다.

### 6-3. 운영 활성화에 필요한 설정 (배포하지 않았다)

| 설정                         | 값 · 확인                                                                                                                                                                                                                  |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `VITE_BRIDGE_EXTENSION_IDS`  | Workers Builds 빌드 변수. 정식 ID(a–p 32자) 쉼표. 형식이 틀리면 빌드 실패, 비면 브리지 꺼짐                                                                                                                                |
| `VITE_BRIDGE_DEV_BUILD`      | 운영에서는 **두지 않는다** — 두지 않으면 개발 ID 가 섞인 빌드가 실패한다                                                                                                                                                   |
| `dist/_headers` (자동)       | `/bridge.html` · `/bridge` 에 `Content-Security-Policy: frame-ancestors chrome-extension://<ID>` (없으면 `'none'`) · `nosniff` · `no-referrer`                                                                             |
| Cloudflare Workers 정적 자원 | 이 프로젝트는 Worker 코드가 없는 정적 자원 전용(`wrangler.toml` 에 `main` 없음) → 공식 문서상 `_headers` 가 적용된다 [문서]. **실제 응답 헤더는 배포 뒤에만 확인 가능** — 로컬 `vite preview` 는 `_headers` 를 읽지 않는다 |
| 경로                         | Workers 정적 자원의 기본 `html_handling` 이 `/bridge.html` 을 `/bridge` 로 옮길 수 있어 두 경로 모두에 헤더를 둔다 (배포 뒤 확인)                                                                                          |
| 확장 manifest                | `optional_host_permissions: ["https://39page.com/*"]` — 웹앱 허용 ID 와 확장 ID 가 같아야 한다 (스토어 ID)                                                                                                                 |
| 설정이 빠지면                | 브리지는 `refused` 신호만 → 패널이 "아직 바로 저장을 받지 않아요" + 수집 화면 [실측: 빈 허용 목록 · 다른 ID 에서 `not-allowed`]                                                                                            |

M10 과 M11 웹앱이 동시에 열려 있을 때: 저장 키 · 스키마 · 백업 형식 · 탭 간 잠금 규약(ADR 0025)이 같다. 확장이 만든 항목 id
(`ext-…`)는 문자열일 뿐이라 M10 코드도 그대로 읽는다. 옛 탭은 새로고침 전까지 옛 화면이다 — 데이터는 같은 규칙으로 보호된다.

### 6-4. Chrome 116

Chrome for Testing 116.0.5845.96 을 받아 확장을 명령줄로 올렸다(116 에는 CDP `Extensions.loadUnpacked` · `triggerAction` 이 없다).
`results/2026-11-12-m11-6-chrome116.json`.

- **확인**: 확장이 올라가고 서비스 워커가 고정 ID 로 돈다. 권한이 없을 때 브리지 요청은 `unavailable · permission` 으로 거절된다.
  권한 프롬프트가 뜨고 닫힌다(거부 → `false`).
- **미확인**: 116 의 권한 프롬프트 단추는 UI Automation 에 보이지 않았고, OS 키 입력(Enter → 거부로 닫힘, Tab+Enter → 닫히지
  않음)으로 "허용" 을 누르지 못했다. 그래서 **116 에서 권한 허용 뒤의 저장 · 패널 표시는 확인하지 못했다**. manifest 의 최소
  버전(116)은 유지하되 사람 확인(§8 H13) 전까지 116–126 지원은 "설계상" 이다.

## 7. 운영 배포 절차 (실행하지 않음)

1. **백업 안내** — 배포 전 사용자에게 "⇩ 데이터 → JSON 백업 내보내기" 를 권한다(2조작). 저장 키 · 스키마는 바뀌지 않지만 되돌림 대비.
2. **빌드 변수** — 웹앱만 먼저: `VITE_BRIDGE_EXTENSION_IDS` 를 **비운 채** 배포(브리지 꺼짐, `_headers` 는 `'none'`).
3. **Workers Builds** — `main` 푸시 = 배포(DEPLOYMENT.md). `dist/_headers` 가 산출물에 있는지 빌드 로그에서 확인.
4. **순서** — 웹앱 M11 → (스토어 ID 확정 뒤) 웹앱 빌드 변수에 ID → 재배포 → 확장 게시.
5. **열린 옛 탭** — 새 버전은 새로고침 뒤 적용. 옛 탭과 새 탭이 함께 있어도 같은 잠금 · 영수증 규칙이라 조용한 덮어쓰기는 없다. 화면
   차이는 새로고침으로 해결.
6. **허용 ID** — 스토어 ID 를 빌드 변수에, 개발 ID 는 넣지 않는다(넣으면 빌드 실패).
7. **HTTPS Smoke Test** — `https://39page.com/` 대시보드 · 곡 추가 · 재생 · Moment · 백업 내보내기 / `curl -I https://39page.com/bridge.html`
   (그리고 `/bridge`)의 `Content-Security-Policy` 헤더 / 브리지를 켠 뒤에는 정식 확장으로 패널 담기 1회.
8. **롤백** — Workers 대시보드에서 직전 배포(M10)로 되돌린다. 데이터 형식이 같아 데이터 이동이 필요 없다. 확장이 만든 `ext-…` 항목은
   M10 에서도 보이고 지울 수 있다. 브리지만 끄려면 빌드 변수를 비우고 재배포.

> 실제 사용자 프로필과 39page 데이터가 있는 브라우저에서는 **가져오기 · 삭제 시험을 하지 말 것**. 새 Chrome 프로필(사용자 추가)에서 한다.
