# Chrome 확장 출시 준비 (M10-6)

39page 확장(`extension/`)을 Chrome 웹 스토어에 올리기 전에 할 일과 순서. **게시 · 운영 배포 ·
개발자 계정 등록과 결제는 사용자가 한다** — 이 문서는 준비물과 확인 방법을 적는다.

- 설계: [`../architecture/EXTENSION_DESIGN.md`](../architecture/EXTENSION_DESIGN.md)
- 스토어 등록 초안: [`../product/EXTENSION_STORE_LISTING.md`](../product/EXTENSION_STORE_LISTING.md)
- 개인정보처리방침 초안: [`../product/EXTENSION_PRIVACY.md`](../product/EXTENSION_PRIVACY.md)
- 사용 안내: [`../product/EXTENSION_USER_GUIDE.md`](../product/EXTENSION_USER_GUIDE.md)

## 1. 출시 순서 — 웹앱이 먼저다

확장은 `https://39page.com/#collect?…` 를 연다. 운영 웹앱에 수집 화면이 없으면 확장이 연 탭은
대시보드만 보여 주고 아무것도 담지 못한다. 그래서 **반드시 이 순서**로 한다.

| 순서 | 할 일                          | 누가   | 확인                                                                                                                                                                                    |
| ---- | ------------------------------ | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 웹앱(M10 브랜치)을 운영에 배포 | 사용자 | `DEPLOYMENT.md` 의 배포 절차와 검증 체크리스트. `main` 병합 · 푸시는 사용자가 결정한다                                                                                                  |
| 2    | 운영 수집 화면 확인            | 사용자 | 아래 §2 의 주소를 운영에서 열어 본다 — 화면만 열리고 저장되지 않아야 한다                                                                                                               |
| 3    | 확장의 운영 origin 확인        | 사용자 | 출시 ZIP 을 압축 해제해 "압축해제된 확장 프로그램 로드" 로 설치 → YouTube 영상에서 "플레이리스트에 추가" → `https://39page.com/#collect?v=1&kind=track…` 탭이 열리고 수집 화면이 보인다 |
| 4    | Chrome 웹 스토어에 제출        | 사용자 | 개발자 대시보드 · 등록비 · 아래 §4 의 준비물                                                                                                                                            |
| 5    | 승인 뒤 게시                   | 사용자 | 스토어 설치본으로 3 을 다시 한다                                                                                                                                                        |

**1 전에 확장을 게시하지 않는다.** 1 과 4 사이에 웹앱을 되돌리면(롤백) 확장이 연 탭이 수집
화면을 못 찾는다 — 그때는 게시를 미룬다.

### 이 버전을 배포할 때 알아 둘 것 (M10-3 안정화)

배포 직전에 열려 있던 39page 탭(이전 버전)은 **새로 고치기 전까지** 탭 간 쓰기 잠금 규약 밖이다
(ADR 0025 "한계"). 배포 뒤에는 열어 둔 39page 탭을 새로 고치라고 안내한다.

## 2. 운영 수집 화면 확인 (순서 2)

배포 뒤 브라우저에서 아래를 연다. **열기만 하고 아무것도 누르지 않는다.**

```
https://39page.com/#collect?v=1&kind=track&videoId=jNQXAC9IVRw&title=Me+at+the+zoo&req=releasecheck000001
https://39page.com/#collect?v=1&kind=moment&videoId=jNQXAC9IVRw&atSeconds=5&title=Me+at+the+zoo&req=releasecheck000002
https://39page.com/#collect?v=1&kind=moment&videoId=jNQXAC9IVRw&atSeconds=5&note=x&req=releasecheck000003
```

| 주소             | 기대                                                                             |
| ---------------- | -------------------------------------------------------------------------------- |
| 첫째 (곡)        | "담을 영상" · 플레이리스트 고르기 · "플레이리스트에 추가" 버튼. 저장은 아직 없음 |
| 둘째 (Moment)    | "저장할 순간" · "0:05 지점" · 메모 입력란 · "Moment 저장". 저장은 아직 없음      |
| 셋째 (메모 실음) | "이 수집 요청은 열 수 없습니다" — 메모는 주소로 받지 않는다                      |

대시보드(`https://39page.com/`)의 라이브러리와 Moments 가 그대로인지 함께 본다.

## 3. 패키지 만들기

```sh
cd extension
npm run package
```

`npm run build`(타입 검사 · 운영 빌드 · manifest 검사) 뒤 `scripts/package.mjs` 가

- `dist/` 를 검사한다 — 허용한 파일만(manifest · background · content · popup · assets · icons),
  소스맵 없음, `localhost` · `127.0.0.1` · `dist-dev` 없음, `eval` · `new Function` 없음,
  예상하지 못한 외부 주소 없음, manifest 와 `package.json` 버전 일치
- `release/39page-extension-<버전>.zip` 과 `.sha256` 을 만든다 — 항목은 경로 순, 시각은
  1980-01-01 고정이라 **같은 dist 면 같은 해시**다 (재현 가능)
- 만든 ZIP 을 다시 읽어 항목 · 내용이 `dist/` 와 같은지 확인한다. 어긋나면 ZIP 을 남기지 않는다

`release/` 는 저장소에 넣지 않는다 (`extension/.gitignore`). 의존성을 더하지 않았다 — Node 의
`zlib`(deflate · crc32)로 ZIP 을 직접 쓴다.

**M10-6 기록 (2026-11-11)**: `39page-extension-1.0.0.zip` — 11개 파일 · SHA-256
`3421a9ae95c8891ba42464bcf84fa7112547d38947a8694effa05f768837fb75`. 시스템 `unzip -t` 오류 없음. 두 번
만들어 같은 해시. 소스맵 · 개발 주소를 일부러 넣으면 거절했다. (통합 시나리오 16단계는 그 직전 패키지
`cfd2c1cd…` 로 했다 — 둘의 차이는 Prettier 가 고친 `manifest.json` 의 공백뿐이고 내용은 같다.)

### 버전 정책

`manifest.json` 과 `package.json` 의 `version` 을 같이 올린다 (패키지 스크립트가 다르면 멈춘다).
스토어는 같은 버전을 두 번 받지 않는다. 동작이 바뀌면 둘째 자리, 문구 · 고침이면 셋째 자리.

## 5. 보안 · 개인정보 검토 (M10-6)

공식 문서로 확인한 기준: Chrome 웹 스토어 프로그램 정책(단일 목적 · 최소 권한 · MV3 원격 코드 ·
사용자 데이터 · 제한적 사용), activeTab 문서(단축키 실행도 activeTab 을 준다), scripting 문서
(`world` 는 Chrome 95+).

| 항목               | 결과                                                                                                                                              |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 권한               | `activeTab` · `scripting` 뿐. 호스트 권한 · 상시 content script · `externally_connectable` · `web_accessible_resources` 없음 (검사기가 막는다)    |
| 단일 목적          | "YouTube 에서 보고 있는 영상과 시점을 39page 로 담기" — 두 동작 모두 이 목적                                                                      |
| 원격 코드          | 없음 — 모든 로직이 패키지 안. 번들에 `eval` · `new Function` 없음 (패키지 스크립트가 확인). 확장 페이지 CSP 는 기본값                             |
| 페이지 접근        | 사용자가 아이콘 · 단축키를 누른 그 탭만. 메인 세계 실행은 읽기만 하고 반환값을 다시 검증한다                                                      |
| 메시지             | 모든 수신 지점이 한 검증 함수를 쓴다. Background 는 우리 확장 페이지가 보낸 것만 받는다                                                           |
| 데이터 흐름        | 탭 주소 · 플레이어 제목 · 재생 시점 → 39page 수집 주소의 **조각(`#`)** — 서버로 가지 않는다. 39page 는 그 브라우저의 `localStorage` 에만 저장     |
| 확장의 저장        | 없음 — `storage` 권한 없음. 5초 중복 기록만 워커 메모리에                                                                                         |
| 외부 요청          | 확장은 네트워크 요청을 하지 않는다                                                                                                                |
| 위조된 수집 주소   | 다른 사이트가 만든 링크도 저장하려면 사용자가 눌러야 한다. 메모는 주소로 받지 않는다. 제목은 길이 · 제어 · 양방향 문자를 검사하고 글자로만 그린다 |
| 의존성 취약점      | `npm audit --omit=dev` — 웹앱 · 확장 모두 **0건**. 개발 도구에만 중간 13건(glob · minimatch, 배포물에 없음) — 강제 업그레이드하지 않았다          |
| 사용자 데이터 정책 | 탭 주소 · 제목을 **사용자가 누른 기능에만** 쓴다(웹 탐색 활동 예외 조건). 개인정보처리방침 게시가 필요하다 (TODO)                                 |

## 6. 브라우저 확인 범위

| 환경                                    | 확인                                                                                         |
| --------------------------------------- | -------------------------------------------------------------------------------------------- |
| Chromium 155 헤드리스 (이 기기, Termux) | ✔ 압축해제 설치 · 개발 빌드 · 운영 ZIP — 통합 시나리오 16단계 (아래 §7)                      |
| Google Chrome 안정판 (데스크톱)         | ✖ 확인하지 못함 — 이 기기에서 설치할 수 없다. **제출 전 사용자가 데스크톱에서 §1-3 을 한다** |
| 사람이 직접 누르는 툴바 · 단축키        | ✖ 확인하지 못함 — CDP 로 대신. 헤드리스는 단축키 키 입력을 처리하지 않는다                   |
| Android Chrome                          | 해당 없음 — Android Chrome 은 확장을 지원하지 않는다. 39page 웹앱만 쓴다                     |
| 실기기 · 다른 OS                        | ✖ 확인하지 못함                                                                              |

헤드리스 Chromium 은 **흉내가 아니라 실제 Chromium** 이지만 화면 · 입력 장치 · 일부 단축키 처리가
데스크톱 Chrome 과 다르다. 실기기 확인은 사용자가 한다.

## 7. 통합 시나리오 (M10-6)

Chromium 155 헤드리스 · 격리 프로필 · 실제 YouTube. 1–15 는 **개발 빌드** 확장(수집 origin
`http://127.0.0.1:4173`)과 이 브랜치 웹앱 빌드, 16 은 **출시 ZIP 을 풀어 설치**한 별도 브라우저(39page.com
을 127.0.0.1 로 돌려 운영 서버에 요청하지 않음). 누르는 자리는 실제 마우스, 메모는 실제 키 입력.

## 8. 되돌리기

- 스토어 게시 뒤 문제가 생기면 대시보드에서 게시를 중지(비공개)한다. 이미 설치한 사람의 확장은
  그대로 남으므로, 고친 버전을 올려 자동 업데이트로 바꾼다.
- 확장은 데이터를 갖지 않는다. 사용자의 라이브러리 · Moments 는 39page 의 `localStorage` 에 있고
  백업(JSON 내보내기)으로 지킨다.
