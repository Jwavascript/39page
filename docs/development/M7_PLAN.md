## 1. 2번은 내 버그였다

가로에서 드로어를 열면 **스테이지가 아래로 밀리고 드로어가 위쪽에 별도 공간을
차지했다.** 겹치게 만든 M6-2 의 의도와 정반대다.

원인은 CSS Grid 의 자동 배치다.

```css
/* M6-2 — 드로어만 셀을 명시했다 */
.workspace.is-drawer-open > :last-child {
  grid-area: 1 / 1;
}
```

자동 배치 알고리즘은 **명시적으로 배치된 아이템을 먼저 놓고**, 자동 아이템은
이미 찬 셀을 **건너뛴다.** 드로어가 1행 1열을 차지하면 스테이지(`WidgetHost`)는
DOM 에서 먼저 있어도 2행으로 내려간다.

수정은 스테이지에도 같은 셀을 명시하는 것이다.

```css
.workspace.is-drawer-open > :first-child,
.workspace.is-drawer-open > :last-child {
  grid-area: 1 / 1;
}
```

**단위 테스트가 잡지 못했다.** jsdom 은 레이아웃을 계산하지 않아 그리드 배치를
확인할 수 없고, 내가 쓴 테스트는 CSS **텍스트**만 단정했다. 텍스트 단정은
"이 규칙이 있다" 를 보장하지만 "그 규칙이 의도한 결과를 낸다" 는 보장하지
않는다. 지금은 두 선택자가 **함께** 같은 셀을 쓰는 것을 정규식으로 고정했다 —
여전히 텍스트 단정이지만, 빠뜨리면 깨진다.

> 교훈: 레이아웃 보장을 CSS 텍스트로 고정할 때는 **보장을 성립시키는 모든
> 조각**을 함께 단정해야 한다. 한 조각만 단정하면 다른 조각이 없어도 통과한다.

## 2. 표면과 트리거를 다시 나눴다 (1번, 5번)

| 조작                 | M6-4·5               | M7                                |
| -------------------- | -------------------- | --------------------------------- |
| 데크(LP·카세트) 누름 | 트랙 드로어 열기     | **플레이리스트 위젯 펼치기/접기** |
| 타일 본문 누름       | 그 목록 전체 재생    | **그 목록의 트랙 편집 열기**      |
| 타일 `⋯`             | 트랙 편집 열기       | 없어짐                            |
| 타일 `▶`(우측 상단)  | 없음                 | **그 목록 전체 재생**             |
| 길게 누르기          | 편집 열기(추가 경로) | 없어짐 — 본문 한 번 누름으로 충분 |

재생 경로는 줄지 않았다: 타일의 `▶`, 드로어의 `▶ 목록 전체 재생`, 트랙별 `▶`,
데크의 트랜스포트 `▶`. 넷이다.

**실수 재생이 사라진 것이 덤이다.** M6-4 에서는 타일을 누르면 바로 소리가 났고,
그래서 목록을 들여다보려면 작은 `⋯` 를 찾아야 했다.

### 접힘/펼침

접힌 상태에서도 **타일은 보인다**(`--size-playlist-collapsed-max-height`,
타일 한 줄). `display: none` 으로 숨기면 플레이리스트가 있는지조차 알 수 없고
드로어로 가는 길도 막힌다.

세로에서 펼치면 **데크 높이를 넘지 않는다** (사용자 요청). 높이를 숫자로 정하지
않고 `WidgetHost` 가 위젯을 데크와 같은 행에 늘려 붙인다
(`align-self: stretch`). 행 높이가 곧 데크 높이이고, 목록이 길면 위젯 안에서
스크롤한다. 화면 폭이 바뀌어도 따라간다.

## 3. 배치 (3번, 4번, 5번)

### 가로 (>1100px)

```
'deck     player   clock'
'deck     player   weather'
'deck     player   .'       ← 정보 열의 빈자리 (다른 위젯 자리)
'playlist mascot   .'
grid-template-rows: auto auto 1fr auto;
```

4번의 원인은 **행 높이 배분**이었다. 행이 둘뿐일 때 두 행의 높이는 데크·플레이어
(두 행을 span 하는 큰 아이템)가 지배한다. 시계는 1행 위쪽에 붙고 그 아래로 빈
공간이 생긴 다음, 날씨가 2행 시작에 붙는다. 그래서 둘 사이가 벌어져 보였다.

1·2행을 `auto` 로 두고 3행에 `1fr` 을 주면, 데크가 요구하는 나머지 높이가 **3행
으로 모인다.** 시계와 날씨가 붙고 빈자리는 아래에 생긴다.

### 세로 (≤1100px)

```
'deck     playlist'    ← 이전의 시계·날씨 자리
'player   player'
'clock    weather'     ← 아래로 내려왔다
'mascot   mascot'
```

## 4. 세로 드로어는 하단 겹침 시트가 됐다 (5번)

세 번 바뀐 자리다.

| 시점 | 배치                       | 왜 바꿨나                                        |
| ---- | -------------------------- | ------------------------------------------------ |
| M3-4 | 스테이지를 `display: none` | 플레이어가 0×0 → 세로에서 재생이 불가능했다      |
| M6-2 | 아래 **행**(별도 공간)     | 다른 위젯이 모두 사라지고 화면이 통째로 바뀌었다 |
| M7   | 하단 **고정 시트**(겹침)   | 보던 화면 위로 올라오기를 요청받았다             |

이제 위젯을 **숨기지 않는다.** 시트는 `position: fixed` 로 뷰포트 하단에 겹친다.

### ⚠ 그래서 겹침 보장을 다시 세워야 했다

M6-2 의 보장은 "드로어와 플레이어가 **다른 그리드 셀**에 있다" 였다. 겹치게
바꾸면 그 보장이 사라지고, **플레이어가 시트에 덮인 채 소리만 나는 상태**가
가능해진다 — III.I.9 가 금지하는 바로 그 상태다. 가시성 측정은 뷰포트 겹침만
보므로 덮인 것을 감지하지 못한다 (`playerVisibility.ts`).

그대로 두면 더 나쁜 일이 생긴다. 시트를 열고 `▶ 목록 전체 재생` 을 누르면
가드가 거절해서 **"세로에서 재생이 불가능하다"(보고 5번)가 재발한다.**

그래서 시트가 열려 있는 동안 **플레이어를 `position: sticky` 로 뷰포트 상단에
붙인다.** 시트가 아래 `--size-sheet-height`(최대 58vh)를 쓰므로 그 위에 플레이어
자리가 남는다. 640px 짜리 화면에서도 42vh = 269px 이고 플레이어는 16:9 로 약
200px + 제목이다.

`sticky` 가 문서 스크롤에 붙으려면 조상의 `overflow` 가 `visible` 이어야 하므로
시트가 열린 동안만 바꾼다. `display` 도 DOM 부모도 건드리지 않으므로 iframe 은
그대로다 (ADR 0002).

> ⚠ **이 보장은 그리드 셀보다 약하다.** `sticky` 는 스크롤 위치와 조상의
> `overflow` 에 의존한다. **실기기 확인이 필요한 1순위 항목이다.**
>
> 실기기에서 깨지면 다음 단계는 가시성 측정에 **하단 가림 높이**를 넣는 것이다
> (`measurePlayerVisibility` 에 `obstructedBottom`, 계약에 통지 메서드). 그러면
> 보장이 측정으로 옮겨가 레이아웃에 의존하지 않는다. 지금 하지 않은 이유는,
> 측정만 고치면 "시트를 열면 재생이 거절된다" 가 되어 사용자가 가장 싫어한
> 상태로 돌아가기 때문이다. **덮이지 않게 두는 것이 먼저다.**

## 5. 바꾸지 않은 것

| 제약                                                        | 근거         |
| ----------------------------------------------------------- | ------------ |
| 플레이어 iframe 의 **부모를 바꾸지 않는다**                 | ADR 0002     |
| 플레이어 영역 **200×200 이상**                              | YouTube 공식 |
| **가려진 채로 재생하지 않는다**                             | III.I.9      |
| 테마 전환이 **재생 상태를 초기화하지 않는다**               | 규칙 5       |
| 드로어 개폐가 **iframe 을 재생성하지 않는다**               | ADR 0002     |
| `PlayerAdapter`·iframe DOM 을 **반응형 상태에 두지 않는다** | ADR 0006     |
| 재생 로직은 테마를, 테마는 재생 구현을 모른다               | 규칙 4       |
| `design/references/` 는 읽기 전용                           | 규칙 6       |

데크 아트 SVG 도 그대로다. 트리거의 **역할만** 바뀌었고 버튼 위치·크기는 승인된
`.disc-open` / `.cassette-open` 값을 따른다.

## 6. 아직 검증되지 않은 것

- **세로 하단 시트가 플레이어를 덮지 않는지** (§4 의 경고). 1순위다
- 접힌 위젯의 타일 한 줄이 폰에서 실제로 읽히는지
- 가로 3열에서 정보 열의 빈자리가 의도대로 **아래에** 모이는지
- 세로에서 펼친 위젯이 데크 높이와 실제로 같아지는지
- 데크 트랜스포트의 터치 목표 크기 (M6 에서 넘어온 항목)
- `PAUSED`·`ENDED` 상태 전이 (M5 에서 넘어온 항목)
