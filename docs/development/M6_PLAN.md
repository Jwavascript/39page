## 1. 완료한 것 (2026-11-04)

### 1-a. 노출 비율 임계값 폐지 (보고 1번의 절반)

`MIN_VISIBLE_FRACTION = 0.5` 을 없애고 판정선을 **"조금이라도 보이는가"** 하나로
바꿨다. 상세와 근거는 ADR 0011 의 개정 절에 있다.

사용자가 물은 "정책상 그런 것이냐" 에 대한 답은 **아니다** 다. 200×200 은 공식
요구사항이지만 50% 는 우리가 정한 숫자였다.

> ⚠ 이것만으로 1번이 닫히지 않는다. 좁은 화면에서 플레이어는 여전히 단일 열의
> **맨 아래**(실측 top 1247px)에 있어 스크롤해야 보인다. 화면 밖이면 겹침이 0
> 이므로 그대로 거절된다. **§2 의 레이아웃 작업이 끝나야 1번이 닫힌다.**

### 1-b. 카세트 릴 궤도 버그 (보고 3번)

원인은 CSS 변환 합성 순서다. 개별 변환 속성(`rotate`)은 `transform` 속성보다
**나중에 합성**되므로, 한 요소가 둘을 같이 가지면 최종 행렬이
`rotate × translate` 가 되어 **translate 된 위치가 회전한다.**

| 릴     | 좌표       | 궤도 반지름 |
| ------ | ---------- | ----------- |
| 왼쪽   | (310, 327) | 450.6       |
| 오른쪽 | (589, 327) | 673.7       |

viewBox 가 `0 0 900 570` 이므로 릴이 좌상단 원점을 중심으로 큰 원을 그렸다.

**이 버그는 승인된 레퍼런스(`two-themes-v09.html` 32행)에 있다.** 포팅 실수가
아니라 레퍼런스를 충실히 재현한 결과다. 고치면 레퍼런스와 달라지므로 규칙 6 에
따라 사용자 확인을 받았다.

수정: 배치(`transform="translate(...)"`)와 회전(`rotate`)을 **다른 요소로 분리**
했다. 바깥 `<g>` 가 배치하고 안쪽 `<g class="cassette-spool">` 이 회전한다.
안쪽에는 자기 `transform` 이 없으므로 `fill-box` 의 중심이 곧 릴의 중심이다.

좌표·색·속성은 하나도 바꾸지 않았다. 레퍼런스 일치 테스트가 이를 증명한다 —
`applyIntendedChanges()` 에 이 그룹 분리만 의도된 차이로 등록했고, 그 외 모든
바이트가 여전히 일치해야 통과한다.

사용자가 실기기에서 **"릴이 제자리에서 돈다"** 고 확인했다. 보고 3번은 닫혔다.

## 2. 1·4·5 의 공통 뿌리

### 현재 구조

`WidgetHost.vue` 의 그리드:

```
넓은 화면 (>1100px)        좁은 화면 (≤1100px)
┌──────┬────────┐          deck
│ deck │ clock  │          mascot
│ deck │ weather│          clock
│mascot│ player │          weather
└──────┴────────┘          player   ← 맨 아래
```

좁은 화면에서 **플레이어가 마지막**이다. 실측 top = 1247px — 화면 밖이다.
그래서 `reveal()`(재생 요청 시 1회 `scrollIntoView`)이 존재한다.

`DashboardShell.vue` 의 드로어:

```css
/* 넓은 화면: 340px 열을 만들어 스테이지를 좁힌다 → 보고 4번 */
.workspace.is-drawer-open {
  grid-template-columns: minmax(0, 1fr) var(--size-drawer-width);
}

/* 좁은 화면: 스테이지를 통째로 숨긴다 → 보고 5번 */
@media (max-width: 1100px) {
  .workspace.is-drawer-open > :first-child {
    display: none;
  }
}
```

**보고 5번(세로에서 재생 불가)은 버그가 아니라 설계된 동작이다.** 드로어를 열면
플레이어가 `display: none` → 0×0 → 가드가 거절한다. 그래서 드로어 안의 "목록
전체 재생" 을 눌러도 아무 일이 없고, `.play-notice` 가 "닫고 ▶ 를 눌러주세요" 를
안내한다. 사용자는 그 안내를 찾지 못했다 — **세로 화면에 재생 경로가 사실상
없다.** 데크의 ▶ 는 SVG 그림이고 동작하는 컨트롤이 아니다 (M1-6).

### 결정 (사용자 확인)

**드로어를 "플레이어를 비켜가는 오버레이" 로 바꾼다.**

```
가로 (≥1100px)                  세로 (<1100px)
┌─────────────────────────┐      ┌───────────┐
│ ┌──────┐   ╔══════════╗ │      │ ┌───────┐ │ ← 플레이어는
│ │PLAYER│   ║ LIBRARY  ║ │      │ │PLAYER │ │   항상 보임
│ └──────┘   ║(overlay) ║ │      │ └───────┘ │
│ ┌────┬────┐║          ║ │      │╔═════════╗│
│ │DECK│CLK │╚══════════╝ │      │║ LIBRARY ║│ ← 아래쪽만
│ └────┴────┘             │      │║(sheet)  ║│   오버레이
└─────────────────────────┘      │╚═════════╝│
                                 └───────────┘
```

### ⚠ 반드시 지켜야 하는 제약

`measurePlayerVisibility()` 는 **뷰포트와의 겹침만** 본다. **다른 요소가 위에
덮은 것은 감지하지 못한다.** 지금은 드로어를 형제 열로 둬서 "절대 겹치지
않는다" 를 구조로 보장하고 있다.

오버레이로 바꾸면 그 보장이 사라진다. **오버레이가 플레이어를 덮으면 소리는
나는데 영상은 안 보이는 상태**가 되고, 그것이 III.I.9 가 금지하는 바로 그
상태다. 따라서:

1. **오버레이는 플레이어 영역을 덮지 않는다.** 레이아웃으로 보장한다.
2. 그 보장을 **테스트로 고정한다.** 사각형 겹침 계산을 단위 테스트로 둔다.
3. 가리는 것이 불가피한 경우에는 기존 `playerWillHide()` 통지를 유지한다.

### 그래서 레이아웃이 선행한다 (보고 1·2번)

오버레이가 플레이어를 비켜가려면 **플레이어가 화면 안에 있어야** 한다. 사용자
제안과 같은 방향이다.

- 영상 영역을 **위로** 올린다
- 데크(LP·카세트)와 플레이어 **크기를 줄인다**
- **스크롤 없이 한 화면**에 위젯이 들어가게 한다
- 가로는 **3열**, 세로는 **2열** 배치를 검토한다 (보고 2번)

**그리드 값은 M6-1 에서 정했다** (§5 의 구현 요약). 브레이크포인트는 승인된
1100px 을 그대로 쓴다 — 새 값을 만들지 않았다. 레퍼런스 이탈은 사용자 확인을
받았고 `WidgetHost.vue` 의 주석에 근거를 적었다 (규칙 6).

**`reveal()`(자동 스크롤)은 안전망으로 남긴다.** 플레이어가 이제 화면 위쪽에
있어 평소에는 부르지 않는다. 그러나 가시성 판정은 **뷰포트 겹침**만 보므로,
사용자가 아래로 스크롤한 뒤 재생을 누르면 여전히 끌어와야 한다. 지우면 그
경우에 "영상이 보이지 않아 재생할 수 없어요" 로 끝나고 사용자가 직접 스크롤해야
한다. 한 번만 끌어오고 다시 재지 않으므로 화면이 멋대로 움직이지도 않는다.

## 3. 라이브러리 재설계 (보고 6·7번)

### 현재 문제

드로어 한 열에 전부 쌓여 있다.

```
[＋ 새 목록] [＋ YouTube 링크 추가]   ← 위계가 다른 둘이 동급
플레이리스트 목록
[▶ 목록 전체 재생] [이름 수정] [삭제]  ← '이름 수정' 이 트랙 목록 바로 위
트랙 목록                              ← 그래서 트랙 이름으로 읽힌다
```

- **6a** 노래를 추가하는 버튼을 찾기 어렵다. 두 `＋` 가 나란히 있고 하나는
  플레이리스트를, 하나는 트랙을 만든다.
- **6b** `이름 수정` 은 플레이리스트 이름을 바꾸는데 트랙 목록 바로 위에 있어
  트랙 이름으로 읽힌다.
- **6c** **트랙 이름 변경 기능이 없다.** 새로 만들어야 한다.
- **7** 플레이리스트와 트랙이 같은 스크롤에 있어 둘 중 하나만 길어져도 전체가
  아래로 늘어난다.

### 결정 (사용자 구상) — 플레이리스트를 위젯으로 꺼낸다

바탕화면의 **폴더 아이콘** 메타포다.

| 표면                           | 담당                                                                   |
| ------------------------------ | ---------------------------------------------------------------------- |
| **플레이리스트 위젯**          | 플레이리스트 타일 격자. 생성·삭제. 내부 스크롤                         |
| **플레이리스트 편집 오버레이** | 한 플레이리스트의 트랙. 이름 변경, 레코드 추가·삭제·순서·**이름 변경** |

이 분리가 6·7 을 동시에 푼다.

- 6a: `＋ 새 목록` 은 플레이리스트가 사는 **위젯**으로, `＋ YouTube 링크 추가` 는
  트랙이 사는 **편집 오버레이**로 간다. 위계가 공간에 드러난다.
- 6b: `이름 수정` 은 편집 오버레이의 **머리말**로 간다. 무엇의 이름인지 자명해진다.
- 6c: 트랙 행에 이름 변경을 더한다.
- 7: 두 표면이 각자 스크롤한다. 한쪽이 길어져도 다른 쪽을 밀지 않는다.

### 상호작용

- **타일 누르기 → 그 플레이리스트 전체 재생**
- **타일 열기 → 편집 오버레이** (사용자 구상: 롱프레스 또는 다른 동작)

> ⚠ **롱프레스만으로는 안 된다.** 키보드·스크린리더에 대응되는 동작이 없고 M5
> 접근성 감사를 통과하지 못한다. 타일마다 **보이는 보조 버튼**(예: 우측 상단
> `⋯`)을 두고, 롱프레스·우클릭은 그 버튼의 **추가 경로**로만 둔다.

### M6-4·5 구현 결과 (2026-11-04)

결정과 그 근거는 **ADR 0016** 에 적었다. 여기에는 확정된 답만 남긴다.

| 열어 둔 질문     | 확정                                                                               |
| ---------------- | ---------------------------------------------------------------------------------- |
| 타일 기본 동작   | **재생.** 단 **빈 목록은 열기** — 비활성 타일은 막다른 길이다                      |
| 위젯 위치        | `src/features/library/` (초안의 `src/widgets/playlist/` 를 바꿨다 — 디렉터리 규약) |
| 레이아웃 자리    | 가로 `'mascot playlist .'`, 세로 `'playlist playlist'` — **플레이어와 같은 열**    |
| 데크 누름의 역할 | 그대로 둔다. 선택된 목록의 편집 오버레이를 연다                                    |
| 여는 조작        | 보이는 `⋯` 가 본체. `contextmenu`(길게 누르기·우클릭)는 추가 경로                  |
| 드로어 분해      | `TrackList.vue` 분리. `PlaylistList.vue` 삭제 (드로어에 목록이 없어졌다)           |

**가시성 거절 안내를 한 곳으로 모았다.** 재생을 요청하는 세 표면(편집 오버레이 ·
플레이리스트 위젯 · 데크)이 `player-hidden` 에는 아무 말도 하지 않는다. 그 사유는
코디네이터가 플레이어의 `.status` 에 적는다. M3-4 에는 좁은 화면에서 드로어가
플레이어를 **대체**했기 때문에 누른 자리에 띄워야 했지만, M6-2 부터 플레이어가
항상 보이므로 같은 말을 두 곳에 띄우는 것이 된다.

## 4. 전체에 걸리는 제약

바꾸면 안 되는 것들이다.

| 제약                                                        | 근거         |
| ----------------------------------------------------------- | ------------ |
| 플레이어 iframe 의 **부모를 바꾸지 않는다**                 | ADR 0002     |
| 플레이어 영역 **200×200 이상**                              | YouTube 공식 |
| **가려진 채로 재생하지 않는다**                             | III.I.9      |
| 테마 전환이 **재생 상태를 초기화하지 않는다**               | 규칙 5       |
| 드로어 개폐가 **iframe 을 재생성하지 않는다**               | ADR 0002     |
| `PlayerAdapter`·iframe DOM 을 **반응형 상태에 두지 않는다** | ADR 0006     |
| 재생 로직은 테마를, 테마는 재생 구현을 모른다               | 규칙 4       |

5. ~~**M6-5 편집 오버레이**~~ — **완료.** 드로어를 한 목록의 편집 표면으로
   좁히고 트랙 이름 변경을 더했다 (6번). **ADR 0016**
6. ~~**M6-6 데크 트랜스포트**~~ — **완료.** 그려진 ▶ / ■ 를 네이티브 버튼으로
   덮었다 (§5-a). **ADR 0017**

### M6-1·2·3 구현 요약

**가로 (>1100px) 3열**

```
'deck   player  clock'      데크 | 플레이어 | 정보
'deck   player  weather'
'mascot .       .'
```

열 최소값이 둘 다 근거를 갖는다.

- 2열 `minmax(360px, …)` — `.video-holder` 가 `min-height: 202px` 과
  `aspect-ratio: 16/9` 를 함께 가지므로 202 × 16/9 ≈ 359px 미만에서는 16:9 를
  지킬 수 없다
- 3열 `minmax(var(--size-drawer-width), …)` — **우측 오버레이가 이 열 안에서
  끝나야 플레이어를 가리지 않는다.** 가시성 측정은 덮인 것을 감지하지 못하므로
  이 보장은 레이아웃이 진다. 두 값을 묶어 두면 드로어 폭을 바꿔도 따라간다

**세로 (≤1100px) 2열**

```
'deck   clock'
'deck   weather'
'player player'             ← 데크 바로 아래, 두 열을 가로지른다
'mascot mascot'
```

플레이어가 두 열을 가로지르는 것은 **공식 요구 때문**이다. 폰 세로(390px)에서
반 칸은 약 168px 이고 `.video-holder` 최소값은 202px 이라 반 칸에 두면 넘치거나
`too-small` 로 거절된다. 대신 `--size-player-max-compact: 640px` 상한을 두어
1000px 쯤에서 높이가 530px 까지 커지는 것을 막는다.

**오버레이**

절대 위치를 쓰지 않는다. 스테이지와 드로어를 **같은 그리드 셀**(`1 / 1`)에
넣으면 스테이지의 트랙 크기가 바뀌지 않아 위젯이 재배치되지 않는다. DOM
부모·순서도 그대로다 (ADR 0002).

좁은 화면에서는 드로어가 **아래 행**(`2 / 1`)을 쓰고 스테이지는 **플레이어만**
남긴다. 겹침이 구조적으로 불가능하다 — 픽셀 비율로 맞추면 화면 크기마다 깨진다.

**사전 통지 제거**

`DashboardShell` 이 `playerWillHide()` 를 부르지 않는다. 플레이어가 가려지지
않으므로 멈출 이유가 없고, 그래서 세로 화면에서 재생이 끊기지 않는다. 그 결과
이 컴포넌트는 재생 계약을 다시 모르게 됐다 (규칙 4 에 더 부합한다).

레이아웃이 깨져 플레이어가 화면 밖으로 밀리는 경우는 `PlayerSurface` 의
`IntersectionObserver` 가 안전망으로 잡는다.

**`playerWillHide()` 는 존치로 결정했다.** 운영 코드 호출자가 없지만 계약과
단위 테스트(C3)는 남아 있다. 플레이어를 가리는 레이아웃이 다시 생기면 그때
필요한 장치이고, 지웠다가 다시 만들면 "가리기 **전에** 멈춘다" 는 타이밍 보장을
다시 발견해야 한다. 지금은 **사용되지 않는 안전장치**로 남는다.

**`.play-notice` 의 틀린 조언은 제거했다.** "닫고 ▶ 를 눌러주세요" 가 아니라,
가시성 사유는 플레이어의 `.status` 가 혼자 말한다 (위 §3 의 구현 결과).

**ADR 을 두 개 썼다.** 레이아웃·오버레이는 ADR 0011 의 개정 절에 들어갔고,
플레이리스트 표면 분리는 **ADR 0016**, 데크 트랜스포트는 **ADR 0017** 이다.

## 5-a. 추가로 보고된 문제 — 데크의 ▶/■ 가 동작하지 않는다

실기기 검증에서 다시 지적됐다. LP·카세트 아트에 `▶ PLAY` / `■ STOP` 이
그려져 있지만 **SVG 그림이고 동작하는 컨트롤이 아니다** (M1-6 에서 승인된
디자인의 속도 키도 같은 이유로 비활성으로 뒀다).

누를 수 있어 보이는 것이 동작하지 않는 것은 그 자체로 UX 결함이다. 선택지는
둘이다.

| 선택지                      | 결과                                                                             |
| --------------------------- | -------------------------------------------------------------------------------- |
| **동작하게 만든다**         | 세로에서 재생 경로가 하나 더 생긴다. 규칙 4 를 지켜 store 경유로만 호출해야 한다 |
| **누를 수 없음을 드러낸다** | 그림임을 시각적으로 분명히 한다. 기능은 늘지 않는다                              |

**동작하게 만들었다** (M6-6, ADR 0017). 사용자는 두 번 언급했고, 재생·일시정지는
이미 구현된 기능이다. "동작하지 않는 버튼을 만들지 않는다" 는 원칙은 **없는
기능**의 버튼을 금지하는 것이지 **있는 기능**을 그림으로 두라는 것이 아니다.

- 승인된 SVG 는 수정하지 않았다. `.deck-open` 과 같이 네이티브 버튼을 좌표에
  맞춰 겹쳤다
- 큐가 없으면 **선택된 목록을 처음부터** 재생한다 — 세로 화면의 두 번째 재생 경로
- ■ 는 소리가 날 때만 동작한다. 멈춰 있을 때 `togglePlay()` 를 보내면 ■ 가 재생을
  시작해 그림과 어긋난다
- 보이는 글자는 `STOP` 이지만 실제 동작은 일시정지다. 접근성 이름이 사실을 말한다
- 속도 키(33/45)는 그대로 그림이다. 속도 변경은 **없는 기능**이다

## 6. 아직 검증되지 않은 것

- **실제 재생(`PLAYING`) 외의 상태 전이** — `PAUSED`·`ENDED` 는 실기기에서
  확인하지 못했다. 사용자가 "유튜브 재생은 된다" 고 확인한 것이 처음이다.
- 위 1-a·1-b 수정은 **단위 테스트로만 확인했다.** 실기기 재확인이 남아 있다.
- **M6-1 ~ M6-6 전부 jsdom 단위·통합 테스트로만 확인했다.** 실기기 확인이
  남아 있고, 특히 다음은 jsdom 에서 확인할 수 없다.
  - 데크 트랜스포트의 **실제 터치 목표 크기** (계산상 약 37 × 27px)
  - `contextmenu` 가 안드로이드 Chrome 의 **길게 누르기**로 실제로 오는지
  - 타일 두 칸이 폰 세로(약 356px)에서 실제로 읽히는지
  - 위젯이 한 줄 더 늘어난 뒤에도 **스크롤 없이 한 화면**이 지켜지는지
  - 카세트 릴이 제자리에서 도는 것 외에 **LP 와 다른 연출**이 더 필요한지
