# M12-6 UX Polish 구현·검증 보고 (2026-11-15)

브랜치 `m12-6-ux-polish`, 시작 HEAD `fd4b995` (`m12-custom-artwork`), 시작 작업 트리 깨끗함.
기존 커밋 재작성·push·main 통합·운영 배포·스토어 업로드는 하지 않았다. 새 의존성은 없다.

## A. 변경한 UX와 사용자 동작

- 헤더는 마지막 상위 탭, 데크는 음악 목록, NOW PLAYLIST 편집은 해당 목록 상세, 카드 그림은 해당 트랙 설정으로 연다.
- 닫기·새 진입에서 Artwork·곡 편집·관리 메뉴를 정리한다. 파일·입력·구도 변경은 계속 편집/버리고 나가기 확인을 받으며,
  단순 라디오 선택은 취소로 폐기한다. 새 목록 만들기·목록 선택도 미저장 편집을 먼저 확인한다.
- YouTube 썸네일·기본 그림·업로드 모두 저장 전 미리보기가 바뀐다. 현재 저장값과 점선의 저장 전 미리보기를 구분한다.
- 사용자 이미지의 Cover/Contain, 가로·세로 위치, 확대 1–3배, 기본값, 마우스·터치 포인터 끌기를 제공한다.
- Moments 모두 보기는 전체 필터를 연다. 곡 배지는 그 videoId 필터이며 이 곡→전체→최근 순서는 유지한다.
- 곡 변경 경고를 Moment 입력·동작 뒤로 옮겼다. 처음 잡은 영상·시점·메모와 기존 최종 저장 정책은 유지한다.
- 빠른 링크 제출은 oEmbed 조회를 최대 4초까지 마친다. 실패해도 추가하며 수동 제목과 저장된 제목을 덮지 않는다.
- 카세트는 실제 재생 큐 출처 이름을 표시한다. 선택 목록을 바꿔도 재생 큐 이름을 유지하고 긴 다국어 이름은 말줄임한다.
- 목록/곡 관리 메뉴에서 기존 공유 화면을 정확한 대상·Moments 꺼짐으로 연다. 기존 데이터·백업 진입도 유지한다.

oEmbed의 실제 Chrome 성공과 차단 실패를 확인했다. 과거 UAT의 정확한 네트워크 실패 원인은 로그가 없어 단정하지 않는다.
HTTP 400/404·401/403·서버 오류·네트워크·잘못된 JSON·타임아웃은 자동 시험으로 구분한다.
IFrame 어댑터는 실제 제목을 노출하지 않으며 비공개 API 의존성을 추가하지 않았다 ([ADR 0035](../decisions/0035-m12-6-edit-sessions-and-artwork-display.md)).

## C. Artwork 모델과 호환성

- 연결 키는 `(playlistId, trackId)`. 선택 필드 `display = { fit, positionX, positionY, zoom }`를 더했다.
  생략은 cover/50/50/1. 위치 0–100%, 확대 1–3배를 검증하며 잘못된 값·미래 버전은 쓰기 전에 거절한다.
- 원본 GIF/PNG/JPEG/WebP와 SHA-256 assetId는 그대로다. 구도만 변경할 때 assignments만 쓴다.
  같은 자산의 곡별 구도는 독립적이고 저장 실패·revision 충돌은 이전 연결을 보존한다.
- IndexedDB v1 유지: object store·키·색인 변화가 없는 선택 필드다. 기존 데이터 재작성이나 일괄 마이그레이션은 없다.
- 전체 ZIP manifest/artwork.json, 공유 manifest/share.json은 v2로 내보내며 v1/v2를 읽는다. 구버전 앱의 조용한 구도 누락을 막는다.
  내부 backup.json은 기존 형식. 기존 staging·rollback·텍스트/그림 부분 실패·재시도·자산 누락 fallback은 유지한다.
- v1·v2 왕복, 새 프로필 복원, 같은 자산/다른 구도, 유효한 해시 안의 잘못된 수치, 미래 버전 거절을 검증했다.
