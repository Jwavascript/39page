# 확장 저장 브리지 — 후보 비교와 PoC 결과 (M11-1)

> 상태: **M11-1 기술 검증 완료 (2026-11-12)** — 정식 구현은 M11-5. 결정(제안): [ADR 0028](../decisions/0028-extension-save-bridge.md)
> UX: [`../product/M11_UX_DESIGN.md`](../product/M11_UX_DESIGN.md) §8 · PoC 코드: [`../../poc/m11-bridge/`](../../poc/m11-bridge/README.md)
> 실측 기록: `poc/m11-bridge/results/2026-11-12-chrome157.json`

## 0. 질문

> 39page 탭으로 화면을 전환하지 않고도, 기존 저장소와 데이터 보호 로직을 유지하면서 YouTube 위 플로팅 패널에서
> Library · Moments 조회와 저장을 끝낼 수 있는가?

**답: 된다 — 실제 Chrome 157 에서 확인했다.** 조건은 하나다: 확장이 **39page origin 의 호스트 권한**을 가져야 한다.
그 권한이 있으면 확장 페이지(offscreen 문서) 안의 39page iframe 이 사용자의 39page 탭과 **같은** localStorage ·
Web Locks 잠금 관리자 · `storage` 이벤트를 쓴다. 권한이 없으면 같은 iframe 이 **분할된 빈 저장소**를 본다.

## 1. 출발점 — 바꿀 수 없는 사실

| 사실                                                                                                                                                            | 근거                                            |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| 39page 데이터는 `https://39page.com` origin 의 localStorage 에 있다. 확장 · YouTube 는 다른 origin 이다                                                         | 설계 (ADR 0007 · 0019)                          |
| 확장 → 웹페이지로 먼저 메시지를 보내는 API 는 없다                                                                                                              | 공식 Messaging 문서 (ADR 0023 에서 확인)        |
| 웹페이지 → 확장은 `externally_connectable` 을 선언했을 때만, 확장 ID 를 알아야 한다                                                                             | 공식 externally_connectable 문서                |
| 서비스 워커에는 localStorage 가 없다. offscreen 문서에서는 `chrome.runtime` 만 쓸 수 있다                                                                       | 공식 Storage and cookies · offscreen 문서       |
| Chrome 115+ 는 제3자 iframe 의 저장소를 최상위 사이트로 분할한다. **확장 페이지가 띄운 iframe 은 확장에 그 사이트의 호스트 권한이 있으면 최상위 파티션을 쓴다** | 공식 Storage and cookies 문서 (2026-11-12 확인) |
| 서비스 워커는 30초 유휴 뒤 종료된다. 포트를 여는 것만으로는 타이머가 초기화되지 않는다 (Chrome 114+)                                                            | 공식 서비스 워커 수명 주기 문서                 |
| offscreen 문서는 확장마다 하나, `IFRAME_SCRIPTING` 등 오디오가 아닌 이유는 수명 제한이 없다                                                                     | 공식 offscreen 문서 (Chrome 109+)               |

## 2. 후보

| 후보                                            | 방식                                                                                                               |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| **A. 웹앱 ↔ 확장 메시징 (탭 포트)**             | 사람이 연 39page 탭이 `externally_connectable` 로 확장에 포트를 열어 둔다. 확장은 그 포트로 요청한다               |

| C3. 39page 탭에 content script                  | 39page 호스트 권한으로 열린 39page 탭에 스크립트를 넣어 중계                                                       |
| C4. 확장이 저장소를 직접                        | offscreen · 확장 페이지가 localStorage 를 직접                                                                     |

## 3. PoC 구성

```
YouTube 탭 ─────────────────────────────────────────────────────────────┐
│  content script(격리) → 닫힌 shadow root → <iframe chrome-extension://…/panel.html>  ← 플로팅 패널
│                                                │ runtime.sendMessage (sender.url = panel.html 만 받음)
└────────────────────────────────────────────────┼────────────────────────┘
                                                 ▼
                                   서비스 워커 (상태 없음 · 요청 ID 한 번만 전달)
                         ┌───────────────────────┴───────────────────────┐
             route=offscreen (후보 B)                          route=tab-port (후보 A)
                         ▼                                               ▼
         offscreen.html (확장 origin)                    39page 탭 bridge.html?mode=connect
           └ <iframe 39page/bridge.html>                   (externally_connectable 포트)
               postMessage (origin · source 확인)
                         └──────────── 기존 useLibraryStore · useMomentsStore ────────────┘
                                         (검증 · 보호 상태 · Web Locks 잠금 + 영수증)
```

- 브리지 페이지는 **기존 store 만** 부른다 (`addTrack` · `createPlaylist` · Moments `add`). 저장소를 직접 쓰지 않는다.
- 저장 확인: store 가 `persisted: true` 를 돌려줘도 **저장소를 다시 읽어 그 항목이 있을 때만** `ok`.
- 39page 는 PoC 빌드를 `vite preview` 로 `http://127.0.0.1:4173` 에 띄웠다 (대시보드 + 브리지, 같은 origin). 운영 사이트에 접속하지 않았다.
- 브라우저: **Chrome for Testing 157.0.8103.50** (Windows 11), 매번 새 임시 프로필, 헤드리스. 확장 로드 · 툴바 클릭은
  CDP `Extensions.loadUnpacked` · `Extensions.triggerAction` (실제 `activeTab` 부여). 누르는 자리는 실제 마우스 이벤트,
  입력은 실제 키 입력(`Input.insertText`). YouTube 는 실제 www.youtube.com 영상.

### 3-1. 이 기기에서 하네스를 세우며 알게 된 것

- 브랜드 Chrome 157 은 `--load-extension` 을 무시했다 (137+ 정책). `--remote-debugging-pipe` 로 띄우면 Windows 에서 Chrome 이
  바로 종료(코드 0)했다 — 브랜드 Chrome · Chrome for Testing 둘 다. 그래서 **Chrome for Testing + WebSocket CDP +
  `--enable-unsafe-extension-debugging`** 을 썼다 (`Extensions.*` 가 이 조합에서 동작).
- `Extensions.triggerAction` 은 `tab` 종류 대상 ID 를 받고, 그 탭이 활성이어야 했다.
- Windows 에서 `child.kill()` 은 Chrome 을 끝내지 못했다 — 두 번째 실행이 앞 브라우저에 붙어 측정이 오염됐고 버렸다.
  지금 하네스는 포트 0 + 프로필의 `DevToolsActivePort` + `taskkill /T` 를 쓴다.

## 4. 저장소 파티션 실측 (P0)

대시보드 탭(최상위 `127.0.0.1:4173`)이 표지 값을 쓰고 Web Lock 하나를 잡은 채로, 다른 자리에 띄운 39page 탐침이
무엇을 보는지 쟀다.

| #   | 자리                                                   | 호스트 권한 | 표지 값 (localStorage) | 대시보드의 잠금이 보임 | storage 이벤트  | 판정            |
| --- | ------------------------------------------------------ | ----------- | ---------------------- | ---------------------- | --------------- | --------------- |
| P0a | **offscreen 문서** 안 iframe                           | 있음        | **같음**               | **예**                 | —               | 최상위 파티션 ✔ |
| P0b | 확장 **탭 페이지** 안 iframe (사이드 패널과 같은 종류) | 있음        | **같음**               | **예**                 | **양방향 도착** | 최상위 파티션 ✔ |
| P0d | 확장 탭 페이지 안 iframe                               | **없음**    | 없음 (`null`)          | —                      | —               | **분할** ✖      |
| P0c | YouTube 위 확장 iframe(패널) 안의 39page iframe        | 있음        | 없음 (`null`)          | 아니오                 | —               | **분할** ✖      |

- P0c 의 조상은 `[chrome-extension://…, https://www.youtube.com]` — 최상위가 YouTube 이므로 호스트 권한이 있어도
  분할된다. **패널 안에서 39page 를 띄우는 방식(C2 의 변형)은 쓸 수 없다.** 잠금 관리자도 따로라 탭 간 잠금이 깨진다.
- 그래서 브리지 페이지는 **조상 전체가 허용한 확장 origin 일 때만** 일한다 (`isTrustedAncestry`). P0c 자리에 넣은
  브리지는 실제로 `refused` 였다.

### 5-1. 측정하지 않은 것 · 흉내 낸 것

- **부분 성공**은 `addTrack` 하나를 거절하도록 주입했다. 실제로 두 명령 사이(수 ms)에 다른 탭이 잠금을 잡게 만드는 것은
  우연에 달려 재현하지 않았다. 목록 생성은 실제 store 경로다.
- **응답 중단 · 지연**은 브리지 안의 결함 주입이다 (네트워크가 아니다 — 브리지와 확장은 같은 브라우저 안의 메시지다).
- **사용 불가(`unavailable`) 저장소**는 실제 브라우저에서 만들지 않았다 — 단위 시험이 같은 거절 경로(`blocked`)를 고정한다.
- 서비스 워커 재시작은 CDP `Target.closeTarget` 으로 했다. 30초 유휴 종료를 기다리지는 않았다.

### 5-2. 동시 저장 — 측정 결함 하나를 걸러 낸 과정

최종 직전 실행에서 S5-race 가 "성공 응답 20 · 저장 19" 로 읽혔다 — 그대로라면 **조용한 손실**이다. 그러나 하네스는 마지막
쌍이 끝난 **바로 그 순간** 대시보드 탭의 localStorage 를 읽었다. 다른 렌더러의 쓰기는 수 ms 뒤에 도착한다(ADR 0025 실측
3–10ms). 그래서 바로 읽은 값과 전파 뒤(값이 더 바뀌지 않을 때까지) 값을 나눠 30쌍씩 3회 다시 쟀다.

| 회차 | 성공 응답 | 바로 읽음 | 전파 뒤 | 39page 탭 브리지가 본 값 | 빠진 항목 |
| ---- | --------- | --------- | ------- | ------------------------ | --------- |
| 1    | 60        | 60        | 60      | 60                       | 없음      |
| 2    | 60        | 59        | 60      | 60                       | 없음      |
| 3    | 60        | 58        | 60      | 60                       | 없음      |
| 최종 | 60        | 60        | 60      | 60                       | 없음      |

결론: 19 는 **전파 전에 읽은 측정 결함**이었다. 하네스는 이제 전파 뒤 값으로 판정하고 두 값을 함께 남긴다. 이것이 손실이
**불가능하다**는 뜻은 아니다 — ADR 0025 의 "한계" 가 그대로 적용된다.

**추천: B** — 39page 탭이 없어도 되고(목표 UX), 기존 store 와 잠금을 그대로 쓰며, 웹페이지에서 확장으로 들어오는 문
(`externally_connectable`)을 열지 않는다. **새 탭 수집 화면(M10)은 검증된 대체 경로로 남긴다.**

C1(사이드 패널)은 저장소 조건이 B 와 같아 기술적으로 되지만(P0b 로 대신 측정), "YouTube 위에 떠 있는 작은 패널"
이라는 목표와 다르다. 사용자가 사이드 패널을 원하면 B 의 브리지를 그대로 쓸 수 있다.

## 7. 메시지 계약 v1 (PoC)

```ts
// 확장(offscreen · 탭 포트) → 브리지
{ ns: '39page-bridge', v: 1, kind: 'request', id: string /* ^[A-Za-z0-9_-]{16,64}$ */, deadline: number /* epoch ms */,
  payload:
    | { op: 'hello' }
    | { op: 'library/list', videoId: string | null }                      // 목록 + 그 영상의 위치
    | { op: 'track/add', playlistId, videoId, title: string | null }
    | { op: 'playlist/create-and-add', name, videoId, title: string | null }
    | { op: 'moment/add', videoId, atSeconds, note, title: string | null }
    | { op: 'moment/list-for-video', videoId }
    | { op: 'track/find', playlistId, videoId }                           // 저장 여부 조회 (응답을 잃었을 때)
    | { op: 'moment/find', videoId, atSeconds, since } }
// 브리지 → 확장
{ ns, v: 1, kind: 'response', id, ok: true, data } | { ns, v: 1, kind: 'response', id, ok: false, error: { code, retryable, detail? } }
{ ns, v: 1, kind: 'ready', status }   // 브리지가 떴을 때 한 번
```

| 항목               | 규칙                                                                                                                                                                                                                                                                                |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 버전               | `v: 1` 이 아니면 `unsupported-version`. 모르는 `op` 는 `unsupported-op`                                                                                                                                                                                                             |
| 요청 ID · 중복     | 브리지가 ID → 결과를 기억(10분, 메모리). 같은 ID 같은 내용 = 처음 결과를 그대로, 다른 내용 = `id-reused`. 워커도 같은 규칙(60초). **패널은 응답을 잃으면 같은 쓰기를 다시 보내지 않고 먼저 조회한다**                                                                               |
| 마감 · 재전송 방어 | 쓰기는 `deadline`(보낸 때 + 8초)이 지났으면 시작하지 않는다(`expired`). 30초보다 먼 마감은 거절 — 가로챈 요청을 나중에 다시 보내도 쓰지 않는다                                                                                                                                      |
| 시간 한도          | offscreen 은 브리지 준비 6초(한 번 다시 띄움), 응답 15초. 워커는 전체 16초. 브리지는 마감 전에 시작한 쓰기를 잠금 5초 + 확인 1.5초 안에 끝낸다                                                                                                                                      |
| 송신자 검증        | 워커: `sender.id` = 이 확장 **그리고** `sender.url` 이 `panel.html` (content script 는 웹페이지 주소라 걸린다). offscreen → 브리지: `targetOrigin` = 브리지 origin. 브리지: `event.source === parent` **그리고** `event.origin` ∈ 허용 확장 origin **그리고** 조상 전체가 허용 확장 |
| 허용 origin        | 빌드에 박는다(주소 · 쿼리로 받지 않는다). PoC: `chrome-extension://pkagnijdhfmkodpdfgdehfdghcgbfpoa` (manifest `key` 로 고정). 탭 포트(A)는 `sender.origin` + 경로가 브리지일 때만                                                                                                  |
| 입력 검증          | `videoId` = 웹앱 `isYouTubeVideoId` · 제목 100자 · 제어/양방향 문자 거절 (수집 URL 계약과 같다) · 목록 이름 60자 · `atSeconds` 0–999999 정수 · 메모 500자(줄바꿈만 허용). store 가 한 번 더 검증한다                                                                                |
| 저장 결과          | `ok` 는 **저장소를 다시 읽어 확인한 뒤에만**. store 가 메모리에만 반영했으면 `not-persisted` + 메모리를 저장소 상태로 되돌림. 다시 읽어 없으면 `not-verified`                                                                                                                       |
| 보호 · 사용 불가   | store 를 부르지 않고 `blocked` (store 는 그 상태에서 메모리에만 반영하므로 브리지 메모리가 갈라진다)                                                                                                                                                                                |
| 사용자 동의        | 쓰기는 패널에서 사람이 버튼을 누를 때만 보낸다. 패널은 확장 origin iframe 이라 YouTube 페이지가 대신 누를 수 없다                                                                                                                                                                   |
| 부분 성공          | `partial` + `detail.playlistId` — 패널은 그 목록에 다시 담는다                                                                                                                                                                                                                      |

### 8-3. 저장 일관성

- 브리지는 대시보드 · 수집 화면과 **같은 store 코드와 같은 잠금 관리자**를 쓴다 (P0a). 잠금 + 영수증(ADR 0025)이 그대로
  적용되고, offscreen 브리지 ↔ 39page 탭의 동시 저장 20/20 이 남았다 (S5-race).
- 대시보드는 `storage` 이벤트로 브리지의 저장을 새로고침 없이 본다 (S3 · S4 · P0b).
- ADR 0025 의 "한계" 는 그대로다 — 규약 밖의 옛 탭, Web Locks 없는 환경, 쓰자마자 닫힌 탭.
- 브리지의 요청 기록은 메모리다. offscreen 이 다시 뜨면 사라진다 — 그래서 패널은 응답을 잃으면 **다시 보내기 전에 조회**한다.
  조회도 못 하면 "확인하지 못했어요" 라고 말하고 사용자에게 39page 에서 확인하게 한다 (성공이라 하지 않는다).

## 10. 권장 아키텍처 (M11-5)

1. 웹앱: `https://39page.com/bridge.html` — 대시보드를 싣지 않는 별도 Vite 입력. `src/features/bridge/` (PoC 의
   `bridgeProtocol` · `bridgeHandlers` 정식화). 허용 확장 ID 를 빌드에 박고, `_headers` 로 `frame-ancestors` 를 제한한다.
2. 확장: `offscreen`(+ `optional_host_permissions: ["https://39page.com/*"]`). 처음 쓸 때 패널이 권한을 묻는다.
   offscreen 은 첫 패널 사용 때 만들고 유휴 몇 분 뒤 닫는다 (TODO: 시간 · 메모리 측정).
3. 패널: 확장 페이지 iframe (Vue). 계약 v1 그대로, 조회 우선 재시도.
4. 단축키: 지금처럼 `activeTab` 을 얻고 새 탭 대신 패널을 연다. Moment 는 누른 순간 고정(ADR 0026) 그대로.
5. 폴백: M10 수집 URL · 수집 화면을 지우지 않는다. 브리지 실패 · 권한 거절 · 보호 상태에서 쓴다.
6. store: `createPlaylist(name, { select: false })` — 확장에서 만든 목록이 대시보드 선택을 바꾸지 않게 (D4).
